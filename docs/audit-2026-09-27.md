## 二、审计发现（三类清单，附依据与方案）

### 2.1 不足（bug / 健壮性缺口）

#### E-P1-1　Electron 启动失败后无限自动重试【Electron，高置信】
- **依据**：`index.ts` 的 splash `did-finish-load` 只要 `navStarted===false` 就自动 `bootstrap()`；
  而 `bootstrap()` 失败分支无条件 `navStarted=false` 并重新 `loadURL('splash://')`
  → 失败 → splash 重新加载 → 再次自动 bootstrap …… sidecar 缺失时是紧密循环（每轮
  spawn 一次 w2c-proxy），用户点重试的设计意图被架空，且与注释「用户至少能看到并点重试」矛盾。
- **方案**：新增模块级 `splashAutoBootConsumed`；自动 bootstrap 一生只自动一次，
  失败后只有用户点「重试」（`/retry` 处理器先置 `navStarted=false` 再显式调用）能再跑。
- **效果 / 影响**：失败停在可交互启动页；首次成功行为不变；纯 `index.ts` 改动，零接口变化。
- **成本**：3 行状态 + 注释。

#### E-P1-2　关闭后台（非活动）页签后壳标签栏残留「幽灵页签」【Electron】
- **依据**：`tabs.ts closeTab()` 只有在 `wasActive` 分支调 `activate()`（内部 push），
  非活动分支没有任何推送；`shell.html` 点 × 不做本地乐观更新，全靠宿主 `render()`
  → 被关条目残留在 DOM 直到下一次切换/新建/标题推送。Rust 侧 `close_tab_inner`
  非活动分支本来就有 `push_tabs_to_shell`，两壳分叉。
- **方案**：非活动分支补 `this.pushToShell()`。
- **回归**：探针新增 P7c 两条（前提同步 + 关后台后壳 DOM 条数==集合数）。
- **成本**：1 行 + 探针 2 条 + 夹具复用。

#### E-P1-3　设置保存失败时「被销毁的托盘」不回滚【Electron】
- **依据**：`applySettings` 注释自称「任一步失败都不写内存态，只回滚快捷键/托盘」，
  但 catch 只在 `trayCreatedThisCall` 时重建；`true→false` 分支先 `destroyTray()`，
  随后持久化抛错时托盘已消失且不会恢复（快捷键的对称回滚是有的，托盘只做了一半）。
- **方案**：补 `trayDestroyedThisCall`，catch 里 best-effort `createTray()` 并告警。
- **影响**：重建失败只告警不抛（图标缺失现在也是 Err 而非 panic，见 R-P2-4）。

#### E-P1-4　preload 向子框架暴露特权窗口桥【Electron，纵深防御】
- **依据**：preload 默认每个框架执行；旧实现在子框架里照样 `sendSync('web2app:bootstrap')`
  + `contextBridge.exposeInMainWorld('web2app', …)` + 注册 overlay 监听 → 被壳页面嵌入的
  任何第三方 iframe 都能调 `minimize/close/openSettings`、读到 `web2appExtra`，
  还白拉一份 ~81KB 的同步载荷。
- **重要实测修正**：Electron 44.4 + 当前 webPreferences（未开 `nodeIntegrationInSubFrames`）
  下，**preload 实际并不注入子框架**（探针在子框架 realm 内用 contextBridge 诊断标记实测
  `marker=undefined`）。因此该路径在默认配置下当前不可达；本修复属**纵深防御 + 前向兼容**
  （未来 Electron 行为变化或有人开启子框架集成时桥梁不会漏出），不是封堵正在发生的泄漏。
- **方案**：preload 全部运行时主体收进 `if (window.self === window.top)`。
- **回归**：探针新增第 16 节 4 条（iframe 夹具 `frame.html` + 子框架 realm 内求值）。
  反向对照：曾尝试把子框架闸门改成 `if(true)`，因上述默认行为探针**无法**制造失败
  （已在报告中如实记录，未强行宣称咬人）；顶层桥正常暴露的断言防止功能被收窄。

#### E-P1-5　`public_key` 归一化与打包解析器漂移【Electron】
- **依据**：打包路径 `parse-packaging-config.py::normalize_public_key` 会把 JSON 手写的
  `\\n` 还原成真换行、去 `\\r`、trim；Electron 运行时 `config.ts` 原样透传
  → 同一份 config.json 走 Tauri 打包可用、走 Electron「域名数组 + PEM 公钥」必败
  （resolve-core 按真换行 `.lines()` 取 base64 体，单行含字面量 `\n` 被 ----- 过滤）。
- **方案**：`normalizePublicKey()` 与 Python 逐字同规则；`loadConfig` 与数组公钥校验都吃归一化值。
- **回归**：单测 2 条（裸 base64、PEM 字面量）。

#### E-P1-6　`sanitizeDirName` 与 Rust 漏了两条规则【双壳漂移】
- **依据**：Rust `sanitize_dir_name` 有「连续空白压缩为一个空格」「去首尾句点」，
  TS 版只做非法字符替换 + trim → `"My  App"`、`"MyApp."` 两壳算出不同目录名，
  `data_dir=""` 模式下 settings.json 读取候选分叉。
- **方案**：补齐两条（控制字符在 Rust 里先于空白压缩映射成下划线，此边界已在测试中钉明）。
- **回归**：单测新增 6 个断言。

#### R-P1-1　Tauri 多页签真实标题回传是一条「ACL 死路」【Rust，框架源码取证】
- **依据**：tab 窗口加载远程 origin（代理 `http://127.0.0.1:<port>` 或直连上游）；
  Tauri 2 对远程页面的应用自定义命令一律拒绝（框架自带测试
  `remote_origin_blocked_for_custom_commands_without_app_manifest`，tauri-2.11.5
  `src/webview/mod.rs:1823`），工程没有 app ACL manifest；`tab_title.js` 的
  `invoke('set_tab_title')` 必被 reject 而 `.catch` 静默吞掉 → 标签栏**永远显示 TITLE 默认名**，
  CI 与编译期全绿。旧静态守卫甚至把这条死命令钉成「已注册」（假绿）。
- **方案**：
  1. `tab_title.js` 改发核心事件 `web2app:tab-title`（`__TAURI__.event` →
     `__TAURI_INTERNALS__.invoke('plugin:event|emit')` 双通路，与 titlebar.js 设置按钮同法）；
  2. 新增 `capabilities/tabs-remote.json`：windows glob `tab-*` + remote
     `http(s)://*:*` + **仅** `core:event:allow-emit`（窗口类权限一律不给）；
  3. 删命令 `set_tab_title`，落地改为 `app.listen` → `tabs::report_tab_title`；
  4. 因 `app.listen` 的 Event 不携带发送窗口标识（2.11 实测 Event 只有 id/payload），
     建窗时注入一次性 128-bit token，payload 必须带回且与在册 tab 匹配，否则丢弃
     （防任意外部页面伪造其它页签标题钓鱼）。
- **回归**：静态守卫 3 条（capability 内容、事件名三处一致、脚本不得再出现应用命令）。

#### R-P1-2　多页签模式外部 HTTP 代理被所有 tab 绕过【Rust】
- **依据**：`additional_browser_args` 只挂在单窗口主窗 builder；多页签的宿主与 tab
  builder 都没有。WebView2 同一 user-data-folder 复用 browser 进程，`--proxy-server`
  仅在 browser 进程首次启动（第一个环境）时生效；多页签最先创建的是宿主窗口
  → `PROXY_ENABLED=true` + 外部代理 + `TABS_ENABLED=true` 组合下整组页签静默绕过代理。
- **方案**：宿主与 tab 两个 builder 都挂 `config::build_proxy_args()`（同源、None 时 no-op）。
- **回归**：静态守卫钉死生产代码段恰有两处调用点（自引用用 split(test) 排除）。
- **影响**：本地代理（无外部代理）与未启用代理场景行为不变。

#### R-P1-3　直连模式凭据对所有 origin 盲发【Rust，安全收口】
- **依据**：`webview_hooks.rs` 对 `"*"` 的每个 WebResourceRequested 无条件
  `SetHeader(Authorization)`，`BasicAuthenticationRequested` 对任意 401 都填账号密码
  → 第三方子资源 / 被注入内容诱导的外站请求/质询都能拿到入口凭据。Electron 壳
  `login` 处理器本来就有 `authInfo.host === new URL(target.url).host` 校验，两壳分叉。
- **方案**：新增纯函数 `bootstrap::origin_of`（scheme://host，默认端口归一化：
  `https://h` == `https://h:443`，`:8443` 不同源）与 `is_upstream_request`（失败关闭）；
  WR 过滤器读 `req.Uri()`、BasicAuth 读 `args.Uri()`，仅同源时注入/应答。
  `Navigation.upstream_host`（host-only，漏端口）升级为 `upstream_origin`，
  多页签 `resolve_popup_url_for` 同源判定同步改用源（顺手修了 `:8443` 抹端口误判）。
- **回归**：origin/白名单纯函数单测 8 个断言（异主机/异端口/异 scheme/None 全拒），
  弹窗同源测试补默认端口与非默认端口 2 条。
- **影响**：本地代理模式钩子整块不注册（`use_local_proxy` 原条件未动），不受影响。

#### R/E-P1-4　`WEB2APP_DEBUG` 真值集合两壳不一致【双壳】
- **依据**：Rust `flag_truthy` 认 trim+小写后的 `1/true/yes`；Electron 旧实现只认字符串 `'1'`
  → `set WEB2APP_DEBUG=true` 对 Tauri 壳生效、对 Electron 壳静默无效（逃生口形同虚设）。
  docs §3.5 一直宣称「逐字一致」，失实的是代码。
- **方案**：Electron 新增 `debugFlagTruthy()` 与 Rust 逐字对齐（刻意不认 `on`），单测钉住。
  文档无需改（原文案本就正确）。

#### E-P2-1　settings IPC 缺 sender 校验【Electron，纵深防御】
- **依据**：`settings-window.ts` 四个 `ipcMain.handle` 不校验发送者；内容视图目前
  不可达（preload 无 invoke 白名单），但 tabs IPC 已有 `assertShell` 范例，
  `save_settings` / `clear_web_data`` 是高破坏面通道，值得同纪律。
- **方案**：`assertSettingsSender`（与设置窗 webContents.id 比对，窗口不存在时拒绝）。
- **影响**：探针全部通过真实设置窗调用，断言零回归。

#### E-P2-2　sidecar 握手后异常退出无感知 / stopSidecar 重复调用叠加资源【Electron】
- **依据**：`exit` 处理器里 `finish(…)` 在握手成功后是 no-op → sidecar 崩溃静默，
  页面只会重试失败无日志；`stopSidecar` 第二次调用（进程未退出时）会再挂一个
  1s 定时器与 `once('exit')`（注释自称 once 防堆积，但每次是新闭包，仍叠加）。
- **方案**：exit 分支区分「握手前失败 reject」与「握手后异常退出 → 写启动日志」；
  WeakSet 记录在途停止，重复调用直接返回。

#### R-P2-1　bootstrap 无 scheme 校验【Rust】
- sidecar 显式只允许 http/https；Tauri 侧非 http(s) 配置时代理每条请求 502、启动页不报错。
  已在 `prepare_navigation` 加与 sidecar 同文案的 scheme 白名单。

#### R-P2-2　tab 首屏失败态被「done」吞掉【Rust】
- tab 首文档是 `dist/index.html`（有可见占位文案），overlay 模式 ~240ms 误判内容就绪淡出，
  之后 bootstrap 失败的 `fail()` 因 state==='done' 被忽略，用户停在占位页。
  修复：①`dist/index.html` body 清空（并加注释钉住）；②tab builder 在 OVERLAY_SCRIPT
  之前注入**按 origin 选择模式**的标记（本地资产页 `tauri.localhost/tauri:` → splash 语义
  不自动淡出，远程文档 → overlay 语义）；③占位页「重试」按钮发
  `web2app:retry-bootstrap` 事件（带 label+token，`retry_tab_bootstrap` 校验后重走
  bootstrap）；④`handle_splash /retry` 改为按**请求 webview 的 label**引导
  （原来硬编码 `"main"`，单窗口行为不变）。

#### R-P2-3　并发 bootstrap 互相 abort 代理【Rust 竞态】
- 首个 tab 解析未完成时新 tab 走缓存缺失分支会再起一轮 bootstrap：B 的成功收尾
  abort 掉 A 刚给在用 tab 起好的代理。改为后台轮询等待缓存（30s 上限），
  就绪后回主线程走缓存命中分支；只有超时（首轮失败）才回落完整 bootstrap。

#### R-P2-4　其它健壮性收口【Rust】
- bootstrap 线程 `catch_unwind`：CSPRNG 等 panic 不再让 detached 线程静默死亡，
  统一转成启动页可见错误；
- 托盘图标 `expect()` 改 `tauri::Error::InvalidIcon`（该函数也在设置切换运行期路径上，
  panic 会让进程因配置问题崩溃）；
- 代理 e2e 客户端改 `Client::builder().no_proxy()`，防开发机代理环境变量导致偶发红；
- `close_tab` 邻接选择抽纯函数 `plan_active_after_close`（11 条穷举单测，与
  Electron `tab-order.ts` 同义）。

## 五、遗留事项与建议（本轮刻意不改 / 无法在本机验证）

1. **Tauri 多页签改动缺真机 GUI 目视**：标题事件链路有框架源码（tauri-2.11.5）+
   capability 静态守卫 + Windows 编译保证，但「标签栏真实显示标题」「占位页失败态/重试」
   「tab 外部代理实际生效」需 `TABS_ENABLED=true` 出包后真机点验；Tauri 没有等价探针。
2. **CI Ubuntu / Android 作业实证**：新增 windows-only 常量已加 cfg，但本机无 GTK/NDK，
   非 Windows 编译要靠 push 后的 CI 确认（风险已按 09-23 纪律静态评估）。
3. **WS 子协议/握手响应头透传**：axum/tungstenite 合成 101 不回传
   `Sec-WebSocket-Protocol`/Extensions/握手 Set-Cookie，目标应用（Trilium）不依赖；
   属推断项，本轮不动。
4. **WS 半关闭排空 / 消息上限**：弱网最后帧与超大帧策略，需业务确认后再改。
5. **bootstrap 快速重试（splash 连点）**：Electron 已修成不自动循环；Tauri splash
   `/retry` 多次快速点击仍会 spawn 多个 bootstrap（成功幂等、失败各自报错），影响轻微。
6. **sidecar 运行期死亡后页面无法自愈**：Electron 侧已有退出日志（本轮），自动重启策略
   涉及「复用旧 URL 是否安全」的产品决策，未做。
7. **下载文件名 Windows 保留设备名（CON/NUL/COM1…）**：建议在 Rust/Electron
   文件名清洗各加一条，未纳入本轮。
8. **store.rs 跨进程/多线程文件锁**：当前依赖「写入方均在主线程」的隐含前提，
   已在注释中固化；未来若引入 async 命令需加进程内 Mutex。
9. **非 Windows 直连 + userinfo 静默无凭据**：Android 上 PROXY_ENABLED=false 且
   Basic 站点必然 401，仅启动日志可查；属产品形态确认项。
10. **Electron spawnTab 在途并发上限**：静态分析为不可达（首个 await 前已完成
    Map 登记，Node 事件循环串行化），未加锁，避免无效代码；如未来在检查前插入 await
    需重评。
11. **Electron login 白名单暂缺 scheme 维度（R1-A3）**：Electron `AuthInfo` 只给
    host:port、不带请求 scheme，无法在 401 事件里精确区分 http/https；Chromium
    mixed-content 对「https 页 → http 子资源」已默认拦截。待 Electron API 暴露更多
    请求信息后对齐成与 Tauri 相同的 origin 三元组比较。
