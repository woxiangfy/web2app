## 七、收口热修：CI Ubuntu 作业 `unused_mut`（同日追加）

### 7.1 现象与归因

CI 的 `lint-and-test`（**ubuntu-latest**）在 `cargo clippy --all-targets -- -D warnings` 阶段失败：

```
error: variable does not need to be mutable
--> src/lib.rs:807:13
error: could not compile `web2app` (lib test) due to 1 previous error
```

⚠️ **归因更正**：该行在 `HEAD` 版本里**已存在**（`git show HEAD:webview-app/src/lib.rs` 第 807 行），
**不是本轮新增的缺陷**，而是存量问题 —— 说明 Ubuntu 作业此前就一直红着。
本轮 §4.3 的「门禁复测全绿」跑的全是 **Windows 目标**，`cfg(windows)` 为真、`mut` 恰好被用到，
所以本地看不见。**本地门禁与 CI 门禁是互补关系，不是包含关系**：判据 A1 的取证口径本身有缺口（已记入 §7.6）。

### 7.2 根因

```rust
let mut sources: Vec<(&str, &str)> = vec![("dist/settings.html", …)];
#[cfg(windows)]
{
    sources.push(("src/shell.html", …));      // ← 非 Windows 目标上不参与编译
    sources.push(("src/tab_title.js", …));
}
```

平台差异被写进了**可变性**：非 Windows 目标（Ubuntu / Android）里那次 `push` 被 cfg 剔除，
`sources` 从未被改 ⇒ `unused_mut` ⇒ `-D warnings` 下编译失败。

### 7.3 修法（把平台差异从「可变性」移到「数据」）

```rust
#[cfg(windows)]
const PLATFORM_SOURCES: &[(&str, &str)] = &[("src/shell.html", …), ("src/tab_title.js", …)];
#[cfg(not(windows))]
const PLATFORM_SOURCES: &[(&str, &str)] = &[];

fn frontend_sources() -> Vec<(&'static str, &'static str)> {
    std::iter::once(("dist/settings.html", …)).chain(PLATFORM_SOURCES.iter().copied()).collect()
}
```

`mut` 彻底消失 ⇒ 任何目标上都不可能再出现 `unused_mut`；断言覆盖范围**与改前逐项相同**
（Windows 三份页面；非 Windows 只验设置页 —— 与旧 `#[cfg(windows)]` 语义一致，零行为变化）。

### 7.4 取证（含反向对照）

| 步骤 | 做法 | 结果 |
|:--|:--|:--|
| 复现 | 该处 `#[cfg(windows)]` 临时换成 `#[cfg(any())]`（模拟非 Windows cfg 状态） | ✅ 复现**逐字一致**的报错：`variable does not need to be mutable` + `could not compile web2app (lib test)` |
| 修复后同状态 | 两个 const 临时换成互斥分叉 | ✅ `clippy --all-targets -D warnings` 退出码 **0**；`test -p web2app --lib` **74 通过** |
| 还原 | 换回 `cfg(windows)` / `cfg(not(windows))` | ✅ `sha256sum -c` → `src/lib.rs: OK` |
| Windows 全套 | `fmt --check` / `check --all-targets` / `check`（`TABS_ENABLED=true`）/ `clippy --all-targets -D warnings` / `test --all` | ✅ 全绿，单测 **116**（13 + 7 + 22 + 74） |

> 模拟手法自身的坑：第一版把两个 const 写成 `#[cfg(any())]` / `#[cfg(all())]`，`unused_mut` 虽已消失，
> 却因**无条件 cfg** 被 clippy 判为 `non_minimal_cfg` 而报错 —— 那是模拟语法的噪声，与被测代码无关。
> 改用互斥的 `#[cfg(target_os = "linux")]` / `#[cfg(not(target_os = "linux"))]` 后干净。
> ⇒ 用 cfg 模拟另一个目标时，**模拟本身也要过 lint**，否则会把噪声当成结论。

### 7.5 同类隐患排查

全仓库扫描「`let mut` 声明在 cfg 之外、变更只发生在 cfg 块内」的模式：**仅此一处**。
`src/web_data.rs` 的两个 `let mut`（`labels.sort()` 在同一函数体内、`reloaded` 位于 `#[cfg(windows)]` 函数内部）
都在自身 cfg 边界内，安全。

### 7.6 结论与约定（本轮新增纪律）

1. **平台差异只允许落在数据上，不允许落在可变性上** —— 否则「只在某个目标上成立的代码」
   会去影响另一个目标上的 lint，而 `-D warnings` 把 lint 升格为编译失败。
2. **`cfg` 分叉的两侧都要能被检查到**：本机只能跑 Windows 目标，Ubuntu / Android 的 cfg 分支
   只能靠 CI（本机无法真跑：Linux 目标缺 GTK / WebKit2GTK，Android 缺 NDK）。
   ⇒ 本地「全绿」**不得**表述为「CI 会绿」；提交前若改动了带 `#[cfg(...)]` 的代码，
   应显式列出「未在本机覆盖的 cfg 分支」。

### 8.3 落点搬家的语义（本轮唯一有静默风险的改动）

`settings.json` 由「固定 `%APPDATA%\<app_name>\`」改为「**写入 = `<data_dir>\settings.json`**」时，
**读取**刻意保留旧位置：

```
读取候选 = [ <data_dir>\settings.json , %APPDATA%\<app_name>\settings.json ]   （新位置优先）
写入位置 =   <data_dir>\settings.json                                          （只写新位置）
```

风险点：两个写入方（设置页保存 / 关窗记几何）都走**读-改-写**，
若「读」只读**写入位置**（新位置为空）而「写」写新位置，则升级后**第一次保存会把老设置清零**。
⇒ 契约定为「读-改-写的**读**也走同一份候选」（Rust `store::update_with` / Electron `readRawForUpdate`），
并由 `store::tests::update_reads_legacy_but_writes_new_location`（断言旧文件字节不变）
与探针「落点搬家」两条**双向钉住**。旧文件**不迁移、不删除**（升级可回退）。

### 8.5 本轮暴露的一条新教训

**「跑探针前必须先构建」同样适用于 Rust 侧的视觉取证**：直接用 `target\debug\web2app.exe`
目视设置窗时，若此前只跑了 `cargo test` / `check`（**不刷新** exe），看到的是**旧界面**，
会误判「改了没生效」。判据：比 exe 与源文件 mtime，或在 exe 的 ASCII 里搜本次新增的字符串常量。
（既有教训「`cargo test` 不刷新 exe」的**跨领域复现**——原教训只说 Rust 二进制，本轮证实它同样会
污染「改 UI 后的目视验收」。）
