## v1.79（2026-10-12）：区域圆回退为与活柱严格重合 + Tauri 球页自绘不透明黑底（壳标记注入，Electron 不命中）

### 真机症状

v1.78 打包后真机截图：蓝色悬浮球约 10 点 / 2 点钟方向出现浅灰白块，形状的**外边界是以球心
为圆心的阶梯圆** —— 与 v1.77b 之前两轮「不选中时背景异样」的残片同形。即 v1.78 外扩
`REGION_PAD_LOGICAL = 4px` 的那圈环带里漏出了浅色东西。

### 根因（读 crate 源码坐实，比 v1.78 决策时的认知更深一层）

- **wry 0.55.1**（`webview2/mod.rs`）在 Windows 只创建 HWND 版
  `CreateCoreWebView2Controller`（全文件无 CompositionController），透明时仅
  `SetDefaultBackgroundColor(0,0,0,0)`。
- **tao 0.35.3** 虽有 `with_no_redirection_bitmap`（控制 `WS_EX_NOREDIRECTIONBITMAP`
  与 `DwmEnableBlurBehindWindow`），但 **tauri-runtime-wry 2.11.4 完全不透传**该属性
  （只有 transparent）。
- 结论：这条旧透明链路上，页面**全透明像素能透出桌面，半透明像素（border-radius 的抗锯齿、
  box-shadow）被压平到白底**。
  - v1.77b（pad=0，球 == 区域圆）：1bit 区域硬边界切过 CSS 圆边的 AA ⇒ 白锯齿（毛刺）；
  - v1.78（pad=4）：环带里的半透明 AA / 阴影漏成浅色异形（本次）。
  - 同一机制的两面，几何上无解。Electron 侧走真 DirectComposition alpha，不受此限。

### 方案（v1.79 定稿）

1. **区域圆恢复与活柱 / 球严格重合**：`CreateEllipticRgn(x1, 0, x2, lh)`，删除
   `REGION_PAD_LOGICAL` 常量与 `region_pad_px()`。
2. **页面自绘不透明黑底（仅 Tauri）**：`floaticon.html` 新增
   `html[data-w2f-shell="tauri"] body { background: #000; }`。球缘 AA 在页面内部先合成成「蓝→黑」
   的深色暗边 —— 送进 WebView 的帧在圆缘处全是不透明 RGB，绕过坏掉的 alpha 链路；区域严格
   裁圆，圆外黑像素被 SetWindowRgn 整像素裁掉；黑锯齿在深色桌面近似自然阴影边。
3. **壳标记在文档最早期注入**：`floatwin.rs` 的 `initialization_script()` 扩展为
   `document.documentElement.setAttribute('data-w2f-shell', 'tauri')`（首帧前执行，
   on_page_load 再 eval 会闪一帧无黑底）。Electron 不注入 ⇒ 选择器不命中 ⇒ 保持真透明。
   双壳共用同一份球页，Electron 代码不动（仅更新注释）。

## v1.80（2026-10-12）：弃黑底绕路 —— 升级 Tauri 2.12 走真逐像素 alpha + WM_NCHITTEST 圆形命中（视觉/命中分离，双壳同构）

### 真机反馈与方向反思

v1.79 打包后真机：浅色异形确实消失，但球缘**仍有轻微锯齿**（黑底把轮廓固定成整像素
阶梯）。结论：v1.77b→v1.79 三案都在「视觉与命中耦合在 1bit 窗口区域 / 页面绕路」这条
思路里打转，几何与底色都救不了坏掉的 alpha 链路。正确方向是让窗口本身具备**逐像素
alpha** —— Electron 壳早已走的 WS_EX_NOREDIRECTIONBITMAP + DirectComposition 路径。

### 版本调研（读 crate 源码坐实升级可行）

- **tao 0.35.3**：`transparent && !no_redirection_bitmap` 只调
  `DwmEnableBlurBehindWindow` + 空 region；只有 `NO_BACK_BUFFER` 才加
  `WS_EX_NOREDIRECTIONBITMAP`。
- **tauri-runtime-wry 2.11.4**：完全不透传 `no_redirection_bitmap`（只透传
  transparent），transparent 时还用 softbuffer fill 清顶层 surface。
- **tauri-runtime-wry 2.12.1**：已透传 `.no_redirection_bitmap(...)`；tao 0.37 双开时
  跳过 blur-behind；tauri core 2.12.1 的
  `WebviewWindowBuilder::no_redirection_bitmap(enable)` 存在。
- 版本涟漪及落地（`Cargo.toml` + `cargo update --precise`，Cargo.lock 已更新）：
  tauri 2.11 → **2.12.1**、wry 0.55 → **0.57.0**、tao 0.35 → **0.37.1**（`Cargo.toml` 约束写 `0.37`、`Cargo.lock` 锁 `0.37.1`）、
  webview2-com 0.38 → **0.39.1**、windows 0.61 → **0.62.2**。旧代码 `cargo check`
  零涟漪（0.62 仅 `BOOL` 移到 `windows::core`、部分 API 参数包 `Option` 两处适配）。

### 架构（v1.80 定稿）

1. **视觉真 alpha**：球窗 builder 同开 `.transparent(true).no_redirection_bitmap(true)`
   ⇒ WS_EX_NOREDIRECTIONBITMAP + DComp，border-radius AA / box-shadow 逐像素合成。
2. **命中走 WM_NCHITTEST 子类化**：**删除全部 SetWindowRgn / CreateEllipticRgn**，新增
   `install_circle_hit_test`：`EnumChildWindows` 递归枚举父窗 + 全部后代子窗
   （WebView2 子窗覆盖整个客户区，只拦父窗拦不住），`SetWindowLongPtrW(GWLP_WNDPROC)`
   幂等子类化；新过程只拦 WM_NCHITTEST，屏坐标经 `ScreenToClient` 转父窗客户区，圆内调
   原过程（HTCLIENT）、圆外回 `HTTRANSPARENT`；WM_NCDESTROY 还原。圆心 / 半径存静态
   原子量（0 = 未初始化 fail-open），`update_hit_circle` 替代旧 `apply_live_region`，
   调用时机不变（建窗后 / on_page_load / Resized / ScaleFactorChanged）。
3. **页面恢复真透明**：初始化脚本回退为只注入一次性令牌（删除 `data-w2f-shell` 壳标记
   注入）；页面删除 `html[data-w2f-shell="tauri"] body { background:#000 }` 整规则。
   双壳现在同一份页面、同一种合成路径、无任何壳判断。
