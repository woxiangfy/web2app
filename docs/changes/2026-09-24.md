## v1.31（2026-09-24）

**本地打包入口改为 Node 实现（去掉 Python 依赖）**：①**动机**——`scripts/pack-local.py` 依赖 Python，但 Python **不是**「拿着这个仓库就一定有」的依赖：实测本机 PATH 里的 `python` 来自会话注入（`~/.workbuddy/binaries/python/…`），系统既无 `py.exe` launcher 也无任何 Python 安装 ⇒ 出会话即 `command not found`；而打 Electron 包**必然已有 node**（`electron-builder` 是 node 程序，`pnpm run sidecar/build/stage` 全是 node 脚本）⇒ 新增 **`scripts/pack-local.mjs`**（ESM、零第三方依赖、需 Node ≥ 18），删除 `pack-local.py`；②**代价与护栏**——解析逻辑从此有两份实现 ⇒ 内置 `--selftest`（契约自测，不需要 Python）与 `--parity`（对 **39 个 payload** 与 `.github/scripts/parse-packaging-config.py` 逐项比对：退出码 / `::warning::` 序列 / 错误文案 / `config.json` 字节；缺 Python 时明确报「跳过」而非假装通过），两者均接入 `ci.yml` 的 `config-contract` 作业（Linux 上两侧都是 LF ⇒ 比对逐字节；本机 Windows 的 Python 会把 `\n` 翻成 `\r\n`，`--parity` 把它降级为「仅行尾不同」的汇总提示并说明 CI 不受影响）；③**逐字复刻**——`difflib.SequenceMatcher` 相似度（近似名建议，**不是** Levenshtein）、Python `str()` / `repr()` 语义（`True` / `None` / 容器 repr）、全部 warning 与报错文案、`REMOVED_KEYS` 迁移指引、`data_dir` 空串保留语义；④**天然绕开的三个坑**——不落 env 文件 ⇒ `--env-out` 的 CRLF / heredoc / append 三坑不存在；⑤**新增加固**——传给子进程的环境里剥掉 `ELECTRON_RUN_AS_NODE`（本机 shell 里它是 `1`；对普通 node 无害，但会让子进程里任何 **electron 可执行文件**退化成 node 模式）；⑥**端到端实证**（`--config test2.json --target electron-all --out tests/pack-node`）：产物 `osfipin.test-0.1.0-win-x64.zip`（148M）/ `-portable.exe`（97M）文件名来自 JSON 的 `app_name`、`check-asar-config.cjs` 护栏通过（asar 24 条目）、包内 `out/config.json` **14 字段**（`tabs_enabled` 真 bool、`debug` 自动补默认值、无 `android_*`）、`electron-app/config.json` 打包后**逐字节还原**（sha256 `5b3458db455f`）；⑦文档：`docs/packaging-config.md` §7.3 重写（新增两条护栏对照表）、根 `README.md` §二 的 `scripts` 登记行同步

## v1.32（2026-09-24）

**本地打包「JSON 定义行为」两处纠正 + `--parity` 诊断补强**：①**图标判据**——`icon_url` 非空即下载并应用（判据与 CI 的 `if [ -z "$ICON_URL" ]` 逐字同源），**删除**原先额外要求的 `--icon` 开关（那等于把「配置说了算」变成「命令行说了算」：同一份 JSON 在 CI 带图标、本地不带），保留 `--no-icon` 作逃逸口；应用图标会**同时**覆盖 `webview-app/icons/icon.png`（Electron 托盘取自 `extraResources`，只设 `-c.win.icon` 对托盘无效），打包后整份还原（实测 sha256 `4cff2467101e` 一致）；②**输出目录不再需要人工介入**——先让 electron-builder 按常规流程清 `release/`，**只有它被删除策略拦住时**才自动换 `release/local-<时间戳>/` 重试一次。⚠️ 中途试过「脚本先自己清一遍」，实测**反噬**：本机删除有配额（`SAFE_DELETE_BULK_CONFIRM_REQUIRED`，50 次/轮），清一次上千个文件把配额烧光 ⇒ electron-builder 连自己的中间产物 `*.nsis.7z` 都删不掉，zip / portable **明明已产出**却以「失败」收尾；改为「不清、被拦才换目录」后同一环境 `PACK_EXIT=0`；③**`--parity` 诊断补强**——`spawnSync` 的 `error` 原先被吞，进程起不来时只报「退出码 null」；现区分「**未能验证**」（spawn 失败＝环境限制，退出码 2）与「语义不一致」（退出码 1）。本机实测：PATH 上那份 `python` 从 Node 里 spawn **恒定 EBUSY**（需兜底到绝对路径），连续 spawn 到第 ~37 次再次 EBUSY ⇒ 本机 `--parity` 可能留少量用例未验证（CI 是 Linux，无此限制）；④**端到端实证**（`--config test1.json --target electron-all`，`app_name=osfipin.test`，`icon_url` 是 256×256 PNG）：第一次尝试被 `safe-delete` 拦住 → **自动**换 `release/local-20260924-215645` 重试 → 产物 `osfipin.test-0.1.0-win-x64.zip`（147.7M）/ `-portable.exe`（96.7M）、`asar 配置护栏通过 ✓`、包内 `out/config.json` 与 test1.json 一致（`tabs_enabled` 为**假**，正好证明吃的是 test1 而非 test2；`debug`/`proxy_bypass` 为自动补的默认值；无 `android_*`）、`config.json` 与 `icons/icon.png` 均逐字节还原、全程 `PACK_EXIT=0`；⑤文档：`docs/packaging-config.md` §7.3 新增「本地行为一律由 JSON 决定」对照表
