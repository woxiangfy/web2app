# 变更记录 · 2026-10-13

> 多页签「首页页签」：默认入口地址（app_url）那一签**固定在第一位、不允许关闭**，
> 页签名字前带一个房子图标作标记。双壳同时落地（规则真源在宿主侧，渲染在共享 `shell.html`）。

---

## 需求与判定口径

用户原文：「Windows 版本 多标签页 默认打开的首页(app_url) 固定在第一个位置 且不允许关闭，
页签名字前面加一个主页的小图标。目的是 这个首页是一定要有的 且有特定标记。」

关键设计取舍：**首页 = 多页签列表的位次 0**（不给 `TabInfo` / `Tab` 加状态字段）。
理由：入口那一签是本进程**第一个**建出来的 tab，而它不可关闭 ⇒ 它永远占着下标 0。写成位次判定
就同时拿到三条不变式，不需要再多一份可能漂移的状态：

| 不变式 | 由什么保证 |
| :-- | :-- |
| 固定第一位 | 列表其余项只做尾部追加（`tabs.push` / `Map.set`）与按位删除，0 号位不会被顶走 |
| 一定存在 | 唯一的删除入口（`close_tab_inner` / `closeTab`）对本位次**直接拒绝** |
| 自动补齐 | 空壳自愈路径（`set_tabs_visible` / `presentMainWindow`）补出来的那一个自然就是首页 |

规则真源两处（双壳必须给同一答案，两侧各配守卫）：
`webview-app/src/tabs.rs::is_home_index` ∥ `electron-app/src/main/tab-order.ts::isPinnedHome`。

# 追加 · 移动端底栏三缺陷修复（同日第四轮）

> 真机反馈三个问题：① 页面底部的悬浮按钮（FAB）被底栏切掉半截；② `tabs_enabled=true`
> 时底栏没有「列表」；③ 页面加载转圈时遮罩把底栏也盖住，加载期间无法操作底栏。
> ③ 与 ② 合并实施：移动端补齐【单 webview 页签记录】，加载层让出底栏。

## 问题 1：贴底 FAB 被挡（`mobilebar.js`）

- 根因：`applyChromeFit()` 旧实现要求贴底元素「宽 ≥ 半屏」才上移 —— FAB / 客服球一般只有
  40–64px 宽，被整类漏掉。
- 修复：`position:fixed` 的贴底元素**不再设宽度门槛**（fixed 的包含块就是视口，窄也能确定是
  贴底件）；sticky/absolute 仍要求半屏宽（absolute 还要求底边真压视口底），避免内部容器误判。
- 新增 `shiftedBottom(declared)`：元素原 `bottom:Npx` 上移后保留为
  `calc(52px + env(safe-area-inset-bottom,0px) + Npx)`，不再把悬浮按钮顶死在栏边上；
  auto / 非 px 单位回退贴齐底栏上沿。
- `scheduleChromeFit()` 补 `pageshow`（bfcache 恢复）与 5s / 9s 两拍延迟，覆盖首屏后 3–8s
  才异步挂出的客服 SDK 悬浮球。

## 问题 2：移动端单 webview 页签（`mobilebar.rs` + `mobilebar.js` + `config.rs`）

- 平台事实：Tauri/wry 在 Android **不支持同一窗口挂多个子 webview**（`WebviewBuilder` 文档对
  Android/iOS 标注 Not supported；2.12 的多窗口是 Activity Embedding 平板分屏）。故移动端页签
  与桌面端（`tabs.rs`：多个真实 webview 并行、状态保留）本质不同：
  - 壳侧新增纯逻辑状态机 `MobileTabs { tabs: Vec<MTab{label,url,title}>, active, seq }`：
    `reset_home` / `new_tab` / `switch` / `close`（首页 Blocked；关活动标签导航到左邻；
    关后台标签只刷列表；序号只增不复用）/ `observe`（内置页与空标题不覆盖）/ `rows_json`
    （与桌面端同形四元组 `[label,title,active,home]`）。
  - 接线：`new-tab` / `switch-tab` / `close-tab` / `request-tabs` / `mobile-doc` 五个事件
    （`setup()` 共 6 个监听）；切换/新建前先 `bind_current_url` 保住旧标签落点；
    `on_page_finished` 挂进 `bootstrap::on_page_load` 的 finished 分支；同落点退化为 reload。
  - 前端：列表面板顶部加「＋ 新建标签」行；开面板时 emit `request-tabs` 拉最新行；
    新增 `watchDoc()`（DCL/load/pageshow/popstate/hashchange/title MutationObserver +
    pushState/replaceState 包装，150ms 防抖）经 `mobile-doc` 上报 `{title,url}`。
  - `config.rs::TABS_ENABLED` 去掉 `cfg!(windows) &&` 钳制（v1.53 起的非 Windows 恒 false
    至此解除）；`tabs_available()` 直接取该常量。仅开 `tabs_enabled` 不开 `mobile_bar` 时
    移动端无入口（按钮在底栏里），不会产生异常界面。

## 问题 3：加载层让出底栏（`loading.js` + `mobilebar.js`）

- 镜像顶部 titlebar 已有的 `window.__web2appChromeH` + `web2app:chrome-ready` 协议，新增
  `window.__web2appMobileBarH`：底栏脚本 document-start 先给内容区高度 52 的首帧近似值
  （写在「内置启动页早退」之后 —— 启动页没有底栏），挂好后用 `getBoundingClientRect()`
  实测值（含安全区）纠正并广播；resize / orientationchange 重新上报。
- `loading.js::applyChromeOffset()` 同时读顶 / 底两个全局，设置 top/bottom 且**显式把
  height 改成 `calc(100vh - top - bottom)`**（只设 bottom 挡不住 `height:100vh` 的层继续
  铺满底部）。加载转圈期间底栏始终可见、可点。
