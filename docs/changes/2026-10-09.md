## v1.59（2026-10-09）

**Tauri 壳支持网页登录密码保存（气泡询问 + 下次自动填充），与 Electron 壳默认行为对齐**（使用者需求：「需要支持保存密码功能」）：

- **背景（两壳行为不一致）**：Electron 壳基于 Chromium，密码管理器**默认开启**——登录表单提交即弹「保存密码？」、保存后下次访问自动填充；Tauri 壳的 WebView2 对应开关 `ICoreWebView2Settings4::IsPasswordAutosaveEnabled` **默认 `false`**（MSDN 明确：默认既不弹保存/更新气泡，也不保存新密码；一般表单自动填充是另一个独立开关、默认 true），两壳在同一站点上行为分叉。两壳均无自研密码管理。
- **修复（`src/webview_hooks.rs`，最小改动）**：在 `register_webview_hooks()` 的 DevTools 段之后新增「0b) 网页登录密码自动保存」段——拿到 `core.Settings()` 后 `cast::<ICoreWebView2Settings4>()`，成功即 `SetIsPasswordAutosaveEnabled(true)`。
  - 接口门槛选 **Settings4**（WebView2 Runtime 1.0.902.49+，2021 年起随系统分发）而非 Profile6（1.0.1823+）：现存机器基本都满足，cast 失败的极老运行时静默跳过、保持默认行为——与下载（`ICoreWebView2_4`）、右键菜单（`ICoreWebView2_11`）钩子同口径：单项不可用绝不影响其它钩子注册。
  - 该属性是 **per-webview** 的，每个窗口注册钩子时各设一次；所有窗口共用同一个 WebView2 用户数据目录（`config::data_dir`），多页签下各 tab 保存的密码互通。已保存密码随设置页「清除全部浏览数据」（`ClearBrowsingDataAll`）一并清除。
- **测试**：新增静态契约测试 `contract_tests::webview2_password_autosave::enabled_via_settings4_on_every_webview`（`#[cfg(windows)]`），断言钩子源码包含 `ICoreWebView2Settings4` 与 `SetIsPasswordAutosaveEnabled(true)`，防止回归为静默关闭。主 crate 105 → **106**，工作区 **179 通过 / 6 ignored**（resolve-core 19 + resolve-tool 22 + w2a-proxy 32 + 主 crate 106）。
- **真机验证（2026-10-09，本机 WebView2 Runtime `154.0.4258.62`，零 CDP 注入）**：用仓库根 `tests/pw-fixture/`（gitignored）的零依赖 Node 登录夹具站（GET 表单 → POST `/login` 成功页 → 8s 跳 `/again` 空表单）配合 SendInput 硬件级键盘输入实测：
  1. **反向对照**：同机把开关临时置 `false` + 全新数据目录，真实键入账号密码提交——**无保存气泡、无自动填充**；
  2. **正向链路**：置 `true` + 全新数据目录，硬件键入 `testuser` / `TestPass-123` 回车提交——成功页右上角弹出「**保存密码？** 你的密码将在下次自动填充，并将保存到你的设备」气泡（用户名/密码预填、保存/以后再说）；点击「保存」后直接读取 WebView2 `Login Data` SQLite（只统计条数、不导出凭据值）确认新增 **1 条**夹具源记录；跳转 `/again` 后用户名/密码框**自动填充**（带 Chromium 自动填充底色）。运行期诊断日志另确认 `cast=Settings4 ok`、`SetIsPasswordAutosaveEnabled(true) => Ok(())`（诊断代码已在合入前移除）。
  3. **两个取证注意点（Chromium 行为，非本壳缺陷）**：① JS 程序化预填（`input.value=…`）+ `form.submit()` 或真实回车**不会**触发保存气泡——Chromium 要求凭据来自真实键入；自动化验证必须用 SendInput 逐字输入。② 连续 3 次左右不处理/关闭气泡会触发 Chromium 的「忽略次数配额」，后续提交暂时不再弹气泡；换新数据目录即复位。
  4. 另外确认：气泡是 `msedgewebview2.exe` 子进程的独立 HWND，按宿主 PID 的 PrintWindow 抓不到，需用屏幕区域抓取；自动化点击「保存」要按窗口内相对坐标精确定位（气泡锚定在 WebView 右上角）。
