# 2026-10-27 变更记录

## 一、悬浮球 v1.81：边缘毛刺根治 + 背景自适应 + 四边吸附（双壳）

背景（用户三轮拍板）：悬浮球三项缺陷 —— ① 边缘毛刺**依旧存在**（v1.77b–v1.80 四轮修补均未根治，
用户明确否定一切「CSS 画圆打补丁」路线，目标**彻底消除**）；② 盘面蓝色渐变不好看，应跟随系统
深浅色白 / 黑（或透明）；③ 吸附只支持左 / 右，希望支持顶部等更多边。
实施文档：`.trae/documents/悬浮球渲染与吸附重构方案.md`（已拍板）。

### 1. 根因定性（v1.77b–v1.80 失败链存档）

毛刺三源**全在「浏览器 CSS 画圆」这条链上**：

- 透明窗上 `border-radius` 圆角裁剪的抗锯齿（Chromium 对白底合成再套 alpha 掩码 ⇒ 白边 / 毛刺）；
- `filter: brightness()` 状态反馈强制合成层、`radial-gradient` 渐变抖动；
- `translate(-50%,-50%)` 在非 1 / 4 整数倍 DPI 下落到分数物理像素（阶梯毛刺）。

v1.77b `SetWindowRgn` 严格裁圆（1bit 硬边切 AA）、v1.78 区域外扩（半透明压平白底）、
v1.79 页面自绘不透明黑底（暗锯齿）、v1.80 `WS_EX_NOREDIRECTIONBITMAP` 真逐像素 alpha
（合成路径对了，但圆角仍在 Chromium 裁剪里）—— **圆的边缘只要经过浏览器裁剪 / 合成管线，
就一定有毛刺**。故 v1.81 让圆的边缘彻底离开浏览器。

### 2. Tauri 侧：球窗原生化（Win32 分层窗口 + 位图 alpha）

- **建窗**：弃 WebView2 球窗（`WebviewWindowBuilder` 链整体退役），改 `CreateWindowExW`
  自注册窗口类 `web2app_float_ball`：`WS_EX_LAYERED | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE |
  WS_EX_TOPMOST` + `WS_POPUP`，样式**创建时一次定死**（v1.77 的 `GWL_EXSTYLE` 补丁 /
  `ITaskbarList::DeleteTab` 连同任务栏问题一并消失）。文件：`webview-app/src/floatwin/native.rs`
  （新建，923 行）。
- **渲染**：`UpdateLayeredWindow`（`ULW_ALPHA` + `AC_SRC_OVER` / `AC_SRC_ALPHA`）提交
  **32bpp 预乘 ARGB**（`premultiply_bgra` 最后统一预乘、BGRA 字节序、`biHeight: -h` 顶向下）
  位图；圆盘由 **4×4 超采样**画出（`const SS: i32 = 4`，覆盖率 alpha = `cnt / (SS*SS)`）+
  1px 半透明描边 + `include_bytes!("../../icons/icon.png")` 图标**面积平均**叠加（`composite_icon`）。
  **圆轮廓就是位图 alpha**，系统合成器逐像素合成 —— 无 CSS、无裁剪、无窗口区域。
- **命中**：分层窗口天然按**像素 alpha 穿透**（alpha=0 自动透传点击，含跨进程）⇒
  `WM_NCHITTEST` 子类化 / 命中圆原子量 / 「活柱」/ 窗口区域 / WebView2 最小宽 hack **全部退役**。
- **主题自适应**（缺陷②）：弃蓝色渐变（`radial-gradient(#6a9bff …)`），读注册表
  `HKCU\…\Themes\Personalize\AppsUseLightTheme`（`fn apps_use_light_theme`）决定
  **平涂白 (255,255,255) / 近黑 (30,30,32) 底盘**，监听 `WM_SETTINGCHANGE |
  WM_DWMCOLORIZATIONCHANGED` 重绘；hover 提亮 / 半隐藏压暗只改平涂色（亮度系数）。
- **交互全进 WndProc**（`webview-app/src/floatwin/events.rs` 状态机重接原生窗）：
  `on_down` / `on_move`（物理屏幕坐标 + 抓取偏移，`DRAG_THRESHOLD_LOGICAL = 5.0`）/
  `end_press(canceled)` 分派 `on_drag_end` / `on_cancel` / `on_click`（`CLICK_DEBOUNCE_MS = 250`
  去抖）/ `on_right_click`（关功能 + 唤回主窗）/ `on_peek_enter` / `on_peek_leave`（300ms 延迟
  + 真实光标校验）。
- **退役清单**：球页 → Rust 的一次性令牌 + 8 事件链（`token_matches` / `__web2appFloatToken` /
  `web2app:float-*`）、`floaticon://` 协议注册、`capabilities/float-icon.json`（**已删除**）、
  `floatwin/{shape,window}.rs`（已删除）、`SetWindowRgn` 整条失败链 —— 无球页 = 无 IPC 攻击面。
- **保留**：`ball_hwnd` 重导出（floatprobe 真机取证用）；`FloatState` 与几何纯函数全部纯化。

## 二、Electron NSIS：默认安装路径套娃根治（appId 随安装名变化）

**现象**：`tests/build-electron-nsis.bat`（`--config json/osfipin.note.json`）出的安装包，用户反馈默认
安装路径是 `…\AppData\Local\Programs\osfipin.note\osfipin.mark` —— 两层，且内层是**另一个应用**
（osfipin.mark）的名字。

**根因**（不是打包脚本拼错路径）：

1. `electron-builder.yml` 里 `appId` 写死 `com.example.web2app`，`packlib/driver-electron.mjs` 的
   `builderCmd` 只覆盖了 `productName` / `version`，**没覆盖 appId** ⇒ 本仓库出的每个应用共用同一个 appId。
2. NSIS 用 `UUID.v5(appId)` 生成 `APP_GUID`，而 `APP_GUID` 决定安装登记键
   `HKCU\Software\{APP_GUID}` 的 `InstallLocation`（`templates/nsis/multiUser.nsh:26-28`）。
   先装 A、再装 B 时，B 的安装包读到 **A 的** `InstallLocation` 并沿用它。
3. 向导式安装（`oneClick: false`）还会跑 `templates/nsis/assistedInstaller.nsh::instFilesPre`：
   `$INSTDIR` 里若不含 `${APP_FILENAME}` 就追加一层（`assistedInstaller.nsh:34-36`）⇒
   `…\Programs\<A>` + `\<B>` = 套娃路径。卸载注册项（`UNINSTALL_APP_KEY` 同样取自 GUID）也会互相覆盖。

**修复**：`scripts/packlib/util.mjs` 新增 `appIdFor(name)`（安装名 → `com.web2app.<name>`，仅保留
`[a-z0-9.-]`），`driver-electron.mjs` 传 `-c.appId=${appIdFor(name)}` —— appId 随应用唯一 ⇒
GUID / `InstallLocation` / 卸载项各自独立。自测：`scripts/packlib/selftest.mjs` 新增 4 条断言
（`--selftest` 全通过）。

**升级影响**：appId 变了 ⇒ 旧包的注册键不再被新包识别（不自动覆盖旧安装），需先卸载旧包或删掉
`HKCU\Software\{旧 GUID}` 再装。`electron-builder.yml` 里的 `com.example.web2app` 仅作兜底默认值。

**Tauri 侧对照（刻意不改）**：`webview-app/tauri.conf.json` 的 `identifier` 同样写死
`com.example.web2app`，但 `.github/workflows/release.yml:87` 明确「Windows 侧不改 identifier ——
MSI/NSIS 的升级码依赖它，改了会破坏覆盖升级」，属既定决策而非漏改；Android 包名另由
`prepare-android-conf.py` 按 `app_name` 派生（同为本节的 `com.web2app.<seg>` 方案），与本轮 Electron 修复同源。
