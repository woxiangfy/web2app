# 变更记录 · 2026-10-15

> 修复 Android 打包链路故障：补丁链执行时 wry 的 `RustWebViewClient.kt`
> 等 Kotlin 文件尚不存在（`FileNotFoundError`）。新增两个前置脚本

> 覆盖后重打」双层闭环；排查中又修掉三处会让真实构建失败/变慢的二次缺陷
> （Gradle 9 移除 `Project#exec`、release 白编 debug、cargo metadata
> 定位分支从未生效）。任务清单仍以
> [android-improvements.md](../android-improvements.md) 为唯一真源。

## 1. 故障现象

CI Android job 在 `apply-android-labels.py` 之后执行 `patch-android-extras.py`
时报错（build-custom.yml / release.yml 同样路径必现）：

```
已给 gen/android/app/src/main/java/com/.../MainActivity.kt 注入 JS 桥
FileNotFoundError: 未找到 gen/android/app/src/main/java/**/RustWebViewClient.kt
```

Android job 挂着 `continue-on-error: true`，失败会被「尽力而为」语义掩盖，
表现为出不了 APK 但流水线不红。

## 2. 根因（时序错位，取证于 tauri-cli 2.12.2 / wry 0.57.0 源码）

1. `cargo tauri android init` 只把 `MainActivity.kt` 生成到
   `app/src/main/java/<包名>/`（模板在 tauri-cli 的
   `templates/mobile/android/app/src/main/MainActivity.kt`，仅 `onCreate`）。
2. wry 的 9 个 Kotlin/proguard 文件（`RustWebViewClient.kt`、
   `RustWebChromeClient.kt` 等）由 **wry 的 `build.rs`** 在
   **`tauri android build` 的 Rust 编译阶段**动态生成，落点是
   `app/src/main/java/<包名>/generated/`（tauri-cli `android/mod.rs`
   设置 `WRY_ANDROID_KOTLIN_FILES_OUT_DIR`；`build.rs` 遍历
   `src/android/kotlin/`、替换 5 个占位符、仅内容变化时写盘）。
3. 我们的补丁脚本在 **init 之后、build 之前**运行 —— 那时 `generated/`
   目录还不存在，`android_gen.find_kotlin_file()` 的 `rglob` 必然扑空。
4. 即便提前把文件放进去，wry `build.rs` 在 cargo 编译时还会用模板产物
   **覆盖** `generated/`，提前打的补丁同样保不住。

## 3. 双层修复

### 3.1 `.github/scripts/prepare-wry-kotlin.py`（新增，补丁链前置）

在补丁链之前手动复刻一次 wry `build.rs` 的生成动作：

- 定位 wry crate 的 `src/android/kotlin/`（三级：`WRY_SRC_DIR` 环境变量 →
  `cargo metadata`（不加 `--no-deps`，wry 是 tauri 的传递依赖）→
  registry glob 取最高版本）；
- 从 `tauri.conf.json` 读 `identifier`、从 `Cargo.toml` 读 `[[lib]] name`；
- 9 个文件（Ipc / Logger / PermissionHelper / proguard-wry.pro / Rust /
  RustWebChromeClient / RustWebView / RustWebViewClient / WryActivity）逐个做
  与 build.rs **完全一致**的 5 占位符替换（`{{package}}` /
  `{{package-unescaped}}` / `{{library}}` / `{{class-extension}}` /
  `{{class-init}}`）并加同款 AUTO-GENERATED 头，写到
  `java/<包名>/generated/`，仅内容变化时写盘。
- 支持 `--dry-run` / `--selftest` / `--wry-src` / `--gen-root`。

与真实 build.rs 的差异仅剩「包名含 Kotlin 硬关键字段时的反引号转义」
（`cargo-mobile2` 的 `android_identifier_escape_kotlin_keyword`）：本仓库
包名 `com.example.web2app` 不触发；且 prepare 产物注定被 build.rs 覆盖，
中间产物是否合法不影响最终编译，故不复制关键字表。

### 3.2 `.github/scripts/inject-gradle-patch-task.py`（新增，覆盖后重打）

往 `gen/android/app/build.gradle.kts` 末尾注入任务链：wry build.rs 随
Rust 编译覆盖 `generated/` 后、Kotlin 编译前，按固定顺序重放
extras → schemes → fullscreen 三个补丁（均幂等）。

MainActivity 系补丁（insets / back / download）只在 init 后打一次 ——
`MainActivity.kt` 不在 wry build.rs 的生成清单里，不会被覆盖。

## 4. 排查中修掉的三处二次缺陷

首版注入块做真实环境核对时发现以下问题（均有 selftest 守卫防回归）：

1. **Gradle 9 已移除 `Project#exec`**：模板 `gradle.properties` 默认
   `org.gradle.configuration-cache=true`、wrapper 是 Gradle 9.6.1，
   `Project#exec`/`javaexec` 8.11 弃用、9.0 移除，执行期访问 project
   也违反 configuration cache。首版 `doLast { exec { } }` 写法在真实
   构建会直接报错。改为内置 `org.gradle.api.tasks.Exec`，路径/命令
   全部在配置期固化（CC 安全）。
2. **release 出包白编 debug .so / 架构任务名错配**：首版补丁任务同时
   `dependsOn("rustBuildUniversalDebug"/"Release")`，release 构建会被
   拉起一遍 debug Rust 编译；且 `--split-per-abi` 下实际任务是
   `rustBuildArm64Release` 而非 universal。改为在 `afterEvaluate` 里用
   **`tasks.names`（不 realize 任务）枚举**全部 `rustBuild<Variant>`，
   为每个变体注册 `patchWry<Variant>Step0/1/2` 链 + 聚合任务，
   `compile<Variant>Kotlin` 同名配对（`tasks.named(...).configure{}`，
   惰性）；UnitTest/AndroidTest 编译找不到同名 rustBuild 不连线。
   另修掉一个 Kotlin 闭包捕获陷阱：`register {}` 的配置 lambda 惰性
   执行，三轮循环直接捕获同一个 `var` 会让 Step0/1 最终都依赖 Step2
   （Step2 自依赖报错），每轮必须用独立 `val` 固定上一步。
3. **prepare 的 cargo metadata 分支从未生效**：辅助函数把 stdout
   （一大段 JSON）包成 `pathlib.Path` 再 `.read_text()`，等于把 JSON
   当文件路径打开，必然异常并被静默吞掉，定位一直靠 registry glob
   兜底 —— CI 冷缓存（prepare 早于任何 cargo build，`registry/src`
   里可能还没有 wry 源）时会直接 `FileNotFoundError`。改为返回 stdout
   字符串直接 `json.loads`（已实证 metadata 命中 wry 0.57.0 manifest）；
   metadata 超时 30s → 120s。

python 可执行名按注入脚本的宿主平台写死（CI Linux → `python3`；
Windows 本地构建 → `python`）。

## 5. CI 接线与门禁

- `build-custom.yml` / `release.yml` 的 Android job：在
  `apply-android-labels.py` 之后、`patch-android-insets.py` 之前插入
  「预生成 wry Kotlin 模板」「注入 gradle 补丁任务链」两步（均加中文
  注释说明根因）。
- `ci.yml` 的 `config-contract` 作业：安卓共享脚本 selftest 循环新增
  `prepare-wry-kotlin`、`inject-gradle-patch-task`（共 12 个脚本）。
- 补丁后完整链路：prepare-wry-kotlin → 注入 gradle 任务 →
  insets → back → download → extras → schemes → fullscreen →
  permissions → cleartext sed；构建期再由 gradle 任务链重放
  extras → schemes → fullscreen。

## 6. 验证

- 12/12 安卓共享脚本 `--selftest` 全绿；`check-workflows.py` 通过
  （7 个 workflow / 113 个脚本片段）。
- 与 wry 0.57.0 `build.rs` 逐项比对：9 文件清单、5 个占位符、
  AUTO-GENERATED 头（.kt/.pro 两种）、输出目录（unescaped 包名）、

  存在且只编 aarch64；`android::project::generate`（模板拷贝）只被
  `mobile/init.rs` 调用，build 不会抹掉注入块。
- 真实 dry-run（cwd=webview-app）正确解析工程根、包名
  `com.example.web2app`、库名 `web2app_lib`、9 个模板齐全。
