### ② 真机取证过程本身产出的环境事实（都写进了 harness 模块文档）

这一轮在真机上白查了整整几轮，值得单独记：

1. **`build()` 会偶发永久挂死（受限桌面会话，约 50%）**：`run-G ✓ / H ✗ / I ✓ / K ✗`，同一 exe、
   同一代码。挂点是 `WebviewWindowBuilder::build()` 内部（WebView2 环境创建），**同步阻塞、进程内无法
   给自己设超时**，且换 exe 目录 / 换 UDF / 清残留 `msedgewebview2` 全都无效。**结论：这是环境固有
   抖动，不是产品缺陷**；应对方式是**外部重试器**（见下）。
2. **探针自己的「假主窗」漏设 `data_directory` 时，建窗会从 7~9ms 退化成 60s+ 甚至挂死**
   （生产三处建窗都显式设了它）。这条差一点被误判成「WebView2 初始化偶发停摆」，现已用契约守卫钉住。
3. **WebView2 的 UDF 落点是 `%LOCALAPPDATA%\com.example.web2app\EBWebView`，与 exe 所在目录无关**
   ⇒ 「换个全新目录跑 exe」**不会**换掉脏 UDF（早期几轮的 `about:blank` 就出在这）。禁用时要**重命名
   备份**而不是删除（本机删除有配额，且会反噬宿主进程自己的收尾删除）。
4. **`Start-Process -PassThru`（不带 `-Wait`）拿到的 Process 对象不会自动回填 `ExitCode`** ——
   直接读是空值，脚本会把「成功」当「非 0」从而**无限重试**。必须先 `WaitForExit()` 再 `Refresh()`。
   （`run-float-probe.ps1` 第一版就踩了：`attempt 1` 明明 `EXIT=0`，却打印 `EXIT=` 空值继续重跑。）
5. 既有禁令复述：跑任何 Electron 探针**必须**带 `--no-sandbox --in-process-gpu`（本机 GPU 进程
   以 `exit_code=-1073741819` / `FATAL: GPU process isn't usable` 退出是常态），且必须剥掉
   `ELECTRON_RUN_AS_NODE`。
6. `GetWindowRgnBox` **含端语义**：椭圆区域在 `[0,70)×[0,70)` 上报 `(0,0,69,69)`（宽高各 −1），
   100% / 125% 缩放一致 —— 断言按「实测含端」收敛，不是放宽判据。
7. `monitor_from_point` 用 `MONITOR_DEFAULTTONULL` ⇒ **屏外的点查不到显示器**，软钳制整段被跳过；
   探针的测试点必须落在显示器**内**（取 `mon.x + mon.w - 8`）。

**外部重试器**：`tests/float-v172-rc/run-float-probe.ps1`（一次性诊断脚本，不入库）
—— 按「输出停滞 ≥160s」判卡 → 杀进程 → 换新目录重来；单轮失败后按退出码区分
**97 = 窗口环境没起来**（`wait_main_ready` 60s 内主线程往返不回来）/
**98 = 看门狗总超时**（任何一步阻塞都到点强退，绝不挂死）。

### ③ P1：Electron 球窗四角「看得见但点得着」→ `setShape` 裁圆

`transparent: true` 只解决「**看得见**」：四角在系统看来仍是窗口的一部分，会把桌面 / 下层窗口在球四角上的
点击吃掉（layered window 的完全透明像素**不会**自动穿透）。

- `electron-app/src/main/float-layout.ts` 新增**纯函数** `circleShapeRects(d)`：用扫描线把边长 `d` 的
  正方形逼近成圆（`setShape` 只接受 `Rectangle[]`，没有椭圆 / 路径入口）。取整按「像素中心是否落在圆内」
  定左右端，使阶梯边缘与真圆的偏差 < 1 像素 —— 既不切掉球面本来能点的像素，也不把四角放回命中区。
- `electron-app/src/main/float-window.ts` 建窗后 `win.setShape(circleShapeRects(DEFAULT_FLOAT_W))`，
  **包在 `try/catch`** 里：`setShape` 在 Electron 里标记 `@experimental`（win32 / linux），失败只能
  降级成「四角挡点击」的旧行为，**绝不能让球整个不可用**。
- **区域只决定「命中」，视觉仍由 CSS 圆 + `transparent` 负责** ⇒ 阶梯边缘看不见
  （Tauri 侧 `CreateEllipticRgn` 是真椭圆，两壳视觉一致）。

### ④ P1：双击去抖（双壳单一真源页面）

`webview-app/src/floaticon.html`：新增 `CLICK_DEBOUNCE_MS = 250` 与 `lastClickAt`；`endPointer`
改为两段式 —— 先 `if (moved) { send('dragend'); return; }`，再判窗口期
`if (now - lastClickAt < CLICK_DEBOUNCE_MS) return;`，通过后才 `lastClickAt = now; send('click')`。
系统双击在 ~100ms 内送来两次 `pointerup`，旧实现两次都发 `click` ⇒ toggle 相互抵消、主窗「闪现」；
现在窗口期内的第二次被丢弃。`pointercancel`（未拖动）走 `cancel` 分支，**从不**发 `click`。

⚠️ **这是一次契约变更，会波及测试**：真机 harness 原有断言「连点两次**都必须**触发 toggle」与新契约
互相矛盾。处理方式是**改 harness 而不是改回去**——`tests/float-v170-harness/main.cjs` 的第 ⑥ 组改为
三态：首次生效 / 250ms 内第二次被丢弃 / 去抖窗口外再点再次生效；并顺带钉住 `pointercancel` 不触发。

### ⑥ P2：**真实修复** —— 多页签宿主窗漏设 WebView2 数据目录

`webview-app/src/tabs.rs::create_host_window` 补上 `.data_directory(config::data_dir(app))`。

它是多页签模式下**最先创建 WebView2 环境**的窗口，漏设的后果有两条、**都是静默的**
（编译零警告、单测全绿、探针全绿，只有真机往盘上看才现形）：

1. 宿主的 WebView2 数据落到**系统默认目录**（`%LOCALAPPDATA%\<identifier>\EBWebView`），
   绿色版「不写程序目录之外」的承诺被破坏（主窗 / tab 窗都写在 exe 同级 `data/`）；
2. `tabs.rs` 里那段注释的前提（「宿主是同 user-data-folder 下第一个创建环境的窗口，
   所以 `--proxy-server` 参数必须挂在它身上」）**不再成立** —— 宿主在默认 UDF、tab 在共享 UDF，
   二者分裂成两个环境，「同一 UDF 首个环境生效」的推理失去落点。

新增守卫 `contract_tests::float_window_contract::tabs_host_window_sets_data_directory`
（判据用 `builder.` 作接收者：主窗是 `wb.`、tab 窗是 `window.`、球窗是 `b.`，四种接收者互不相同，
于是这条 needle 在 `tabs.rs` 里只能来自宿主窗那一行）。

## v1.73（2026-10-11）：悬浮球 hover 时「图标背景冒出异样浅色图形」= 原生提示条被 always-on-top
球窗压到身后、从透明环带漏出残片（移除球上原生提示 + 双壳守卫）

### 现象（使用者真机截图）

「Tauri 悬停球，不选中（不点击），图标背景有异样图形」：hover 时球窗圆内、球本体之外的环带里
出现一块**浅色残片**（淡蓝灰、带圆角与直边，里面还有一点点彩色描边的小色块）。

### 取证（三层，全部可复核）

1. **图像像素取证**（`tests/float-tauri-diag` 之外的临时脚本，结论如下）：
   - 残片的**外边界与活柱椭圆**（`CreateEllipticRgn` 的内切椭圆）**逐行吻合**：把亮度/色相分层打印后，
     残片最右边界 ≈ 球心 + 活柱半径、最上边界是球窗顶，说明它被**球窗的区域裁剪**；
   - 残片的**另外两条边是直线 + ~4 物理像素圆角**（左上角 x=55、上边 y=52 逐点收拢）⇒ 它属于**另一个矩形窗口**；
   - 残片颜色 = **白 × 球自身深蓝投影**（白色底被 `box-shadow: 0 4px 14px rgba(20,40,100,.55)` 叠加，
     按 ~30% α 算出 `(184,197,208)`，与实测 `(183,199,217)` 一致）；
   - 残片里那条「彩色小色块」= **ClearType 亚像素描边**的文字碎片（棕/深蓝/浅青三色紧邻 = 典型 RGB 子像素渲染），
     即**浅底深字**的文本。
2. **Electron 复刻本页**（新脚本 `tests/float-tooltip-rc/`，**用同一份 `floaticon.html`**）：
   `main.cjs` 按生产参数复刻球窗（56×56 / `transparent` / `frame:false` / `alwaysOnTop:true` /
   `skipTaskbar` / `setShape(circleShapeRects(56))`），经 `floaticon://` 协议加载同一份页面与图标；
   `grab.py` 用**真实鼠标**（`SetCursorPos`，进程先声明 DPI 感知）移入球上 → 等 2.2s → `PIL.ImageGrab` 抓屏；
   移开鼠标 → 再抓同一区域作对照。结果：**hover 时出现浅底深字的提示条，文案正是球元素的原生提示内容**

## v1.75（2026-10-11）：只启用悬浮图标时「关闭窗口 → 点击悬浮图标不回窗口」

### 起因（使用者真机原话）

### 取证（先定位持锁者式的硬证据，再谈修法）

**① 使用者的真实策略就在那份测试产物里**（不是推测）——

**② 源码级两步链（两壳同形，逐行读到）**：

| 环节 | Electron | Tauri |
|---|---|---|
| 点 ✕ | `index.ts` 的 `win.on('close')` 只在 `tray_enabled && minimize_on_close` 时 `preventDefault()+hide` ⇒ 否则窗口**真销毁** | `lib.rs::handle_main_close` 同一条件，`else` 分支只清 tab 窗口 ⇒ 宿主**真销毁** |

①球即驻留入口（关窗=隐藏，点球唤回；配套补退出入口）；②关闭=真退出（连球一起收掉）；
③点球时重建主窗（进程一直驻留，无托盘时没有退出入口）。
**使用者选①**：悬浮球即「驻留入口」，与「托盘 + 关闭最小化到托盘」同语义。

### 起因（使用者真机原话）

> 悬浮图标 右键隐藏后 程序还在运行 但是无法唤起窗口。右键隐藏 ，应该关闭悬浮图标功能 同时显示窗口(如果隐藏)

拆成三件事：

1. 右键语义 = **关闭悬浮图标功能**（`float_enabled` 置 false 并落盘 + **销毁**球窗），不再是「只把球藏起来」；
2. 同时**唤回并聚焦主窗口**（若此前被隐藏 / 最小化）；
3. 背景死局：右键把球藏掉后，若用户没启用托盘、主窗又处于「关窗驻留隐藏」态，桌面上再无任何入口
   ⇒ 进程还在跑却唤不出窗口。

### 取证

- **机制层**：`float_enabled` 为 true 时两壳都驻留（`(tray && min) || (win && float_enabled)`，见 v1.75）；
  球窗一藏，Electron 侧 `window-all-closed` 也被球窗挡住，而 `float_enabled` 仍为 true ⇒ 进程驻留、窗口却无入口。
- **探针层（真机）**：`--float-probe` 第七段改造后，三条核心断言实测 **PASS**——
  ①球窗**已销毁**（`float_visible = None`）②`float_enabled` 已置 false ③主窗被唤回（`Some(true)`）。
- ⚠️ 探针自身的「复原」断言一度 FAIL（`visible=Some(false) dock=None`）：**这是探针改动自己引入的假失败**——
  v1.72 的复原是「把藏起来的窗口再 `show` 一下」（瞬时），v1.76 起右键会**销毁**窗口 ⇒ 复原变成**重建**
  （隐藏建窗 → 球页加载完才 `show`，另有 1s 兜底），固定 `sleep(700)` 必然赶不上。改为轮询到「可见」为止
  （上限 `RESTORE_WAIT` 120s），并因整轮出现**第二次**窗口构建等待把 `WATCHDOG_SECS` 240 → 330。
- ⚠️ 另：同一台机器**同一天下午**实测球窗「从建到可见」稳定 **>120s**（连续多轮都在 120s 判负、而失败收尾的
  `labels` 里**始终有 `float`**）⇒ `BUILD_WAIT` 120 → **180s**。这是**环境等待**上限、不是对产品行为的断言，
  放宽只是让慢机器也能取证、不掩盖任何产品缺陷（真挂死仍由看门狗兜底给 98）。

## v1.77（2026-10-11）：悬浮球「背景异样」的**第二个**源头——球窗其实带着任务栏按钮（`WS_EX_APPWINDOW`）

### 起因（使用者真机原话 + 截图）

> 悬浮图标 背景异样(不选中时) 仅限 tauri才会出现，Electron版本无此问题

⚠️ 这条与 v1.73 修的「hover 时图标背景冒出异样浅色图形」**现象同名、但不是同一个源头**：v1.73 修的是
**球元素 `title`**（HTML 层），本次修的是**窗口级**的那一份（任务栏按钮 / 任务视图浮层）。

### 排除（先证伪，再动刀）

- **v1.73 的修复确实在用户跑的包里**：对 `tests/pack/tauri/osfipin.mark.exe` 做字符串取证 ——
  `aria-label="单击` 命中 1、`title="单击` 命中 **0**（其余 `width: 30px` / `46px` / `object-fit` 均在，
  说明抽到的就是球页本体）⇒ 症状来自**第二个源头**，不是「包没带上修复」。
- **球页本身无嫌疑**：Electron 复刻同一份 `floaticon.html`（透明 + alwaysOnTop + `setShape` 圆），
  真实鼠标 `SetCursorPos` 悬停 4s，三态对照（hover / 移开 / 再 hover）**不产生任何原生提示条**。
- **截图像素分类**（96×90 局部，`tests/float-frag-rc/`）：`BALL_BLUE` bbox=(7,16,79,84)、图标 `WHITE`
  bbox=(33,40,50,61)、而那块浅灰残片 `CARD` bbox=(12,20,81,59) —— **x 到 81 已超出球窗椭圆裁剪区**，
  且残片内嵌橙色竖条 + 深蓝竖条、下缘圆角收拢 ⇒ 形态是一个**独立的提示条类窗口**，被置顶球窗压在身后、
  只从透明环带漏出。

### 根因（tao 0.35 的两段实现 + 一条窗口语义）

1. `window.rs`：`ON_TASKBAR` 是**按「窗口无父」**置位的 —— `Parent::None => window_flags.set(ON_TASKBAR, true)`，
   **与 `skip_taskbar` 完全无关**；
2. `window_state.rs`：`if flags.contains(ON_TASKBAR) { style_ex |= WS_EX_APPWINDOW }`
   ⇒ **建窗那一刻就把 `WS_EX_APPWINDOW`（0x40000）写死了**；
3. `window.rs::set_skip_taskbar`：`skip_taskbar(true)` 只额外调一次 `ITaskbarList::DeleteTab`，
   **既不清 `APPWINDOW`，又是在窗口还 `visible(false)` 时调的** —— 对从未显示过的窗口无效，
   而 `APPWINDOW` 会让任务栏在 `show()` 时把按钮**加回来**。
4. **实测坐实**：枚举顶层窗口读 `GWL_EXSTYLE`，球窗 `ex = 0x40118`（`APPWINDOW|TOPMOST`）。

⇒ 球是**带着任务栏按钮**被显示出来的。任务栏按钮自带**原生提示条 / 任务视图缩略图浮层**（内容 = 窗口标题），
那是个**独立的非置顶窗口**，被 always-on-top 的球窗压在身后 ⇒ 只从球窗透明环带漏出一块浅色残片
= 用户看到的「背景异样」。

**为什么「仅限 Tauri」**：Electron 的 `skipTaskbar: true` 是**真移除**（自有窗口类写 `WS_EX_TOOLWINDOW`），
球窗根本不在任务栏里 ⇒ 没有承载提示条的载体。顺带说明 Electron 球窗**是带标题的**
（`float-window.ts`：`title: deps.title`），照样没症状 —— 反证「根因是 `APPWINDOW`，不是标题文本」。

### ⚠️ 第一版修法无效（关键教训）

第一版把 `apply_ball_window_styles` 放在 `show()` **之前**（建窗后一次改到位）。读回证明**等于没改**：

- tao `set_visible` → `WindowState::set_window_flags` → `apply_diff`（`window_state.rs:315`）：
  `diff = self ^ new`，非空则在末尾
  `SetWindowLongW(GWL_STYLE, …)` + `SetWindowLongW(GWL_EXSTYLE, style_ex.0 as i32)`
  —— 用**缓存的窗口标志**重新拼出来的 `style_ex` **整体覆盖**，缓存里没有 `NOACTIVATE`/`TOOLWINDOW`、
  却有 `ON_TASKBAR` ⇒ 我们写的两位被抹掉、`APPWINDOW` 被写回。
- 显示路径实测读回依旧 `0x40118`（注：该次读回的 `title=[]` 已生效，证明确实跑的是新二进制）。
- 附带发现：v1.72 加的 `WS_EX_NOACTIVATE` 用的是**同一处「写在 show 之前」**的调用点 ⇒
  在 `show()` 之后读回里**也不存在**（`0x40118` 无 `0x8000000`）。本次一并真正补上。

### 修法（Tauri 侧四处，Electron 无需改动）

1. **`show_ball(w)` 成为显示球窗的唯一入口**（`show() → unminimize() → apply_ball_window_styles() → delete_taskbar_tab()`）：
   顺序是**硬要求** —— 样式只能写在显示**之后**（否则被 `apply_diff` 擦掉）；`unminimize()` 同样触发一次重写，
   所以它也必须在补样式**之前**。
2. **`apply_ball_window_styles`**：一次 `GWL_EXSTYLE` 读-改-写，置 `WS_EX_NOACTIVATE` | `WS_EX_TOOLWINDOW`、
   **按位清 `WS_EX_APPWINDOW`**，并**读回校验**（`SetWindowLongPtrW` 失败只回报 0，而 0 也是合法旧值
   ⇒ 只能读回看结果，配 `dlog!` 留痕）。
3. **`delete_taskbar_tab`**：`CoCreateInstance::<_, ITaskbarList>(&TaskbarList, …, CLSCTX_SERVER)` + `DeleteTab`，
   回收 `show()` 那一刻可能已经建出来的按钮（清样式只保证**将来**不再重建）。COM 取对象失败不致命，只留痕。
4. **球窗 `.title("")`**（原 `.title(TITLE)`）：纵深防御 —— 即便将来别的外壳界面再拿窗口标题当文本，
   也没有可漏的内容。
5. 三处显示路径（冷启动建窗后 `on_page_load(Finished)`、1s 兜底、`show_float_window`）**统一改走 `show_ball`**。

### 守卫（新增 2 条，全部做了反向对照）

  ①`apply_ball_window_styles` 体内必须含 `GWL_EXSTYLE`/`WS_EX_NOACTIVATE`/`WS_EX_TOOLWINDOW`/

## v1.77b（2026-10-11）：悬浮球「背景异样」的**第三个**源头——球比窗口圆形区域小，中间那圈**透明环带**透出了窗口后面的东西

### 起因（使用者真机原话 + 第二次截图）

> `悬浮图标 背景异样(不选中时) 仅限 tauri才会出现，Electron版本无此问题`

### 取证一：逐像素量残片的几何（`tests/float-frag-rc/analyze-frag.py`）

| 量到的东西 | 数值（截图设备像素） |

### 修法（只动两壳共用的 `floaticon.html`）

球铺满整个活柱 ⇒ 球与区域圆严格重合 ⇒ 环带在几何上不存在。

| 项 | 改前 | 改后 | 为什么 |
|---|---|---|---|
| `#w2f-ball` 宽高 | `46px` | **`56px`**（= `ICON_SIZE_LOGICAL`） | 球铺满区域圆，环带消失 |
| `#w2f-ball:hover` | `transform: scale(1.1)` | **`filter: brightness(1.12)`** + 加强外发光 | 球已铺满，`scale>1` 立刻被区域裁掉 = 没有反馈；放大出的那圈又是环带 |
| `.w2f-grabbing` | `scale(1.04)` | **`filter: brightness(1.06)`** | 同上 |
| `html.w2f-collapsed` | `opacity: .92` | **`filter: brightness(.92)`** | `opacity` 让**整颗球**半透明 = 把刚堵上的保护自己拆掉（窗口底色又透出来） |
| `#w2f-ball img` | `30px` | **`36px`** | 球径 ×1.217，图标维持 65% 占比 |
| `transition` | `transform, box-shadow` | **`filter, box-shadow`** | 过渡里不能再有 `transform` |

同心性核对：区域由 `CreateEllipticRgn(x1, 0, x1+lw, lh)` 生成，圆心 =(活柱中心)；
球是 `left:28px` / `html[data-anchor="r"]` 时 `calc(100% - 28px)` + `top:50%` + `translate(-50%,-50%)`
⇒ 圆心 =(活柱中心) —— 逐点对齐，所以「球径 = 活柱边长」即可严格重合。

### 顺手修掉的第二个静默失败：`ITaskbarList` 缺 `HrInit()`

v1.77 的 `delete_taskbar_tab` **没有先调 `HrInit()`**（MSDN 明文要求：任何方法前必须初始化），
且把 `DeleteTab` 的 HRESULT 用 `let _ =` 吞掉 ⇒ 未初始化时 `DeleteTab` 返回 `E_FAIL` 且**什么都不做**，
而窗口样式读回看着完全正确。本次补上 `HrInit()`，并让 `HrInit` / `DeleteTab` 的失败**留痕**。
