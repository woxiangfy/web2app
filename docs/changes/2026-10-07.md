## v1.39（2026-10-07）

**第六轮三类清单审计闭环（无外部输入，模糊项按通用默认补全）**：①**不足（P2 正确性）——本地代理入口 URL 丢弃上游路径**：`proxy::start_proxy` 把入口写死为 `http://127.0.0.1:PORT/?w2a_key=…`，于是配置了子路径的 `app_url`（如 `https://example.com/app/`）在**开启本地代理**（`proxy_enabled=true` 且未配外部代理，Windows 与移动端的默认代理形态）时被送到**站点根**，而直连 / 外部代理模式（`bootstrap::strip_userinfo` 与 sidecar 的 `--no-proxy` 分支）却保留完整路径 —— 同一份配置两种落点，且**完全静默**（正是本项目最忌的失败形态）。修为入口带上 `upstream.path()`；上游无路径时 `path()` 恒为 `/`，产物与旧实现**逐字节相同**（零回归）。修复落在 `src/proxy.rs`，经 `#[path]` 复用同源地被 sidecar（Electron 壳）一并继承，不存在双壳漂移。新增 2 条单测（`proxy_entry_url_keeps_upstream_path` / `proxy_entry_url_origin_only_unchanged`）并做**反向对照**：还原旧写法后前者实测 FAILED（`left: "/" ≠ right: "/app/index.html"`），恢复后全绿；②**过期文档订正**——webview README 与 `docs/project-analysis.md` 的 Rust 单测计数由 144（13+7+29+95）订正为 **151**（13+7+32+99）；根 README §二 `scripts` 行补登 `packlib/` 拆分、§3.2 说明探针已拆为入口 + 四个断言组；③**冗余/缺失**——本轮逐模块审计了 `config.rs` / `store.rs` / `settings.rs` / `bootstrap.rs` / `loading.rs` / `debug_log.rs` / `webview_hooks.rs` / `proxy.rs` / `tabs.rs` / `app-ipc.ts` / `protocols.ts` / `settings-controller.ts` / `hotkey.ts` / `first-existing.ts` / `navigate.ts` 及四组跨壳契约（`hotkeyLabel` 文案、`sanitizeDirName` 空白集、`WEB2APP_DEBUG` 真值集、代理「JSON 即行为」），**未发现**其它可静态验证的 P0/P1 代码缺陷；④门禁（2026-10-07 实跑）：`cargo fmt --check` 0、`clippy --all-targets -D warnings` 0 告警、`cargo test --all` **151 通过 / 6 ignored**；Electron `typecheck` 通过、`unit` **47/47**（未改 TS，计数沿用本轮实跑）。**遗留**：Trilium 笔记树拖放（`dnd_polyfill.js`）在 Windows 仍未修复，历史三次尝试均「编译/测试绿但用户反馈无异」，需**运行时观察**（确认合成 drag 是否真的发起、插入提示线是否出现）才能根因定位；本轮未复跑 GUI 探针与真机验收
