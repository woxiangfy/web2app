## 修本地打包把探针打进 app.asar（`pack-local` 漏了 `prune` 一步）

**现象**（`tests/build-electron-all.bat` 实测，退出码 1）：

```
::error::app.asar 内混入了开发期产物：/out/main/probe-infra.js, /out/main/probe-server.js,
/out/main/probe-single.js, /out/main/probe-tabs.js, /out/main/probe.js, /out/renderer/tabs-probe-preload.js
```

包本身是**出成功**的（zip + portable 都在、exe 也能开），只有出包后的
`check-asar-config.cjs` 反向断言报红 —— 正是 H-4 那条护栏按设计发挥了作用。

**根因**：出包入口有**两个**。2026-11-07 加「探针不进包」时只改了 `electron-app/package.json` 的
`pack` / `dist` / `dist:installer` / `dist:all`（都插了 `pnpm run prune`），**本地打包那条路**
（`build-electron-all.bat` → 根 `scripts/pack-local.mjs` → `packlib/driver-electron.mjs`）

`files: out/**` 于是把 `tsc` 产出的 `probe*.js` 与 `tabs-probe-preload.js` 一并打进了 asar。
守卫 `probe-isolation.test.ts` 当时只遍历 `package.json` 的脚本名 ⇒ 对它**完全盲**。

**修法**

1. `scripts/packlib/driver-electron.mjs`：`stage` 之后、`electron-builder` 之前补
   `run(['pnpm', 'run', 'prune'])`，并在原位留注释说明「顺序不可换」（prune 只删 `out/`，
   放在 build 之前等于删完又被生成回来）与两个入口的对应关系。
2. `electron-app/test/probe-isolation.test.ts` 新增第 4 条守卫「pack-local 的 Electron 驱动同样必须
   build → stage → prune → electron-builder」：读 `../scripts/packlib/driver-electron.mjs`，

   「为什么 prune」，不剥会被注释满足而假绿）；`builder` 的锚点取 `runTee(builderCmd(` 而非
   `builderCmd(` —— 后者的首次出现是**函数定义**，位置在 step 3 之前，会给出恒真的假绿。
3. 文档同步：`electron-app/AGENTS.md` §13 补「两个入口都要有 prune」；
   `docs/packaging-config.md` §7.2 的「Electron 本地要做的」一行改为

## 修「装完打不开、提示服务器连接失败」：TXT 记录名里的下划线被 hickory 判成非法

**现象**（`lcjm-0.0.1-win-x64-portable.exe` 双击后）：首屏只有一句
「首个页签加载失败：服务器连接失败，请检查网络后重试」+ 重试按钮，看起来就是网络断了。

**排查链条**（每一步都用证据排除，别停在「像是网络问题」）：

1. **TXT 记录本身没问题**：三个候选域名 `nslookup -type=TXT` 均返回密文，且经 8.8.8.8 / 1.1.1.1 /
   223.5.5.5 三处公共 DNS 复核结果一致 ⇒ 不是 DNS 没生效、也不是网络不通。
2. **密文与本配置的密钥/公钥匹配**：`resolve-tool decrypt <config.public_key> <密文> --secret <config.resolve_secret>`
   三条全部「解密验证通过」，解出 `https://api2.xwamp.com/user-0408/`、签发日 2026-11-14、`ttl_days=0`
   ⇒ 不是 Secret / 公钥不匹配、不是过期。
3. **包内 sidecar 能跑但要复现**：直接执行 `win-unpacked/resources/sidecar/w2a-proxy.exe --domains … --public-key …`，
   三条域名全部「解析失败」⇒ 问题在 sidecar 的解析链路，不在 Electron 外壳。
4. **拿不到原因 ⇒ 先把原因留下来**：`resolve.rs` 里 `Err(_) => dlog!(…"解析失败"…)` 把唯一线索吞了
   （Tauri 侧早有「解析失败必须保留具体原因」的契约，这里漏了）。改成带上 `{e}` 后真相立刻出来：
   `protocol error: Label contains invalid characters: Err(Errors)`。
5. **对照组定位到规则**：`_w2alcjm.lcjm.cc`（下划线在**首字符**）→ 查询正常发出；`txtw2alcjm26.lcjm.cc`
   （无下划线）→ 正常；`a_b.lcjm.cc`（下划线在**中间**）→ 同样的 `Label contains invalid characters`。

**根因**：hickory-resolver 0.26 的 `Resolver::txt_lookup(&str)` 对 `&str` 走 `Name::from_utf8` ⇒
每个 label 过 `Idna/Uts46 + AsciiDenyList::STD3`，STD3 **只许字母/数字/连字符**，下划线仅在
「label 首字符」被特判放过（SRV 那类 `_dmarc`）。而配置用的记录名是 `txt_w2a_lcjm26.*`
（下划线夹在中间）⇒ **构造查询名这一步就失败，请求根本没发出去** ⇒ 三个候选域名全挂 ⇒ 固定文案
「服务器连接失败」。`nslookup` / 浏览器用的是 Windows 解析器（不套 STD3），所以怎么查都正常，
于是现象被牢牢伪装成网络故障。

**修法**

1. `webview-app/src/resolve.rs`：新增 `lookup_name()`，改用 `Name::from_str_relaxed`（先严格、失败再按
   `from_ascii` 构造）后再 `txt_lookup(name)`。DNS 协议本身允许 owner name 带下划线，严格校验只是
   解析器的自我约束 ⇒ 放宽后既能查规范的 `_dmarc`，也能查实际存在的 `txt_w2a_*`，**用户不必改 DNS**。
   ⚠️ 本文件被 Electron sidecar 以 `#[path]` 复用 ⇒ 一次修复同时覆盖两壳，无需改 sidecar。
2. 同上文件：`Err(_)` → `Err(e)`，把查询失败的具体原因写进 `dlog!`（走 stderr，不污染 sidecar 的
   stdout 单行 JSON 协议；是否落到日志仍由宿主的 `debug` 决定）。
3. 单测（不联网）：`lookup_name_accepts_underscore_inside_label`（含事故现场的记录名、`_dmarc`、
   无下划线、多级域名）+ `lookup_name_rejects_truly_invalid`（含空格仍报错）。
   ⚠️ 首版还断言了 `lookup_name("")` 报错 —— 实测 hickory 把空串当根域名 `.`，而空串在
   `resolve_url_from_domains` 里已被 `continue` 跳过 ⇒ 那是个与实现不符的「假期望」，删掉。

**取证**

- 修复前后同一个 sidecar 命令行（`--domains txt_w2a_lcjm26.{lassl.vip,xwamp.com,lcjm.cc} --public-key …`）：

    `{"ok":true,…,"resolvedUrl":"https://api2.xwamp.com/user-0408/"}`
  这条同时反证了「Secret/公钥没问题」（能解出 URL 就说明 AES-GCM + 验签都过了）。
- `cargo test --all`：主 crate **246 passed / 3 ignored**、sidecar **34 passed / 3 ignored**、
  其余 19 + 22；`cargo fmt --check` ✅、`cargo clippy -p w2a-proxy -p web2app --all-targets -D warnings` ✅。
- 重新出包（`--target electron-portable`）后直接跑包内 `resources/sidecar/w2a-proxy.exe`，
  与上面「后」逐字一致 ⇒ 产物内的 sidecar 已是修好的那份。

**顺带确认的两件事**

- `pack-local` 的 `RESOLVE_SECRET` 注入是**有效**的（`resolve_secret` 不在 `SKIP_ENV` 里，
  `env['RESOLVE_SECRET']` 会被设上），且 cargo 确实跟踪 `option_env!` 的环境依赖 ——
  改值会重编（实测 39s），改回同值时复用（0.5s）。所以「sidecar 内置了错的默认 Secret」这个初始怀疑**不成立**。
- 仍存在的可观测性缺口：Electron 侧 `sidecarFailureText` 对 `kind: resolve` 恒返回固定文案，
  具体原因只进 stderr（默认 `debug=false` 时等于丢弃）。要像 Tauri 那样把原因带到界面，

### 修好客户端后发现的第二层问题：密文里的目标主机不存在

用修好的包（`tests/pack/electron-local-20261114-195846`）实际启动应用并接 DevTools 协议观察：

```
shell://localhost/            title=标签栏           text="← → 加载失败"
https://api2.xwamp.com/user-0408/  loc=chrome-error://chromewebdata/   text=""
```

即：**解析链路已经通了**（sidecar 输出 `上游：https://api2.xwamp.com/user-0408/`），
但页面落到 `chrome-error`。继续查目标主机：

```
nslookup api2.xwamp.com 1.1.1.1      → DNS 名称不存在
nslookup api2.xwamp.com 119.29.29.29 → DNS 名称不存在
nslookup api2.xwamp.com 8.8.8.8      → DNS 名称不存在
nslookup xwamp.com <同上>            → 域名存在但无 A 记录
```

⇒ 密文里签发的 `https://api2.xwamp.com/user-0408/` **主机名是 NXDOMAIN**，三处公共 DNS 一致。
所以这个包即便修好客户端也仍然打不开站点 —— 但**失败形态不同**：界面会变成「网页加载失败」
（导航失败），而不再是「服务器连接失败」（解析失败）。两者容易被混为「网络不好」，故在此写明：

| 阶段 | 失败表现 | 判据 |
|---|---|---|
| 解析（DNS TXT → 验签 → 解密） | 「服务器连接失败，请检查网络后重试」 | `w2a-proxy.exe --domains … --public-key …` 直接跑，看 stderr |
| 导航（打开解出来的 URL） | 网页加载失败 / `chrome-error://` | `nslookup <URL 主机> 1.1.1.1`；必要时开 `--remote-debugging-port` 看 target url |

**待办（用户侧，非代码）**：用 `resolve-tool encrypt <私钥> <可达的地址>` 重新签发，把三条 TXT 换成新密文
（不必重新打包 —— 密文换新不需要改客户端；只有换 Secret / 公钥才要重打包）。

## 移除「Android + 域名数组 + 关代理」的打包期预警（噪声治理）

**动因**：用户在 CI 日志里看到这条注解，判断「完全没必要」。复核后同意 —— 它不是**检出**了
问题，而是**假设**了一个问题：

```
::warning::目标为 Android 且 proxy_enabled=false：域名数组模式下若解密出的真实地址包含
账号密码（user:pass@host），Android 无法注入 Basic 鉴权（只有本地反向代理能注入），真机将 401。
```

- 触发条件只有三个**配置事实**：目标是 Android、`app_url` 是数组、`proxy_enabled=false`。
  而这三者是**默认组合**（`proxy_enabled` 默认 `false`，域名数组是生产上最常见的形态）
  ⇒ 每一次正常的 Android 出包都会刷一条。注解变背景墙之后，真该修的配置问题更容易被忽略。
- 「解密出的地址是否含 `user:pass@`」在打包期**不可知**：密文要密钥 + 运行时 DNS TXT 才解得开。
  也就是说这条注解没有任何判据能升级成硬失败，只能一直「如果」下去，而使用者此刻也无从核对。
- 与它同一处的硬失败（单 URL 内嵌 `user:pass@` + 关代理）**保留**：那一条有确凿判据，
  报错里给两种修法，是真正能在打包期拦住 401 的守卫。

### 改动

1. `.github/scripts/parse-packaging-config.py::validate_for_target` —— 域名数组分支只 `return`，
   无输出；注释写明为什么不再告警（含「真出事时的表现」与解法指路），防止被重新加回来。
2. `scripts/packlib/parser.mjs::validateForTarget` —— 同一语义的 Node 复刻同步（两份实现契约）。
3. 两侧自测**反向钉住**（原来是「数组应只告警」，现在是「数组一个字都不打」）：
   `--selftest` 里对 `validate_for_target` / `validateForTarget` 的 stdout 断言 `== ""`。
   ⚠️ `build_merged` 自身会打 `resolve_secret` 未配置的 warning，必须**在捕获之外**构建
   （第一版写在捕获里，Python 自测当场红：量到的是 `build_merged` 的输出）。
4. 文档：`docs/packaging-config.md` §5 校验表该行改为「不告警 + 为什么 + 真要 Basic Auth 怎么办」；
   §2 与 §4.1 顺带修正两处**过时口径** —— `proxy_enabled` 标着「仅 Windows」、Android 行标着
   「`proxy_*` 忽略」，实际 `nav::local_proxy_enabled()` 的非 Windows 分支 = `PROXY_ENABLED`
   （`proxy.rs` 除 `#[cfg(test)]` 外无平台分叉）⇒ 移动端开它就是本地反向代理，
   也就是「Android 需要 Basic Auth 时唯一可行的机制」。`docs/android-improvements.md` #3 同步。
