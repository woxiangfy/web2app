## 1. 背景与范围

先对 Android 壳（Tauri 2.12.1 / wry 0.57 / tao 0.37，minSdk 24，aarch64 APK）
做了一轮功能与易用性盘点，结论整理成 20 项映射矩阵（P0 三项、P1 五项、P2 九项、
安全 / 分发 / 流程各一项）。本轮**只实施 P0 三项**（清单 #1–#3），P1 起逐项后续推进。

P0 的共同特征：**现状是「静默无反应 / 必然白页 / 必然 401」这类硬伤**，且都不需要
改 Rust 业务代码——前两项走既有的「CI 给 `gen/android` 打补丁」链路，第三项是
打包期配置组合校验。

基线证据（取证于 wry 0.57 真实生成物与本仓库代码）：

- `RustWebViewClient.kt` 未挂 `DownloadListener`；Rust 侧 `download_started_handler`
  在 `android/mod.rs` 的 attributes 解构里被 `..` 丢弃 ⇒ 下载 / 长按存图全无反应。
- `RustWebViewClient.shouldOverrideUrlLoading` 把所有链接决策交给 `Rust.shouldOverride`
  （壳层未配导航拦截 ⇒ 一律放行）⇒ 非 http(s) scheme 落 `ERR_UNKNOWN_URL_SCHEME` 白页。
- `RustWebChromeClient` 未覆写 `onReceivedHttpAuthRequest`（默认取消）；
  `bootstrap.rs` 的 `#[cfg(not(windows))]` 导航分支把 `nav.user/nav.pass` `let _ =` 压掉
  ⇒ 直连 Basic Auth 站点在 Android 必 401，鉴权只能靠本地反向代理。

## 2. #1 下载接管 —— `.github/scripts/patch-android-download.py`（新增）

补丁对象是生成工程里的两个文件：

1. **`MainActivity.kt`**
   - `onWebViewCreate` 里挂 `WebView.setDownloadListener`（该 override 已由
     `patch-android-back.py` 新建，本补丁只往其函数体 `super.onWebViewCreate(...)`
     之后插一行 `web2appSetupDownloads(webView)`；override 不存在时也能自补完整版）。
   - 类尾注入两个私有方法（幂等标记 `web2app-android-download`）：
     - `web2appSetupDownloads`：挂监听并转发；
     - `web2appEnqueueDownload`：构造系统 `DownloadManager.Request` ——
       落公共 Download 目录（`setDestinationInExternalPublicDir(DIRECTORY_DOWNLOADS, ...)`，
       API 29+ 由持系统权限的 DownloadManager 写，重名自动加序号）、
       Cookie（`CookieManager.getCookie`，登录态站点必需）与 UA 透传、
       MIME 透传、文件名取 `URLUtil.guessFileName`（正确解析 `Content-Disposition`）、
       `VISIBILITY_VISIBLE_NOTIFY_COMPLETED` 进度通知 + MediaScanner 可见。
   - 权限策略：API ≤ 28 首次下载时申请 `WRITE_EXTERNAL_STORAGE`（拒绝则 toast 不排队）；
     API 33+ 申请 `POST_NOTIFICATIONS`（拒绝不阻断文件落盘，只少进度通知）。
   - `blob:` / `data:` 链接系统下载器取不到内容 ⇒ toast「该链接不支持系统下载」，不静默。
2. **`AndroidManifest.xml`**：`</manifest>` 前注入带注释标记
   （`web2app-download-permissions`）的两条权限：
   `WRITE_EXTERNAL_STORAGE`（`android:maxSdkVersion="28"`）与 `POST_NOTIFICATIONS`。

工程根 / 文件定位全部走 `android_gen.py`（`resolve_gen_root` / `find_main_activity` /
`android_manifest`）；写盘统一 UTF-8 + LF。

`--selftest` 6 组场景：原始模板要素齐全 + 幂等；**返回键补丁先跑过**的形态下只插调用、
不产生第二个 override、调用在 super 之后、back 守卫逻辑不被破坏、import 不重复；
畸形源码显式报错；Manifest 注入位置 / 幂等 / 缺闭合标签报错；临时 gen/android 工程文件级集成。

> 试打过程中修掉一个注入缩进 bug：复用已有 override 时调用行曾被注成 6 空格
> （类成员缩进又叠了 4 空格），改为「声明行缩进 + 2 空格」= 函数体 4 空格。

## 3. #2 外部 scheme 外跳 —— `.github/scripts/patch-android-schemes.py`（新增）

补丁对象是 **wry 生成的 `RustWebViewClient.kt`**（与 MainActivity 同目录；包名随
identifier 变化，按文件名 rglob 定位，为此给 `android_gen.py` 新增
`find_kotlin_file(gen_root, filename)`，缺失即 `FileNotFoundError`）。

两处外科注入（幂等标记 `web2app-android-external-scheme`）：

1. wry 的 `shouldOverrideUrlLoading(view: WebView, request: WebResourceRequest): Boolean`
   **方法体第一行**插入守卫 `if (web2appHandleExternalScheme(view, request)) return true`
   —— 必须在 wry 原决策（`return Rust.shouldOverride...`）之前；参数名由正则捕获，
   不硬编码（wry 0.57 该签名折成 4 行）。
2. 新增私有方法 `web2appHandleExternalScheme(view, uri): Boolean`：
   - `http / https / about / data / blob / javascript / file / content` 及空 scheme
     → `return false` 放行（splash.localhost、tauri 资源域都是 http(s)，不受影响）；
   - `intent://` → `Intent.parseUri(uri, URI_INTENT_SCHEME)`，解析失败 toast 并吞导航；
   - 其余 → `Intent(ACTION_VIEW, uri)` + `FLAG_ACTIVITY_NEW_TASK` 外跳；
   - 启动失败（目标应用未安装 / 被禁用）时按序回落：链接自带的 `browser_fallback_url`
     → `market://` 特判的 Play Store 网页（`https://play.google.com/store/apps/<host>?<query>`）
     → toast「未安装可打开此链接的应用」。无论哪条都 `return true`，WebView 不再加载，
     杜绝 `ERR_UNKNOWN_URL_SCHEME` 白页。

只动客户端类，不改 Rust / JNI；wry 升级后若调整方法签名，补丁步会因匹配失败**显式报错**
（不允许静默跳过）。`--selftest` 6 组场景：注入位置先于 `return Rust.shouldOverride`、
放行白名单、各类 scheme 要素、幂等、缺方法 / 畸形模板报错、临时目录文件级集成。

> selftest 初版用 `"Rust.shouldOverride"` 做锚点，误命中 KDoc 注释里的同名字样；
> 改为断言完整语句 `"return Rust.shouldOverride"`。

## 9. P1 第一批（同日追加）：#4 清除浏览数据 + #8 底栏「更多」面板

### 9.1 取证：两条原假设被推翻

1. **`web_data.rs` 加 android 分支走不通**：tauri 2.12.1 在 Android 的 `PlatformWebview`
   只暴露 `jni_handle()`（`tauri-2.12.1/src/webview/mod.rs`），没有 Windows 侧那种
   controller / 清数据入口。结论：Rust 侧零改动，能力只能从 Kotlin 侧经 JS 桥给出。
2. **wry 0.57 的 `WebView.clearAllBrowsingData()` 配方不全**
   （`wry-0.57.0/src/android/kotlin/RustWebView.kt`）：只有 deleteDatabase + clearCache
   + clearHistory + clearFormData，**漏清 Cookie 与 HTML5 存储（WebStorage）**，
   直接调它登录态不会掉。桥里必须自行补全。

### 9.2 `.github/scripts/patch-android-extras.py`（新增，6 组 selftest）

打两个文件，各自独立幂等标记（`web2app-android-extras` / `web2app-android-bridge-key`）：

1. **`MainActivity.kt`**：复用 back/download 已建的 `onWebViewCreate`，在 download 调用
   **之后**插 `web2appSetupExtras(webView)`（补丁按「download 锚点 → super 锚点」定位插入点，
   保证 super → downloads → extras 的调用顺序）。注入内容：
   - `@SuppressLint("JavascriptInterface")` 的 setup 方法：
     `webView.addJavascriptInterface(object { … }, "__web2appAndroid")`，四个
     `@JavascriptInterface` 方法 —— `share(key,url,title)`（ACTION_SEND + createChooser，
     纯文本 `text/plain`）、`openBrowser(key,url)`（ACTION_VIEW + NEW_TASK，
     仅 http/https，无应用 toast）、`clearData(key)`（完整清数据配方，见下）、
     `quitApp(key)`（`finishAndRemoveTask()`，postDelayed 300ms 后
     `Process.killProcess(myPid())`）；全部方法体 `webView.post{}` 回 UI 线程
     （接口回调在 binder 线程）。
   - `clearData` 配方：`clearCache(true)` + `clearHistory` + `clearFormData`
     + `deleteDatabase("webviewCache.db"/"webview.db")`
     + `WebStorage.getInstance().deleteAllData()`
     + `CookieManager.getInstance().removeAllCookies { flush() }`；
     Cookie 清除回调内再 `post { evaluateJavascript("location.reload()") }`，
     用户立刻看到登录态失效。
   - setup 末尾立即 `Web2appBridge.rotate()` 并注入一次密钥（首个文档不等 onPageFinished）。
   - **类闭合 `}` 之后**注入顶层 `object Web2appBridge { @Volatile var key; fun rotate()
     = UUID.randomUUID().toString() }`（花括号配对定位，selftest 专门断言 object 在 class 外）。
   - 每个方法首参 `key`，统一经 `web2appBridgeOk(key)`（非空且 == 当页密钥）校验，不符静默 return。
2. **wry `RustWebViewClient.kt`**（`find_kotlin_file` 定位，包名不硬编码）：在老签名
   `onPageFinished(view: WebView, url: String)` 方法体**首行**（`Rust.onPageLoaded` 之前）插
   `val web2appKey = Web2appBridge.rotate()` +
   `view.evaluateJavascript("window.__web2appAndroidKey='$web2appKey';", null)`。
   安全依据：该老签名只可能是主框架回调；evaluateJavascript 只注主框架，
   跨源 iframe 读不到顶层变量 ⇒ 危险动作天然挡住第三方页面。

selftest 6 场景：PRISTINE 全要素（含 object 在 class 外）、幂等、POST_DOWNLOAD 形态
（只插一行、顺序 super<dl<extras、import 不重复）、畸形报错、client PRISTINE/POST_SCHEMES
（rotate 先于 onPageLoaded、与 schemes 补丁共存、缺方法报错）、临时 gen 文件级集成。

### 10.1 #5 `android_permissions` 打包字段（配置契约 20 → 21 键）

- 字段语义：字符串数组、白名单三值 `camera` / `microphone` / `location`，缺省 `[]`，
  trim + 去重保序，非数组 / 非字符串元素 / 白名单外一律打包期硬失败；紧凑 JSON 透传。
  非敏感字段（**不**进 SIGNING_KEYS），写进 Electron `config.json`，Electron 壳接受但忽略。
- 四处真源同步：
  1. `parse-packaging-config.py`：`ANDROID_PERMISSION_CHOICES` +
     `normalize_android_permissions()`、`build_merged` 单独取 raw、
     `write_config_json` 把 JSON 文本还原成真数组、契约表头与 DEFAULTS（21 键）、selftest；
  2. `scripts/packlib/{constants,parser,selftest}.mjs`：同名常量 / 归一函数（pyTypeName、
     pyRepr 对齐报错）/ parity 成功 4 例 + 失败 7 例 + toConfigJson 真数组断言；
  3. `electron-app/src/main/config.ts`：AppConfig + DEFAULTS + `toAndroidPermissions()`
     （只做形态校验，不重复白名单判定）；
  4. 两份 `config.example.json` 均加 `"android_permissions": []`。
- `.github/scripts/patch-android-permissions.py`（新增，7 组 selftest）：
  `--permissions` 参数或 env `ANDROID_PERMISSIONS`，空数组跳过 return 0；
  映射 camera→`CAMERA`、microphone→`RECORD_AUDIO`、
  location→`ACCESS_FINE_LOCATION`+`ACCESS_COARSE_LOCATION`；marker
  `web2app-android-permissions` 幂等；`rfind("</manifest>")` 前插入，缺标签 raise。
- workflow：build-custom.yml 加无参补丁步（env 经一次性 keystore 模板续行链
  `ANDROID_PERMISSIONS_VAL`，内联 cfg 契约键断言同步 21 键）；release.yml android job env
  `ANDROID_PERMISSIONS: ${{ vars.ANDROID_PERMISSIONS || '[]' }}` + 同一步；
  generate-signing-key.yml 内联 cfg 补 `"android_permissions": []`；
  ci.yml selftest 名单与步骤名同步。

### 10.2 #6 `patch-android-fullscreen.py`（新增，6 组 selftest）

- 补丁 wry 0.57 `RustWebChromeClient.kt`（按文件名 rglob）：ON_SHOW / ON_HIDE 两正则
  定位后**整体区间替换**（ON_SHOW.start → ON_HIDE 尾）；要求 ON_SHOW 体内仍含
  `onCustomViewHidden()`，否则判定上游已修、显式报错不替换；先 `_add_imports`
  （ActivityInfo / ViewGroup / WindowInsetsController / FrameLayout 四条）再**重算下标**。
- 注入块：custom view 承载（content 第 0 子 view GONE + MATCH_PARENT FrameLayout）、
  `SCREEN_ORIENTATION_SENSOR_LANDSCAPE`、`web2appSetImmersive` 双分支（API30+
  insetsController / 低版本 systemUiVisibility）、onHide 逆序还原后最后回调
  `callback?.onCustomViewHidden()`；marker `web2app-android-fullscreen` 幂等
  （marker 出现 2 次=onShow/onHide 各一条注释，属预期，selftest 按要素而非次数断言）。
- 两 workflow 在 schemes 步后、permissions 步前加「支持网页视频全屏」步。

### 10.3 #7 blank guard（`mobilebar.js` + `mobilebar.rs`，零 Kotlin 改动）

- `mobilebar.js` 新增 `installBlankGuard()`（仅 HAS_TABS 且非内置页，document-start 安装）：
  document 捕获阶段 click 监听向上找最近 `<a>`，`target` 用词边界正则匹配 `_blank`

  URL 合法且仅 http/https，复用 `new_tab(url)` + 导航 + 列表刷新）；与无 payload 落首页的
  `web2app:new-tab` 职责分离。单测 `open_tab_url_of_parses_url_or_gives_up`。
