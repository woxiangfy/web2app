# 2026-11-03

## 多页签支持 Ctrl+W 关闭当前页签（双壳）

需求：电脑端多页签模式下，用户希望像浏览器那样用 **Ctrl+W** 关掉当前页签（此前只能点标签栏上的 ×）。

### 判据（成对可观测）

| 场景 | 期望 | 验法 |
| --- | --- | --- |
| 焦点在网页里（用户正在页面里打字/点链接） | 关掉**当前激活**页签，激活落到相邻 | Electron 探针 P13（`sendInputEvent` → `before-input-event`）；Tauri 靠注入脚本 `tab_keys.js` |
| 焦点在标签栏（壳页面） | 同上 | 探针 P13 第二条；`shell.html` 的 keydown |
| 落在**首页页签**（位次 0） | **什么都不发生**（与「标签栏不画 ×」成对） | 探针 P13 第三条（集合/激活/窗口三者不动） |
| Ctrl+Shift+W / Ctrl+Alt+W / 长按 | 不算这条快捷键（Ctrl+Shift+W 在浏览器里是**关窗**，本壳不提供那条出口；长按不连关） | `test/page-behavior.test.ts` 三条单测 + `tab_keys.js` 同款守卫 |

### 实现（双壳两条通路，判据必须一致）

**Electron**
- `src/main/page-behavior.ts`：新增纯函数 `isCloseTabKey()`（只认 `keyDown` + `control` + `w/W`，排除
  `shift/alt/meta/isAutoRepeat`）与挂载 `attachCloseTabShortcut()`（`before-input-event` + `preventDefault`）。
- 挂两处：`tab-spawn.ts`（每个内容视图）、`index.ts`（壳页面）。两处合起来才覆盖两种焦点。
- ⚠️ 关页签动作用 `setImmediate` 推迟：它跑在该视图**自己的** `before-input-event` 派发栈里，
  就地 `webContents.close()` 等于「在自己的回调里销毁自己」。

**Tauri**
- 新增注入脚本 `src/tab_keys.js`：capture 阶段 `keydown` → `preventDefault + stopPropagation`
  → emit 核心事件 `web2app:close-tab`（payload 带建窗时注入的 `label` + 一次性 `token`）。
- `tabs/window.rs` 在建窗 builder 上 `initialization_script(include_str!("../tab_keys.js"))`；
  `tabs/state.rs` 新增 `TAB_CLOSE_EVENT`；`tabs/ipc.rs` 新增 `request_close_tab()`（校验令牌 → `close_tab_inner`）；
  `lib.rs` 注册 `app.listen(tabs::TAB_CLOSE_EVENT)`。
- `shell.html`（双壳共用）：新增 keydown → `invoke("close_tab", {label: active.label})`，
  首页那一签直接不发请求（`home` 标记由宿主下发，**规则本体仍只有 `is_home_index` / `isPinnedHome` 一份**）。
- 为什么不用 WebView2 的 `AcceleratorKeyPressed`：该事件只对「WebView2 自己会处理的加速键」触发，
  WebView2 没有页签概念 ⇒ Ctrl+W 不在其加速键表里，写了也永远不触发（假绿）。
- 判键**只看逻辑键位**（`key === 'w'/'W'`），不用物理码 `code`：`code` 按 US 布局命名，
  AZERTY 上「生出 `w` 的那个物理键」是 `KeyZ` ⇒ 按 `code` 匹配会把 Ctrl+Z（撤销）当成 Ctrl+W
  关掉页签。Electron 侧 `isCloseTabKey` 同样只看 `key`，双壳逐条一致（契约测试双向钉住）。

### 与既有约束的关系

- **首页不可关**（2026-10-13 的四元组/位次 0 约定）在这条新入口上继续成立：Rust 侧由
  `close_tab_inner` 第 ① 步拒绝，Electron 侧由 `closeTab` 的 `isPinnedHome` 拒绝 —— 新入口**不重复判定**。
- `tabs-remote.json` **不需要**加权限：远程 tab 页只能发核心事件，`core:event:allow-emit` 已在 v1.78 时授予。

### 门禁实跑（本机 Windows）

- Rust：`fmt --check` 绿；`clippy -D warnings` 仅 `os error 5` 目标竞争噪声（`grep -E "^error"` 无输出）；
  `cargo test --all` **282 passed / 6 ignored**（主 crate 207 → 209，新增 2 条静态契约）。
- Electron：`tsc --noEmit`（源码 + 测试配置）绿；`unit` **123/123**；`probe --tabs` **54/54**（47 → +7，
  新增 P13 三条主断言 + 一条**共享壳页面**断言 + 三条前提）；`probe` **150/150**；`smoke` 通过。
- **反向对照**（守卫必须会响）：把 `tab_keys.js` 的事件名改成 `web2app:close-tab-BROKEN`
  → `tab_close_event_contract_between_lib_tabs_and_script` 如期 **FAILED**；
  把 `window.rs` 的注入换成 `include_str!("../dnd_polyfill.js")`
  → `tab_close_shortcut_wired_on_both_focus_paths` 如期 **FAILED**；
  给 `tab_keys.js` 加回物理码兜底 `e.code === 'KeyW'`／把 `shell.html` 的键判改成只用 `e.code`
  → 同一条契约测试分别以「不得按物理键位匹配」「必须按逻辑键位判」**FAILED**；
  把 `shell.html` 的 keydown 提前 `return` → 探针 P13 ④ **FAILED**（连带清理步失败）。
  每次还原后 sha256 与改前逐字节一致。
- **共享壳页面的实跑点**：`shell.html` 的 keydown 在 Electron 里会被 `before-input-event` 的
  `preventDefault` 挡住（不挡就是一次按键关两个签），所以探针 P13 ④ 用**合成 keydown** 直达该
  handler（合成事件不走输入管线）。Tauri 侧本机不可跑探针 ⇒ 这是这份双壳共用代码唯一被真正
  执行到的地方。

### 仍未验

- Tauri 侧**真机目视**未做（`cargo build`/测试只证明编译与静态契约；按键链路要真机按一次）。
  关键不确定点：`window.__TAURI__.event.emit` 在目标站点 CSP 下是否仍可用 —— 与 `tab_title.js`
  同一条通路（该通路已在真机验证过标题回传），风险低但未复验。
- **已知边界**：Tauri 下焦点落在**同页 iframe** 内时 Ctrl+W 不生效（`tab_keys.js` 只在主框架发
  事件 —— label/token 只注入主框架，故意不给子框架）。让子框架转发等于「任意广告 iframe 都能
  关掉宿主页签」，权衡后不做。Electron 无此问题（`before-input-event` 按 webContents 触发）。
- 焦点在标签栏的 Ctrl+W 在 Electron 里由 `before-input-event` 先接住（`preventDefault` 挡住页面
  keydown）⇒ `shell.html` 那段处理器实际只服务 Tauri，本身已在探针 P13 ④ 用合成事件单独覆盖。

## 设置页「唤醒快捷键」交互重做（歧义 → 显式组合键）

起因（使用者原话）：**「设置中，唤醒快捷键，手动选择 存在歧义，是组合快捷键还是单个按键？」**

### 旧行为为什么会有歧义

| 入口 | 实际发生的事 | 用户看到 |
| --- | --- | --- |
| 「或手动选择：[下拉 主键]」 | 代码里硬写 `captured = { ctrl:false, **alt:true**, shift:false, key: 所选键 }` | 只显示「F9」，**看不出**它其实是 `Alt+F9` |
| 「点击捕获」 | 按什么记什么 ⇒ 只按 F9 就得到**裸单键** `F9` | 「F9」——和上面那种看起来一模一样，语义却相反 |

即：同一个下拉框旁边，一条入口**偷偷补 Alt**，另一条入口**允许裸单键**，而两者的显示文案完全相同。
裸单键不是「更灵活」而是事故：`globalShortcut.register('F9')` 会把系统里每次 F9 都变成「切换窗口」。

### 新交互（`webview-app/dist/settings.html`，双壳共用）

- 词表只有一种：**组合键 = 修饰键（Ctrl / Alt / Shift 至少一个）+ 主键**；主键留空 = 不设置。
- 一行显式构造器：`☐Ctrl ☐Alt ☐Shift  +  [主键 ▼]  =  [预览]`，并配一条实时状态行。
- **一个状态两个编辑器**：`captured` 是唯一真源，「手动组合」与「捕获」改任一处都 `renderHotkey()`
  把另一处一起重画 —— 不会再出现「显示 Alt+4、下拉却是 4」的错位。
- **「当前生效」与「待保存」分开**：左边 kbd 只在保存成功后才变（`savedHotkey`），右边预览才是
  手上正在拼的值；两者不同则状态行写「待保存：X（当前生效的是 Y，点保存后切换）」。
- **保存前校验**（`hkProblem`）：单键 / 系统占用组合（`Alt+Tab`、`Alt+Space`、`Alt+F4`、`Alt+Esc`、
  `Ctrl+Esc`、`Ctrl+Space`（中文输入法中英切换）、`Ctrl+Alt+Del`）/ 与「打开设置」冲突的 `Shift+F1` 一律拦截，预览框描边变红 +
  状态栏写明原因，**一个字节都不写盘**。
- **捕获路径同规则**：捕获到裸键或 Win 组合时**不接收**、继续等下一次（Esc 退出），
  不再先收下再在保存时炸。
- 两处顺带修掉的真缺陷：
  1. **先勾修饰键再选主键，勾选会瞬间被清空**（`readManual` 在 key 为空时把修饰键一起清零）——
     这是最自然的操作顺序，等于「勾了没用」。改为草稿期保留勾选，落盘前才归一成「不设置」。
  2. **历史配置里的键不在下拉列表时**（捕获可得到 `ArrowUp` / `Numpad3` / `BracketLeft` 等），
     `sel.value = key` 会落空 ⇒ 界面显示「无」而实际仍有快捷键，**一保存就把人家的键抹掉**。
     现在把当前键补进下拉（标注「其它键」，见复核轮 ①）。

### 取证

- **真实渲染截图**（Electron 620×600 / 460×600 / 浅色主题各一份，`capturePage`）：三态文案正确、
  窄窗按「修饰键一组 / `+ 主键 = 预览`一组」换行、`scrollWidth == clientWidth`（无横向溢出）、
  浅色下勾选与报错同样清晰；DOM 复核 `.op` 只有 `+` 与 `=` 各一个、三个控件同一行（`rowY` 146/148/147）。
- **探针 `probe --probe` 13b 七条**：组合键拼装 → 单键标红 → 单键保存被拦（主进程设置未变）→
  组合键保存生效 → 捕获裸键不接收 → Esc 退出。**150 → 157**。
- **反向对照**：把 `hkProblem` 的单键分支改成 `if (false)` ⇒ 三条断言 FAILED，其中
  「单键保存被拦」那一刻**真的把 `F9` 写进了设置**，证明确实是这道闸在拦事故；
  把 `readManual` 改回「key 为空就清修饰键」⇒ 第一条断言 FAILED（`on:0`）。还原后 sha256 逐字节一致。

### 边界（未做）

- `settings.json` 被**手工**改成裸单键仍会被接受（后端 `parseHotkey` 保持宽容解析）。刻意如此：
  若在保存路径上加「单键即拒」，老配置用户只要改个托盘开关就会被整条拒绝保存。
- 未加「按下即测能不能注册」的探测（会真的抢占全局键），仍由保存失败时的错误提示兜底。

## 复核轮（重新审查）：两个静默缺陷 + 一处守卫「假绿」

同一份改动的二次审查。**三处问题全部由实测发现，不是读代码猜的** —— 每一条都先写出「应该
发生什么」，再让脚本去证伪。

### ① 捕获「列表之外的键」时，下拉 `selectedIndex = -1`

**实测**（Electron 渲染真实 `settings.html`，点捕获后派发 `Ctrl+ArrowUp`）：

```
修复前：{ preview: "Ctrl+↑", sel: "", selIdx: -1, options: 36 }
修复后：{ preview: "Ctrl+↑", sel: "ArrowUp", selIdx: 36, selText: "↑（其它键）", options: 37 }
```

修复前那一行是**同一个病**换了个位置：预览框说 `Ctrl+↑`，下拉框什么都没选。而且用户随后
碰一下下拉，`readManual` 就用空值覆盖 `captured` —— 刚捕获的键被整条丢掉，看起来还像是
他自己选了「无」。

根因：补 option 的逻辑只写在**初始化**里（只处理历史配置），捕获发生在初始化之后。
修法：抽成 `ensureKeyOption(code)`，由 `renderHotkey` **每次**调用（先补选项、再 `sel.value`）。
顺带把标注从「（当前）」改成「（其它键）」—— 用户换成常用键后，「当前」这个标会过期，
反而变成假话。

### ② `get_settings` 失败后点保存 = 把配置覆盖成默认值

**实测**（preload 让 `get_settings` reject，然后点保存）：

```
修复前：calls = ["get_settings", "save_settings"]     ← 真的写盘了
        status = "已保存：未设置唤醒快捷键（托盘 / 最小化选项将在下次相关操作时生效）。"
修复后：calls = ["get_settings"]                      ← 一个字节都没写
        saveDisabled = true
        status = "加载设置失败：…。已禁用保存——现在保存会把已有配置覆盖成默认值，请关闭本窗后重开。"
```

触发条件不罕见：`settings.json` 被手工改坏 / 反序列化失败 ⇒ 界面全是默认值 ⇒ 用户只想改个
托盘开关 ⇒ 一点保存，快捷键、托盘、最小化三项一起被写成默认，还回一句「已保存」。
这与「升级后首次保存把配置清零」是同一类事故：**读失败被当成了「用户想清空」**。

修法三道，成对：
1. `loadFailed` 标志 + catch 里立刻 `btn.disabled = true`（视觉上断念想）；
2. 保存处理函数里第二道 `if (loadFailed) return`（按钮被重新启用的那天）；
3. 卡片内状态行改说「当前快捷键**未知**」—— 读失败 ≠ 未设置，说「未设置」等于报假情报，
   用户会以为自己的快捷键丢了。

### ③ 新加的静态守卫自己被注释骗过（假绿）

第一版 `settings_hotkey_contract.rs` 用 `contains` 做存在性断言。反向对照时把
`btn.disabled = true;` **注释掉**，测试仍然 `ok` —— 因为注释文本 `// reverse-check: btn.disabled = true;`
里就含有那个串。这正是本仓库记过的坑（「针会被注释满足」）。

修法：把 `mobile_bar_contract.rs` 里的 `has_code_line` 上提到 `contract_tests/mod.rs`
（`has_code_line` / `count_code_lines` / `strip_line_comments` 三件套，单一真源），
新契约全部走剥注释后的文本；位置断言（`ensureKeyOption` 必须在 `sel.value` 之前）也用
`strip_line_comments` 后的整车文本 `find`，否则注释里写一遍就能伪造顺序。

### 新增守卫

`src/contract_tests/settings_hotkey_contract.rs`（5 条，跨平台，无 `cfg(windows)`）：

| 测试 | 钉住的语义 |
| --- | --- |
| `hotkey_ui_is_an_explicit_combo_builder` | 三个修饰键 + 主键下拉 + 预览框必须存在，且修饰键由 `HKMODS` 单表驱动 |
| `hotkey_invalid_combos_are_rejected_before_saving` | 单一判据 `hkProblem`、拒绝裸单键、`Ctrl+Space`/`Alt+Tab`/`Alt+F4` 在册、≥4 处调用 |
| `hotkey_current_and_pending_are_separate` | 「当前生效」读 `savedHotkey`（不读草稿），保存成功才回写 |
| `hotkey_out_of_list_key_is_selectable` | `ensureKeyOption` 存在、在 `renderHotkey` 内、且排在 `sel.value` 之前 |
| `hotkey_save_is_blocked_when_settings_failed_to_load` | `loadFailed` 标志、catch 里禁用按钮、保存处第二道、状态行说「未知」 |

GUI 探针** ⇒ 「少一行就静默」的接线必须在静态层也钉一遍。
