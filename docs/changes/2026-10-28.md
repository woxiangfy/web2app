# 2026-10-28

## 修复：Android 打包崩在 `URLError: unknown url type: {     "app_url"`

### 现象

Actions 跑 `build-custom.yml`（勾选 `android`）时，「解析配置」步骤失败：

```
File ".github/scripts/parse-packaging-config.py", line 175, in read_raw
    with urllib.request.urlopen(req, timeout=30) as r:
urllib.error.URLError: <urlopen error unknown url type: {     "app_url">
```

### 根因（不是代码坏了，是填错了框）

`config_url` 输入框里收到的是**配置 JSON 正文**，不是 URL：`CONFIG_JSON` 为空 ⇒ 走到 `read_raw` 的
URL 分支 ⇒ `urlopen` 把 `{     "app_url` 当 URL 的 scheme 解析失败。旧实现对此毫无防护：

- 没有任何形态判断，`urlopen` 的裸栈直接冒到日志里（栈里全是 urllib，看不出是填错输入框）；
- 文档里「`config_url` 指向仓库内 `.json`」的建议**其实也是坏的** —— 相对路径没有 scheme，
  同样报 `unknown url type`；
- URL 拉取失败（私有仓库 / 拼错 / 超时）同样是一坨 traceback，而不是可照做的文案。

### 改动

`.github/scripts/parse-packaging-config.py` 的 `read_raw` 重写为**先判形态、再取内容**：

| 输入 | 行为 |
|---|---|
| `config_json` 有内容 | 原样返回（优先级最高，不去拉 URL / 不碰文件） |
| `config_url` 以 `{` / `[` 开头 | **按 `config_json` 处理** + `::warning::` 提示下次粘对框（本次照常出包） |
| `config_url` 带 scheme（`^[A-Za-z][\w+.\-]*://`） | `_fetch_url()` 下载，失败转 `ConfigError`（URL + `类型: 原因` + 常见原因） |
| `config_url` 无 scheme | 按**仓库内路径**解析（相对基准 `GITHUB_WORKSPACE`，不是进程 cwd）读文件；不存在则报「既不是 http(s) 地址，也不是存在的文件路径」+ 解析后的绝对路径 |
| 两者都空 | 报「至少填一个」+ 两项各自的正确用法 |

配套：

- 内置 `--selftest` 新增 4 组用例（JSON 粘错框 / 数组形态 / 绝对与相对路径 / 缺参、路径不存在、
  未知 scheme 的报错文案），断言「不许抛 urllib 裸栈」；
- 两个 workflow 的 `config_url` 输入框描述补「**不要把 JSON 内容填在这里**」；
- `docs/packaging-config.md` §7.1 补「别把 JSON 填进 `config_url`」及三条降级行为。

### 验证

| 命令 | 结果 |
|---|---|
| `parse-packaging-config.py --selftest` | 通过 ✓ |
| 复现原场景：`CONFIG_URL='{ "app_url": … }' --target android` | 退出码 0，`::warning::` + 21 个变量正常注入 |
| `CONFIG_URL='webview-app/config.example.json'` | 退出码 0（文档推荐用法这次真的能用） |
| 路径不存在 / 未知 scheme / 两项都空 | 均 `::error::` + 可照做文案，退出码 1 |
| `check-workflows.py` | 通过 ✓（7 workflow / 113 片段） |

## 修复 2（同日、同一条流水线）：Android 构建失败被 `| tee` 吞成绿色

### 现象

上一处修好后重跑，`android` job 报：

```
build-tools: /usr/local/lib/android/sdk/build-tools/37.0.0
使用 JSON 配置的 keystore 签名
Error: 未找到 *-unsigned.apk，构建产物异常
find: 'gen/android/app/build/outputs': No such file or directory
```

关键：**「Build Android APK」那一步是绿的**，日志里一行 error 都没有。

### 根因：`tee` 遮住了退出码（P0）

```yaml
run: cargo tauri android build --target aarch64 --apk 2>&1 | tee "$RUNNER_TEMP/android-build.log"
```

Linux 上 `run:` **不写 `shell:`** 时的默认模板是 `bash -e {0}` —— **不含 pipefail**。
管道退出码取最后一个命令（`tee`，恒 0）⇒ gradle / rustc 失败被吞、步骤显示绿色 ⇒ 失败只在
**下一步签名**里以「未找到 *-unsigned.apk」的形态冒出来，而 `find` 又只打印一句
`No such file or directory`。真实错误只躺在 artifact `android-build-log` 里。
叠加 job 的 `continue-on-error: true`，整条 run 甚至可能是绿的。

> ⚠️ 注意这次报错里 **`*-unsigned.apk` 是结果、不是原因**。真正的原因（gradle / rustc 报什么）
> 必须从 `android-build-log` 里看 —— 本次修复保证下一次运行会把那段摘到主线日志里。

### 改动

`build-custom.yml` + `release.yml`（两份同源，必须一起改）的 `Build Android APK` 步骤：

1. 显式 `shell: bash`（Linux 上该模板自带 `-eo pipefail`）+ 显式 `set -o pipefail`
   （不依赖 runner 模板，两个保险都上）；
2. `if ! … | tee …; then` 失败分支：打 `::error::`，并 `grep` 摘出
   `error[E…]` / `e: ` / `FAILURE: Build` / `What went wrong:` 等根因行 + 末尾 60 行；
3. 成功后**校验产物真的存在**（`shopt -s nullglob globstar` + `apk/**/*-unsigned.apk`）：
   「命令成功但没产物」在本步就红，不再让下一步背锅；
4. 下游「未找到 *-unsigned.apk」文案改为**指向 Build 步骤与 android-build-log**，
   并明说「本行只是结果不是原因」。

## 修复 3（同日）：继续排 Android「零产物」，把 CI 做成一次运行就说清

### 关键定性：**gradle 从来没启动**（所以问题不在签名步骤、也不在补丁脚本）

失败日志里 `find: 'gen/android/app/build/outputs': No such file or directory` 说明 `app/build`
**整个目录都不存在**。AGP 只要开始执行（哪怕只是配置后的第一个任务）就会建这个目录；目录不存在
⇒ 失败发生在 **gradle 启动之前** 或 **gradle 配置期就崩了**。`cargo tauri android build` 的流程是：

```
前置校验（config / npm-crate 版本） → 首次 Rust 交叉编译(aarch64) → gradle 配置 → gradle 执行
```

### 这一轮**排除**掉的嫌疑（都是离线可验证的）

| 嫌疑 | 验证方式 | 结论 |
|---|---|---|
| 12 个 Android 共享脚本自身逻辑 | 逐个 `--selftest` | 12/12 通过 |
| SDK 平台安装脚本 | `bash tests/ci-sdk-step/run-tests.sh` | 36/36 断言通过 |
| **我们的文本补丁把新模板改坏了** | 取 tauri 真模板（AGP 9.3.1 / Gradle 9.6.1 / Kotlin 2.2.10 / compileSdk 37）+ 本地 wry 0.57.0 的 9 个 Kotlin 模板，在临时目录**按 CI 顺序重放 11 步** | 11/11 通过，锚点全部命中 |
| tauri-cli 参数变了（`--target/--apk` 不再支持） | 读 CLI 2.12.4 的 `android/build.rs` 参数定义 | 仍然支持 |
| CLI 与 crate 版本不匹配会硬失败 | 读 `info/plugins.rs::check_mismatched_packages` | 只比 **npm 包 vs crate 的 major/minor**，本仓库无 npm ⇒ 不可能命中 |
| CLI 升级导致模板变化 | 对比 2.12.1 与最新 dev 的模板 | 一致（AGP 9.3.1 从 9-30 起就是这样）⇒ 不是"最近才坏" |
| 前端构建（`beforeBuildCommand`）拖累 | 读 `tauri.conf.json` | 空命令 + `frontendDist=dist`（仓库内已存在） |
| 中文 app_name 派生出非法包名 | 读 `derive_package` + 实测 | 纯中文走 `app+sha1` 兜底，合法 |

### 剩余三类（都只能由 CI 日志区分，不再猜）

1. **tauri 前置校验**（identifier / frontendDist 等 `bail!`）；
2. **Android 首次 Rust 交叉编译失败**（`#[cfg]` 分叉是本机盲区：Windows 绿 ≠ Android 绿）；
3. **gradle 配置期失败** —— 其中唯一"从未被编译过的新代码"是 `inject-gradle-patch-task.py`
   追加的 ~79 行 **Kotlin DSL**（10-16 加入，job 又是 `continue-on-error` + `tee` 吞错，没人发现过）。

### 改动

1. 新增步骤 **「Android 环境指纹（诊断用）」**（`build-custom.yml` + `release.yml` 各一份，只读、
   全 `|| true`、永不失败）：tauri-cli / rustc / rustup targets / java / **模板里钉的 AGP·Gradle·
   Kotlin·compileSdk** / `gradle.properties`（configuration-cache）/ SDK 平台 / build-tools / NDK /
   注入块末 6 行 / `gen/android` 概况。
2. 构建失败分支：日志摘录 60 → **120 行**，并探测 `app/build` 是否存在
   （「配置期就挂」与「编译期挂」从此一眼可分）。
3. **二分开关** `W2A_SKIP_GRADLE_PATCH=1`（默认关，`inject-gradle-patch-task.py`）：只跳过
   「在 gradle 里重放补丁」这一层，用于一次运行判定问题是否出在注入的 Kotlin DSL 上；
   ⚠️ 设了它之后 extras/schemes/fullscreen 会静默失效（wry build.rs 会覆盖），仅作排障。
   自测新增 1 组（设开关 ⇒ 正常退出 + 不注入 + 必须留一行警告）。
