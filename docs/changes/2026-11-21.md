# 2026-11-21 变更记录

## `debug=false` 时屏幕上不出现任何技术细节（两壳 + Android）

### 需求（用户）

> 如果打包参数 `debug` 为 false，启动时要关闭调试显示，用户不应该看到这些信息。
> 比如安卓端和电脑端的启动时。需要分析下，可能还有其他不需要给普通用户看的。

此前 `debug` 只关掉了**日志**（`startup.log` / stdout），屏幕上该显示的一样显示。

### 盘点：`debug=false` 时仍然可见的技术信息（改动前）

| # | 位置 | 用户看到的内容 |
|---|---|---|
| 1 | 加载失败卡（两壳共用 `loading.js`） | `地址: http://127.0.0.1:PORT/auth.html?w2a_key=***`、`状态: interactive，元素 0`、`HTTP: 200，资源 12，860ms`、**整条 UA**、页面脚本错误 |
| 2 | 同上 | 启动阶段进度：`正在解析目标地址（3 个域名）…`、`正在启动本地反向代理…`、`已发起导航，等待页面响应…` |
| 3 | 同上（Android 可达性探测） | `可达性探测：经本地代理访问上游 x.com 已连通（HTTP 200，123ms），但页面未渲染 —— 问题多半在本机 WebView 内核…` |
| 4 | Tauri `bootstrap.rs` | `解析目标地址失败：<hickory / JNI 原始错误>`、`无法打开页面：<wry 底层错误>`、`本地代理启动失败：<IO>`、panic 文本 |
| 5 | Electron `nav-text.ts` | `无法打开 https://真实地址/（ERR_CONNECTION_REFUSED，-102）` |
| 6 | Electron `navigate.ts` | `应用配置的网址不合法（Invalid URL）：<raw>`、`缺少本地代理组件（w2a-proxy）…：<raw>` |
| 7 | Electron `shell-overlay.ts` | `首个页签加载失败：<异常 message>`、重试失败弹窗里的 `e.message` |

已正确收敛、**未改动**的：日志文件 / `console.*`（`debug` 控制）、F12 DevTools（release 构建关闭）、
Android `chrome://inspect` 远程调试（仅 `debug_assertions` 构建打开）、右键菜单无「检查元素」。

### 改动

**一、共享 `loading.js` 增加诊断总闸 `DIAG`**

- 读 `window.__web2appDiag`，**只认严格 `true`，缺省 `false`**（安全默认：标记没送到 = 少显示诊断，
  而不是把 UA 泄漏给用户）；
- `pushNote()` 在 `!DIAG` 时**直接丢弃**（阶段进度 / 探测结论既不累积也不渲染）；
- `diagText()` 的三个拼接点按 `DIAG` 门控：`failCard`、40s 超时卡、overlay 空白文档卡；
  「仍停在启动页：导航没有提交」属分诊结论，一并隐藏；
- `debug=false` 时三类失败卡只剩一句用户能执行的文案 + 重试按钮。

**二、Tauri 注入（`loading.rs` / `lib.rs` / `tabs/window.rs`）**

- 新增 `diag_prefix()` + `pub fn overlay_script()`：把 `window.__web2appDiag = <DEBUG>;` 写在
  `loading.js` **同一段代码**前面（不另注册初始化脚本 —— 那样「标记丢了」只在运行时才看得见）；
- `splash_html()` 改用 `overlay_script()`（启动页与目标页必须同一套门控）；
- 两处注入点（主窗口 / 多页签窗口）改为 `.initialization_script(loading::overlay_script())`；
  源码常量 `OVERLAY_SCRIPT` 降为 `#[cfg(test)]` 的守卫锚点。

**三、Tauri 文案分级（`bootstrap.rs`）**

`解析目标地址失败` / `应用配置的网址不合法` / `无法打开页面` / `本地代理启动失败` / panic /
scheme 白名单错误：`DEBUG` 打开时保留原文（排障需要那句话），关闭时给可执行结论
（如「无法连接服务器，请检查网络连接后重试」）。

**四、Electron（`index.ts` / `nav-text.ts` / `navigate.ts` / `shell-overlay.ts` / `tab-spawn.ts`）**

- `readInject('loading.js')` 前置 `DIAG_MARKER`（定义已移到 `DEBUG` 判定之后，保证取值正确）；
  探针 / 冒烟仍然强制 `DEBUG=true`，取证能力不变；
- `debug=false` 时追加 `--log-level=3` + `--disable-logging`，把 **Chromium 原生 stderr**
  （GPU / network service / 证书告警）一起静音 —— 这部分不受 `silenceConsole()` 管辖；
- `navFailText(url, desc, code, debug)`：默认只给「页面无法打开，请检查网络连接后重试。」；
- `parseAppUrl(raw, debug)` / `sidecarFailureText(e, debug)`：原始异常与地址只在 debug 分支；
  `ResolveContext` / `NavigatorDeps` / `TabSpawnDeps` 增加 `debug` 并逐层传递；
- `showShellStartupError(win, detail, debug)`：`e.message` 与重试失败弹窗同样门控。

## 复审（同日第二轮）：两个漏网点

上一轮交付后重新按「用户还能看到什么」逐条走查（不看自己的改动清单，直接读代码路径），
发现两处**没有被这条契约覆盖**的地方：

### 1. Tauri 屏幕诊断只认编译期 `DEBUG`，丢掉了运行时逃生口

`diag_prefix()` 与 `bootstrap.rs` 的文案分级都写成 `if crate::config::DEBUG`，而 `config::DEBUG`
是 **`env_bool!` 编译期常量**。后果：交付包（`debug=false`）加 `--debug` 或
`WEB2APP_DEBUG=1` 重启后 —— **日志有了，屏幕还是那句通用文案**。而 Electron 侧的 `DEBUG`
本就包含 `--w2a-debug` / `WEB2APP_DEBUG` ⇒ 同一个逃生口，两壳表现分叉；手机上屏幕是唯一
能取到的现场（无控制台、无 adb），这个分叉恰好砍掉了最需要的那条证据。

- 修法：两处判定统一改成 `crate::debug_log::enabled()`（编译期 `DEBUG` **或** 运行时
  `--debug` / `WEB2APP_DEBUG=1`，结果已缓存）；Android 无命令行入口，实际仍只有编译期值。
- 静态守卫：`tauri_error_texts_use_runtime_diagnostics_switch` —— `bootstrap.rs` 里
  `crate::config::DEBUG` 出现即红灯；`tauri_injects_diag_marker_through_overlay_script`
  改为钉 `if crate::debug_log::enabled()`。

### 2. 可达性探测的**失败**详情绕开了总闸

`probe.rs` 的失败路径把 `probe_failure_message()` 的详情（含主机名 + 「域名解析失败 / TLS 握手
失败」分类）直接 `fail(t,d,soft)` 推给卡片 —— 它**不经过 `pushNote`**，`loading.js` 的 `DIAG`
管不到。于是出现分叉：探测**成功**的结论被隐藏，探测**失败**时主机名与技术术语反而显示。

- 修法：新增 `PROBE_FAIL_USER_DETAIL` + 纯函数 `probe_failure_detail(detail, diag)`，调用点传
  `crate::debug_log::enabled()`；`debug=false` 保留标题（「连接超时」「安全连接失败」对用户可读）
  + 一句可执行提示，主机名与分类术语不出现。
- 守卫：静态断言调用点分级 + 单测覆盖两分支（`probe_failure_detail_is_gated_by_diagnostics_switch`）。

### 复审验证

- `cargo test --all` —— **349 passed / 3 ignored**（19 + 22 + 38 + 270）；`cargo fmt` ✅。
- **反向对照 3 组**（改坏 → 红灯 → 还原，`sha256` 一致）：
  1. `loading.rs` 的 `if crate::debug_log::enabled()` 回退成 `if crate::config::DEBUG`
     ⇒ `tauri_injects_diag_marker_through_overlay_script` FAILED；
  2. `probe.rs` 调用点改成 `probe_failure_detail(detail, true)`
     ⇒ `probe_failure_detail_is_gated_before_reaching_overlay` FAILED（纯函数单测仍绿 —— 分层正确）；
  3. `bootstrap.rs` 一处回退成 `crate::config::DEBUG`
     ⇒ `tauri_error_texts_use_runtime_diagnostics_switch` FAILED。
- 未发现其它漏点（逐条核对）：`show_error` / `show_note` 的调用方全部分级或经 `pushNote`；
  `ensure_navigation_committed` 的重发进度走 `note`；其余 `eval` 注入点只写 UI 状态
  （标签栏 / 设置页复选框 / 历史前进后退脚本），无技术文案；标题栏 tooltip 不显示地址；
  Android「更多」面板按 2026-11-20 决定不显示当前地址。

## 两条 CI（`ci.yml` / `electron-ci.yml`）的覆盖缺口与优化

### 需求（用户）

> 「github 两个 CI 分析优化下 确保能够尽量覆盖。CI（Electron）不应该有选项（出包并上传产物）」

两个要点：① 两个 CI 的**覆盖尽量全**（不留「本地不跑、CI 也不跑」的盲区）；
② `electron-ci.yml` 触发时那个 `package` 布尔开关**去掉** —— 出包不再是可选项。

### 盘点（改动前）

| 缺口 | 事实 | 后果 |
| --- | --- | --- |
| **注入 JS 全无语法门禁** | `webview-app/src/*.js` 只被 `include_str!` 后注入；`mobilebar/*.js` 是**分片**（`core.js` / `mount.js` 单独拿出来根本不是合法脚本）；`src/*.html` + `dist/*.html` 的内联 `<script>` 同理 | 少一个括号 ⇒ 自绘标题栏整体消失 / 设置页白屏，**只在运行期现形**；Linux 作业够不着，只能等 Windows GUI 探针甚至真机 |
| **CI 出包是「可选项」** | `electron-ci.yml` 的 `package` 开关默认 `true`，但关掉就只跑 lint/探针 | 打包链路（`stage` / `prune` / `afterPack` / asar 双向断言）可以长期无人验证；一个「只想看 lint」的运行会让那一半永远绿不了 |
| **Windows 作业重复编译** | `check-windows` 是 `cargo check` → `cargo check(TABS)` → `clippy` → `test` 四轮全量 | `cargo check` 被 clippy 完全包含 ⇒ 白烧一整轮 |
| **探针与出包拆成两个 Windows 作业** | `package` 的 `needs: [lint, e2e]` 本来就是串行 | 重复 checkout / pnpm install / cargo 缓存恢复（约 3–5 分钟） |
| **Windows 上没跑 Electron 单测** | 只有 Ubuntu 的 lint 作业跑 `pnpm run unit` | 真 `win32` 分支（sidecar 可执行名、窗口平台判定）不被覆盖 |
| **无超时 / 无并发控制 / 无最小权限** | 两个 workflow 都没有 `timeout-minutes`、`concurrency`、`permissions` | GUI 探针曾在本机间歇卡死（默认能烧满 6 小时）；连点两次各跑一遍；`GITHUB_TOKEN` 权限按仓库默认（可能 write-all） |
| **文档与事实不符** | `workflows.md` 把 `ci.yml` / `electron-ci.yml` 写成「自动」；CI 步骤名里写着 `134 条 / 31 条`（早已是 178 / 69） | 误导后续维护（数字抄进步骤名 ⇒ 每加一条断言就要改一次，改漏即错） |

### 改动

**新增 `scripts/check-js-syntax.mjs`**（零依赖，Node `vm.Script` 只编译不执行）：

- `webview-app/src/*.js` 逐个整文件；`mobilebar/*.js` **按 `lib.rs` 里 `include_str!` 的真实顺序**
  拼成同一个 IIFE 再编译（顺序只从 lib.rs 解析，绝不手写第二份 —— 手写必然漂移，而漂移后的拼接
  能过语法检查、真机上语义错乱）；`src/*.html` + `dist/*.html` 的内联 `<script>`
  （先剥 HTML 注释：`splash.html` 头注释里就写着 `<script>` 字样，不剥会把注释当脚本；跳过
  `src=` 与 `type="module"`）；顺带 `node --check` 一遍 `scripts/**` 与 `electron-app/scripts/**`
  的 `.mjs` / `.cjs`（ESM 的 `import` 只能交给 node 自己解析）。
- **覆盖完整性**：发现结果必须非空，且 `webview-app/src/` 下每个 `.js` 都必须被某条规则覆盖到 ——
  新增子目录没纳入直接红灯（否则等于给新文件自动免检）。
- `--selftest` 8 条反向对照：坏脚本必报错、好脚本不误报、lib.rs 顺序提取、非分片的 `include_str!`
  不算分片、HTML 注释里的 `<script>` 不参与、外链 / `type=module` 跳过、漏项必须被抓到。

**`ci.yml`**：workflow 级加 `permissions: contents: read` + `concurrency`（同分支连点取消上一次）；
四个作业各加 `timeout-minutes`（30 / 45 / 60 / 20，防挂死不是估时）；`check-windows` 去掉
`cargo check --all-targets`（被 clippy 完全包含），顺序改为 `clippy → check(TABS_ENABLED) → test`
并对齐工具链组件；config-contract 增加「注入 / 内联脚本语法门禁」两步（先 `--selftest` 再真跑）。

**`check-workflows.py` 扩了两条 GitHub 自己不报错的结构性检查**（`--selftest` 13 条反向对照）：
① `needs:` 指向不存在的作业 id ⇒ 依赖它的作业一直 pending 到超时 / 直接跳过，看起来像「排队卡住」
（把 `e2e` + `package` 合并成 `e2e-package` 这种改名最容易漏）；② 引用未声明的 `inputs.<name>`
⇒ 表达式恒为空，带它的 `if:` 让作业**静默跳过** —— 正是本次删掉 `package` 输入后遗留 `if:` 会出现的
故障。`declared_inputs()` 两种 `on:` 键名都认（PyYAML 把裸 `on` 解析成布尔 `True`，经典坑），
引用扫描跳过整行注释、排除 `github.event.inputs.*`。

**`electron-ci.yml`**：删掉 `package` 输入与 `if:` —— 出包成为固定一环；`e2e` 与 `package`
**合并成单个 Windows 作业 `e2e-package`**（`needs: lint` 保留「类型不过不出包」的闸门），
顺序＝install → `unit`（Windows 侧补覆盖）→ 单窗口探针 → 多页签探针 → 冒烟 → `dist` + NSIS →
`check-asar-config.cjs` → 三个 upload；两个作业都补 pnpm store 缓存（`actions/setup-node` 的
`cache: pnpm`，因此 **`pnpm/action-setup` 必须排在 `setup-node` 之前**）、`permissions`、
`concurrency`、`timeout-minutes`；`rust-cache` 显式指 `workspaces: webview-app`
（sidecar 用 `--manifest-path ../webview-app/Cargo.toml` 编译，target 落在那里，不指就对着仓库根找）；
Ubuntu 作业加跑同一份 `check-js-syntax.mjs`。步骤名去掉写死的断言条数（时点值只留在注释里）。

### 影响面 / 未做

- 触发方式**没动**：两个 CI 仍是 `workflow_dispatch`（自动触发被刻意关掉，省 Actions 额度）。
  代价是「提交后没人点就永远不跑」，这是策略选择，不在本次范围。
- 未加「对**打包产物**再跑一次 `--probe`」（`Start-Process -Wait -PassThru` 取退出码）：
  它能覆盖 asar 内资源 + prune + sidecar 随包的真实运行态，但 GUI + 便携版自解压两条在
  GitHub runner 上没实跑过，先不把没验证的步骤塞进阻断链路。

## CI（tauri）Ubuntu 作业 dead_code 失败：P2-2 精确豁免补全

### 症状

CI 报 `could not compile web2app (lib) due to 8 previous errors` + `(lib test) due to 6`，
全部是 `-D dead-code implied by -D warnings`：`DATA_DIR`、`PROXY_HTTP/HTTPS/BYPASS`、
`TABS_ENABLED`、`random_hex_token`、`is_upstream_request`、`resolve_popup_target`、`HOOKS_RS`。

### 根因

P2-2 架构审查移除了 crate 级 `#![allow(dead_code)]`（且 `mobile_bar_contract.rs` 有守卫禁止恢复），
但**没有同步给这些「只有特定目标才被消费」的符号补精确豁免**。它们唯一的调用方分别挂在：

| 符号 | 唯一生产调用方 | 挂的 cfg |
|---|---|---|
| `DATA_DIR` | `config.rs::data_dir()` / `resolve_data_dir()` | `#[cfg(windows)]` |
| `PROXY_HTTP/HTTPS/BYPASS` | `config.rs::build_proxy_args()` | `#[cfg(windows)]` |
| `TABS_ENABLED` | `mod tabs` + `nav::main_window_label` / `mobilebar::tabs_available` | `windows` / `mobile` |
| `random_hex_token` | `tabs/window.rs` | `#[cfg(windows)]` |
| `is_upstream_request` | `webview_hooks.rs` | `#[cfg(windows)]` |
| `resolve_popup_target` | `tabs/ipc.rs` / `mobilebar.rs` | `windows` / `mobile` |
| `HOOKS_RS` | 唯一的测试本体 | `#[cfg(windows)]` |

Ubuntu 作业编译 Linux 目标，上述调用方全被摘掉 ⇒ 全 dead。本机只有 Windows target，
`cargo clippy --all-targets` 恒绿 ⇒ **这类错误本地永远看不见，只有 CI 的 Linux 作业能抓**。
lib 目标 8 个全 dead；lib test 目标里 `TABS_ENABLED`（`mod mobilebar` 是 `cfg(any(mobile, test))`）
与两个 `nav` 原语（本模块单测引用）幸免，剩 6 个。

### 修复

按 `lib.rs` 顶部「死代码豁免」约定，逐处挂**精确 `cfg_attr`** 并在注释里写明哪个目标用不到
（不恢复全局豁免）：`#[cfg_attr(not(windows), allow(dead_code))]`、`#[cfg_attr(not(any(windows, test)), …)]`、
`#[cfg_attr(not(any(windows, mobile, test)), …)]`；`HOOKS_RS` 随其唯一测试一起 `#[cfg(windows)]`。
顺手修正 `ci.yml` 第 184 行仍称「本 crate 有全量 `#![allow(dead_code)]`」的过时注释 ——
正是它把排查方向带偏到「全局豁免怎么失效了」。

### 验证

- Windows `cargo clippy --all-targets -- -D warnings` ✅。
- Linux 目标实测：本机 `rustup target add x86_64-unknown-linux-gnu` 下载 `rust-std` 9 分钟无进展
  （网络卡住），**未能实测**；但 9 处豁免条件在 Linux 下均为真（`not(windows)` /
  `not(any(windows, test))` / `not(any(windows, mobile, test))`），CI 的 Ubuntu 作业会做最终确认。
