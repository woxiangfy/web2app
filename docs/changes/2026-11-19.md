## Tauri 侧架构审查（模块划分 / 职责边界 / 依赖 / 复用 / 过度设计，重点 Android）

审查结论：整体健康，依赖方向已收敛，未发现新的跨 crate 重复实现。本轮**只做两项零行为变更**的
结构整理；实质缺口（移动端弹窗地址改写）与三项主链路改造按「需决策先暂缓」登记，不落地。

### 1 `bootstrap` 尾部 273 行 Android 可达性探测 → `src/probe.rs`

- **动机**：`bootstrap.rs` 873 行里，以 banner 注释隔开的 273 行是「导航之后为什么还白屏」的诊断
  （UA / 三类文案 / 探测目标选择 / reqwest 探测 / 错误归类 + 5 条单测），与「何时导航」的编排无关。
  一个文件两种变化原因 ⇒ 改文案要读启动时序，改时序要绕开诊断段。
- **处理**：整段搬到 `src/probe.rs`；`bootstrap` 保留两处调用点
  （`crate::probe::probe_target` / `crate::probe::spawn_reachability_probe`）。
  文件规模 873 → 504（probe 400 行，含 106 行单测）。
- **cfg 不变**（关键）：模块按 `#[cfg(any(not(windows), test))]` 挂载 —— Windows **发布**产物仍不携带
  这组仅 Android 使用的文案；Windows 宿主 `cargo test` 仍编译纯逻辑部分（目标选择 / 三条文案映射），
  Android 逻辑在桌面 CI 上仍有护栏。reqwest / `Url` 只出现在 `#[cfg(not(windows))]` 的探测本体里，
  `use tauri::Manager` 同样按 `not(windows)` gate（否则 Windows 测试构建是未使用导入）。
- **无行为变更**：搬家逐字复制，测试数不变（333，probe 的 5 条单测随实现一起迁走）。

### 2 `Settings` / `Hotkey` 下沉 `src/model.rs`（闭环 architecture-todo P-R1）

- **动机**：`store.rs::Document` 以 `settings::Settings` 为字段类型，`settings.rs` 又调
  `store::load/update` ⇒ 持久化层向上引用业务层模型，依赖成环（Rust 同 crate 允许，编译零告警，
  但方向是反的）。
- **处理**：新增 `src/model.rs`（106 行，**零 crate 内依赖**）：`Settings` / `Hotkey` + `Default`；
  `store` 改 `use crate::model::Settings`；`settings.rs` 用 `pub use crate::model::{Hotkey, Settings}`
  保留旧路径（`crate::settings::Settings` 仍可解析）⇒ `lib.rs` / `debug_log` / 契约测试的调用点零改动。
  方向变为 `store → model`、`settings → model`，类型环消失。
- **契约同步**：`settings_hotkey_contract::invalid_old_hotkey_falls_back_with_visible_notice` 里
  「提示必须 `#[serde(skip)]`」这条断言随字段改扫 `model.rs`（断言语义不变，只跟随落点）。
- **新增单测 2 条**：旧 `settings.json` 缺 `float_enabled` 仍可解析（按 false）；`hotkey_notice` 不落盘、
  回读为空。
- **未做的部分**：`docs/architecture-todo.md` P-R1 原文建议「并入 store 或独立 models」，本轮选**独立
  `model`** —— 持久化层不该拥有业务模型，`models` 语义过泛；`model` 只承载「会落盘 / 跨壳共享」的形状。

## electron-app：D3 执行 —— float-layout 导出面 `@internal` 注释级瘦身

背景：2026-11-18 第二轮架构复查遗留的待决策项 D3（见 `docs/changes/2026-11-18.md`）：`float-layout.ts`
30 个导出面中部分仅测试直接消费（2026-11-07 审查 L-2 残留）。决议：按建议执行**注释级瘦身**
（不改运行期行为；tsconfig 无 `stripInternal` / `declaration`，emit 语义不变）。

### 改动

- **消费面盘点（30 个导出）**：`float-window.ts` 真实消费 24 个（含 `FloatEdge` / `FloatGeom` / `Rect`
  三类型）；仅 `float-layout.test.ts` 直接消费 3 个 —— `decideEdge` / `clampFreeInside` / `rectAt`
  （生产实际经 `planDrop` / `planPeekCollapse` 组合消费，导出只为单测逐条钉规则）；其余 3 个为契约面
  （`MIN_PHYS` 落盘下限、`DropPlan` / `PeekCollapsePlan` 返回型别）—— **保留不标**。
- `src/main/float-layout.ts`：三个函数的 JSDoc 标 `@internal`（注明「仅供单测直接钉规则；生产经
  planDrop / planPeekCollapse 组合消费」），文件头补「导出面约定」一句。
- `test/float-contract.test.ts` 新增静态守卫 1 条：三个函数**各自的 JSDoc 块内**必须含 `@internal`
  （unit 233 → **234**）。

### 反向对照（含一次守卫自纠）

- ⚠️ 第一版守卫用「`export function` 前 500 字符含 `@internal`」判定 —— 回看窗口会覆盖**上一个函数**
  的标注（`rectAt` 吃到 `clampFreeInside` 的 `@internal`）⇒ **假绿**。收紧为「`lastIndexOf('/**')` 到
  `export function` 之间的本函数 JSDoc 块内必须含 `@internal`」。
- 改坏：摘掉 `rectAt` 的 `@internal` ⇒ 守卫精确红灯（`✖ 导出面…` / `rectAt 的 JSDoc 必须标 @internal`，
