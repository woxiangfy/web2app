## 安卓端「解析目标地址失败」：Manifest 缺 `ACCESS_NETWORK_STATE`（真机报错修复）

用户真机截图：域名数组配置的包一打开就停在失败卡，正文
`解析目标地址失败：读取系统 DNS 配置失败：JNI call error: Caught Java exception:
ConnectivityService: Neither user 10358 nor current process has
android.permission.ACCESS_NETWORK_STATE`。

### 根因（依赖源码可核对）

`hickory-resolver 0.26.1` 的 Android `system_conf` 实现是 JNI 调
`ConnectivityManager.getActiveNetwork()` → `getLinkProperties()` → `getDnsServers()` 取系统 DNS
（`~/.cargo/registry/.../hickory-resolver-0.26.1/src/system_conf/android.rs`），前两个接口受
`ACCESS_NETWORK_STATE` 保护 ⇒ 未声明时抛 `SecurityException`，`resolve.rs::build_resolver()`
的 `read_system_conf()` 直接 Failed ⇒ 整轮解析失败 ⇒ 启动页「加载失败」。
而 `patch-android-permissions.py` 当时是「`ANDROID_PERMISSIONS` 为空就整步跳过」，默认空数组
⇒ 生成工程的 Manifest 里从来没有这条权限。字符串 `app_url` 的包不走解析，所以完全正常。

### 修法（打包侧恒声明 + 运行期兜底，两层）

1. **打包侧**（决定性修复）：`patch-android-permissions.py` 增加**恒需权限块**
   （`INTERNET` + `ACCESS_NETWORK_STATE`），与打包配置无关、**缺失才补**（模板自带则不重复写，
   天然幂等），独立 marker `web2app-android-required`；`android_permissions` 恢复「只表达可选能力」
   的原语义。`main()` 不再因空数组提前返回。补丁链顺序与调用点不变，两份 workflow 的步骤名与
   注释同步。
2. **运行期**（第二道保险）：`resolve.rs::build_resolver()` 读系统配置失败**不再判死** ——
   改用新增的 `fallback_config()`（阿里 223.5.5.5 / DNSPod 119.29.29.29，UDP+TCP）继续查，
   并 `dlog!` 留一行「改为内置公共 DNS 兜底」。理由：读不到系统 DNS 配置 ≠ 网络不通
   （飞行模式 / 部分 VPN 下 `getLinkProperties` 也拿不到结果，同一形态）。
3. 新增单测 `resolve::tests::fallback_config_registers_all_builtin_dns`：钉住「兜底不是空配置」
   （写错 IP 会被 `filter_map` 静默吞掉，建 Resolver 时才炸 ⇒ 用户侧又是一个无解的失败卡）。

### 门禁与取证

## Android 打包「冻结契约」（评审意见驱动，只加文档 + 一条守卫，不改打包行为）

评审意见：打包逻辑是**下游项目的参照实现**，一旦定下来几乎不该再动；不能每次功能变化都改打包，
否则下游跟着变，参考实现就失去意义。据此重新分层，并把"能用自己的代码解决"定为默认选项。

### 结论（写进 `docs/android-packaging-freeze.md`）

- **三层模型**：L0 恒需常量（权限全集 / 明文策略 / 启动底色 / 包名版本烘焙 / APK 名，与配置无关）→
  L1 可选能力（只有 `android_permissions` 一个字段 + `tabs_enabled` / `mobile_bar` 两个形态开关）→
  L2 版本适配（wry 生成的 Kotlin 胶水 3 处 + `prepare-wry-kotlin` + `inject-gradle-patch-task`）。
- **诊断纠正**：本次缺 `ACCESS_NETWORK_STATE` 不是"配置面太宽"，而是**恒需常量被写成了随配置消失的
  分支**（`if not permissions: return`）。所以修法是"恒需无条件"，不是"再加一个开关"。
- **唯一产品输入面**：`APP_NAME` / `TITLE` / `VERSION` / `ANDROID_PERMISSIONS`（实测扫描 15 个脚本，
  其余只读基础设施变量）。
- **B 面（迁移路线，登记而非本轮执行）**：① schemes → Rust `on_navigation` + 官方
  `tauri-plugin-opener`；② extras 密钥轮换 → Rust `webview.eval`；③ fullscreen 跟随 wry 升级。
  ③ 完成后 L2 归零 ⇒ `prepare-wry-kotlin.py` 与 `inject-gradle-patch-task.py` 连同两份 workflow 的
  重放/校验步骤可整体删除（15 → 11 个脚本）。
- **不可替代清单**：Manifest 权限、`network_security_config.xml`、主题 `windowBackground`、
  Gradle 包名/版本/APK 名、`tauri.conf.json` 的 `identifier`。

## Android 打包 `error[E0603]`：`probe` 抽模块后可见性没跟着放宽（+ 新增桌面侧守卫）

CI 日志（`cargo build … --target aarch64-linux-android`）：

```
error[E0603]: function `probe_target` is private   --> src/bootstrap.rs:397
error[E0603]: function `spawn_reachability_probe` is private   --> src/bootstrap.rs:458
warning: unused variable: `app`  --> src/lib.rs:142
```

### 根因

架构审查（同日）把 `probe` 从 `bootstrap.rs` 尾部抽成独立模块，`fn` 的可见性**原样带过去**了。
抽模块本身把「同文件内私有调用」变成了**跨模块**调用，`fn` 必须至少 `pub(crate)`。

**为什么桌面 CI 全绿**：调用点（`#[cfg(not(windows))]`）与定义（`#[cfg(any(not(windows), test))]`
/ `#[cfg(not(windows))]`）在 Windows 上**一起被摘掉** —— 编译器两侧都看不见，自然不报错。
`cargo test --all` / `clippy -D warnings` / 15 个契约测试全在 Windows 上跑，全部漏过。
只有 Android 目标会同时看到「调用在」+「定义私有」。

⚠️ 顺带说明：`ci.yml` 的 `check-android` 作业（`cargo ndk -t arm64-v8a build` + Android 目标
`clippy -- -D warnings`）**本来就能拦下这条**（两处 E0603 与 `unused variable: app` 都会红）。
本次是 `build-custom.yml`（`workflow_dispatch` 手工出包）单跑，没等 `check-android` 绿 ——
这是流程缺口，不是门禁缺口。

### 修法

1. `src/probe.rs`：`probe_target` / `spawn_reachability_probe` → `pub(crate)`（附注释说明为什么
   不是多余的）；同文件内其余 4 个 `fn` 保持私有（只在本模块使用）。
2. `src/lib.rs::show_float_window`：非 Windows 分支加 `#[cfg(not(windows))] let _ = app;` ——
   该命令刻意跨平台注册（设置页是跨平台资源），Android 上无事可做，但参数会变「未使用」。

### 新增守卫（让桌面 CI 也看得见这类问题）

`src/contract_tests/module_visibility_contract.rs`：扫描 `src/**/*.rs` 的 `crate::<顶层模块>::<项>`
（`use crate::a::b` 同形态），若该项在模块文件里有**定义行**却不是 `pub*` ⇒ 红灯，并报
`引用文件:行号` + `定义文件`。口径刻意窄（见模块文档）：子模块再导出 / 宏生成 / `/* */` 注释一律跳过，
另带一条自校验「至少真的判过 10 处跨模块引用」，防止扫描方式与代码写法脱节后假绿。

- **反向对照**：把 `pub(crate) fn probe_target` 改回 `fn` ⇒ 红灯，报
  `src/bootstrap.rs:397 跨模块引用 crate::probe::probe_target，但它在 src/probe.rs 里不是 pub`；
  还原后 `src/probe.rs` / `src/lib.rs` sha256 与改前一致。
- `cargo test --all` **338 passed / 6 ignored**（259 + 38 + 22 + 19；较上轮 +1）、
  `fmt --check` ✅、`clippy -D warnings` ✅。Android 目标本机无 SDK/NDK，仍需 CI 复验。

### 教训（写进 `webview-app/AGENTS.md` 测试门禁）

**抽模块 = 可见性变更**：把代码从 A 文件搬到 B 文件时，凡是原来「同文件内调用」的 `fn` / `struct`，
都必须重新确认 `pub(crate)`。平台专属模块（`probe` / `mobilebar` / `floatwin`）尤其危险，
因为它们的错误在桌面 `cargo test` 里根本不会出现。
