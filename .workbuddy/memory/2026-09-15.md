# 2026-09-15

## CI 修复：Android 作业挂在 `setup-android` 步骤（`Failed to find package 'tools'`）

**现象**（用户贴的 run 日志，作业名 `Check (Android aarch64)`，耗时 1m45s 后失败）：
```
[===  ] 10% Computing updates...
Warning: Failed to find package 'tools'
Error: The process '/usr/local/lib/android/sdk/cmdline-tools/20.0/bin/sdkmanager' failed with exit code 1
Node.js v24.19.0
```
失败点是 **`Set up Android SDK` 这个 action 步骤本身**（不是后面的 `sdkmanager "ndk;..."`
也不是 gradle）——报错栈全在 `_actions/android-actions/setup-android/v4/dist/index.js` 里。

**根因（已核对上游源码，非猜测）**：`android-actions/setup-android@v4` 的 `action.yml` 里
`packages` 输入的**默认值就是 `'tools platform-tools'`**（该默认值是 2023-11-25 加的，当时
还能装到那个已废弃的历史 `tools` 包），而 Google 早已把独立的 `tools` 包换成 `cmdline-tools`
并最终下架 ⇒ sdkmanager 报 "Failed to find package" 并以 **exit code 1** 结束 ⇒ 整个 action 步骤失败。
日志里 `cmdline-tools/20.0` 也印证了该 action 的另一个默认值 `cmdline-tools-version: 14742923`（short 20.0）。
**我们的 workflow 一个字都没写错**：三条 workflow（ci.yml / release.yml / build-custom.yml）
都只写了 `uses: android-actions/setup-android@v4`，从没传过 `packages`，是上游默认值过时。

**修法**（三条 workflow 各 +8 行，保持行为不变、最小改动）：显式给 `with:`：
```yaml
      - name: Set up Android SDK        # / Set up Android SDK/NDK
        uses: android-actions/setup-android@v4
        with:
          packages: 'platform-tools'    # 只保留确实存在的包
```
（上游 README 自己的建议是「supply an empty string to skip installing additional packages」，
但保留 `platform-tools` 与改动前的实际效果最接近，故选它。NDK 本来就由紧跟的
`yes | sdkmanager "ndk;27.0.12077973"` 显式安装，不依赖这一步。）
- 全仓扫过：**没有**别处依赖 `tools` 包或 `$ANDROID_HOME/tools/bin`（只有 `cmdline-tools`/`platform-tools`/`build-tools`）。
- 校验：5 个 workflow 全部过 `yaml.safe_load`（`/c/Users/a03/.workbuddy/binaries/python/versions/3.13.12/python.exe`，PyYAML 可用）。
- **未推送**：本机仓库根＝`C:\dev\rust\web-app\webview-app`（remote `git@github.com:woxiangfy/web2app.git`，branch main），
  改动留作未提交状态等用户确认；本机**没有 gh CLI**（`gh: command not found`），要触发 CI 只能 push。

**经验（可复用）**
- 这类「第三方 action 的默认输入」是隐形地雷：报错栈落在 `_actions/<owner>/<repo>/<ref>/dist/index.js`
  里 ⇒ 基本可以断定失败发生在 action 内部，此时**先去读它的 `action.yml` 默认值**，别急着改自己的步骤。
  快手查法：`https://raw.githubusercontent.com/<owner>/<repo>/<ref>/action.yml`（verify 到具体 tag，别只看 main）。
- SHA 钉版本能免疫 tag 移动：`v4` 当前 = `40fd30fb8d7440372e1316f5d1809ec01dcd3699`（tag 类型直接指向 commit ⇒ 会移动）。
- 查「默认值什么时候变的」：`https://api.github.com/repos/<owner>/<repo>/commits?path=action.yml&per_page=8`
  （本次据此看到 cmdline-tools 20.0 是 2026-03-24 加的、仓里 README 还写着 16.0）。
