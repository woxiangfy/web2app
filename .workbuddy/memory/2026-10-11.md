### 经验教训（都值得跨会话复用）

- ⚠️⚠️ **「WebView2 初始化偶发停摆」是假象的一种**：真机探针在 `WebviewWindowBuilder::build()` 里
  约 50% 概率**永久挂死**（同步阻塞、进程内无法给自己设超时；换 exe 目录 / 换 UDF / 清残留
  `msedgewebview2` 全无效）。**应对 = 外部重试器**（按「输出停滞」判卡 → 杀进程 → 换新目录），
  并让探针自带看门狗（本机 `98`）与「环境没起来」专用码（`97`）。**不要把环境抖动写成产品缺陷。**
- ⚠️⚠️ **探针自己也要遵守产品契约**：假主窗漏设 `data_directory` 时建窗从 7~9ms 退化成 60s+ 甚至挂死，
  差点被归因成「WebView2 偶发停摆」。凡「探针里手写建窗」都必须与生产同构 —— 已加契约守卫钉住。
- ⚠️⚠️ **`Start-Process -PassThru` 不带 `-Wait` 读不到 `ExitCode`**（空值）⇒ 重试脚本会把「成功」
  当「非 0」**无限重试**。必须先 `WaitForExit()` 再 `Refresh()`。
- ⚠️⚠️ **守卫的针被注释满足（第五种形态）**：Electron `setShape` 守卫第一版用裸 `includes`，
  反向对照时把调用行改成**注释**后守卫**仍然通过**（注释含同样字面量）。**先剥注释再匹配**
  （`^[ \t]*//…$` + `[ \t]//…`）后才真咬人。**反向对照是唯一能发现这件事的办法。**
- ⚠️ **契约变更必须同步改测试，而不是改回去**：双击去抖让真机 harness 的「连点两次都必须 toggle」
  断言失效 ⇒ 改成三态（首次生效 / 窗口内丢弃 / 窗口外再次生效），顺带钉住 `pointercancel` 不触发。
- ⚠️ **`GetWindowRgnBox` 有含端语义**：椭圆在 `[0,70)×[0,70)` 上报 `(0,0,69,69)`（宽高各 −1），
  100%/125% 一致。断言按「实测含端」写，**不是**放宽判据。
- ⚠️ **`monitor_from_point` 用 `MONITOR_DEFAULTTONULL`** ⇒ 屏外的点查不到显示器、软钳制被整段跳过；
  探针测试点必须落在显示器**内**。
- ⚠️ **WebView2 的 UDF 落点 = `%LOCALAPPDATA%\com.example.web2app\EBWebView`，与 exe 所在目录无关**
  ⇒「换个全新目录跑 exe」不会换掉脏 UDF。要禁用它就**重命名备份**（本机删除有配额，且会反噬收尾删除）。
- ⚠️ **Electron 真机 harness 必须带 `--no-sandbox --in-process-gpu`**（本机 GPU 进程以
  `exit_code=-1073741819` / `FATAL: GPU process isn't usable` 退出是常态），并剥掉 `ELECTRON_RUN_AS_NODE`；
  给 `electron.exe` 传开关时**禁写 `--` 分隔符**。
- ⚠️ **多页签宿主窗漏 `data_directory`**（已修）：它是最先创建 WebView2 环境的窗口，漏设会让宿主的
  WebView2 数据落到系统默认目录（破坏绿色版承诺），并让同文件那段「同 UDF 首个环境」的 proxy 参数
  推理失去落点。**「同一不变量在多处实现」时，必须逐处核对，不能因为「另外两处都设了」就假定第三处也设了。**

## 09:00 使用者报「tauri 悬停球，不选中，图标背景有异样图形」→ 根因 + 修复（v1.73）

**现象**：hover 球时，球窗圆内、球本体之外的环带里冒出一块浅色残片（带圆角直边 + 一点点彩色小色块）。

**取证三层（都可复核）**：
1. 用户截图像素分层：残片外边界**逐行吻合活柱椭圆**（⇒ 被球窗区域裁剪）、另两条边是**带 ~4px 圆角的直线**
   （⇒ 属于另一个矩形窗口）、颜色 = **白 × 球自身深蓝投影 ~30% α**、内部彩块 = **ClearType 亚像素文字碎片**
   （棕/深蓝/浅青三色紧邻）。
2. **Electron 复刻同一份 `floaticon.html`**（透明 + `alwaysOnTop` + `setShape` 圆 + 真实鼠标 `SetCursorPos`
   + `PIL.ImageGrab`）：hover 出现「浅底深字」提示条、文案正是球元素的原生提示串，且**球圆完好压在它上面**；
   移开 1.2s 后同一区域恢复 ⇒ `hover vs nohover` 差异 bbox 就是它（脚本 `tests/float-tooltip-rc/`）。
3. 本项目自己的真机留档 `tests/float-tauri-diag/ball-v171.png` 里**早有同一条提示条**（当时深色主题 ⇒ 深底白字）
   ⇒ 「hover 球必弹原生提示」不是本轮引入。

**根因**：球窗 `always_on_top(true)`（`WS_EX_TOPMOST`），而 Chromium / 系统的原生提示条是**独立非置顶窗口**
⇒ 提示条永远被画在球窗**之后**；球窗又经 `SetWindowRgn` 裁圆 + 页面 `background:transparent` ⇒ 提示条只能从
**圆内环带**漏出。球窗只有 56 逻辑宽、提示条必然与之重叠 ⇒ **结构性不可用**，不是「位置不对」。

**修法**：`floaticon.html` 球元素去掉 `title`，改 `role="button"` + `aria-label`（读屏可见、**不产生原生提示**）；
操作说明本就在 `dist/settings.html` 悬浮图标说明里，文案零丢失；两壳共用同一份页面 ⇒ 同时修好。

**守卫 + 反向对照**：Rust `float_ball_has_no_native_tooltip`（只判「球元素那一个标签」，避开「针被注释满足」）
+ Electron `float-contract.test.ts` 第 35 条；把 `title="x"` 加回 → 两侧如期红 → 字节还原后
`floaticon.html` sha256 `83e2c391…fecd9` 吻合。

**门禁（实跑）**：Rust 工作区 **233 通过 / 6 ignored**（主 crate 160；浮窗契约 17→**18** 条）、
`fmt` 0 diff、`clippy -D warnings` 退出码 0（7 条 `os error 5` = target 竞争噪声）；Electron `unit` **92/92**、
`typecheck` 双配置 0 错误。**修复后复跑同一套 Electron 取证**：hover/nohover 差异 bbox 从
`(112,112,406,198)`（提示条）缩回 `(112,112,182,182)`（仅球自身 70×70 hover 样式）⇒ 残片消失。

**教训（可复用）**：
- ⚠️ **always-on-top 的窗口上不要用原生提示**（tooltip 是独立非置顶窗口，必被压在后面）—— 这不是平台 bug，是结构性冲突。
- ⚠️ **低分辨率截图也能定案**：靠「边界形状 + 颜色混合反解 + 三态对照」而不是靠肉眼。
- ⚠️ **取证脚本要留反向对照**：同一 harness 跑「修复前 / 修复后」两遍，差异 bbox 会自己说话。

## 本地打包 `EBUSY … unlink '…\app.asar'`（v1.74）

`tests/build-electron-all.bat`（`--config json/osfipin.mark.json --target electron-all`）退出码 1，
报 `EBUSY: resource busy or locked, unlink '…\tests\pack\electron\win-unpacked\resources\app.asar'`。
⚠️ 脚本自己承诺的「默认目录清不掉 ⇒ **自动**换全新目录重试、始终能出包」**没发生**。

**根因（两层）**
- **持锁者是 WorkBuddy 宿主进程**（Restart Manager 查出 `PID 7092 = daemon-app-server-entry.js`），
  不是打的包在跑、也不是删除垫片。性质：**持久**（连续 3 次 / 0.8s 间隔全占用）、
  **只读可用**（`FileShare.ReadWrite` 打开成功 ⇒ 只有 `unlink` 会 EBUSY，所以下载/校验步骤照常绿）、
  **孤立**（抽样 61 个文件——含 `tests/pack/electron` 全树 / `electron-app/src` TS / `webview-app/src` Rust——
  **只有那 2 个 `.asar`** 被占）。
- `packlib/util.mjs::isDeleteBlocked` 只认 `safe-delete|emptyDir|trash operation` ⇒ `EBUSY` 被判成
  「不是删除问题」⇒ 既不回退、也不打印那句「换一个全新目录再试」。用户全部可见信息 = 一句「退出码 1」。

**修法**
- 判据补第二类 `<CODE>: …, unlink|rmdir '<path>'`（CODE ∈ `EBUSY|EPERM|EACCES`）；
  **刻意只盯删除类系统调用、不用裸 `EPERM`** —— 受限网络下下工具集会以裸 `EPERM`（rename）失败，
  误判=白等一次重试 + 给出错误建议。
- `driver-electron.mjs` 两处文案改为覆盖两种成因（被占用 / 删除策略）。
- `--selftest` +7 正向 / +4 反向断言；反向对照（判据分支 `&& false`）→ **FAILED**，按字节还原后三文件 sha256 吻合。
- 端到端实跑 **4 m 09 s、退出码 0**：第 1 次撞 `EBUSY`（这次是 `default_app.asar`，删除顺序不固定）
  ⇒ 自动退回 `tests/pack/electron-local-20261011-103832` ⇒ 出 zip 155 MB + portable 102 MB，
  `check-asar-config` 护栏过（条目 50 / 注入资源 5 项齐全），tracked 文件按原 sha256 还原。

**取证手段（可复用）**
- ⚠️⚠️ **「能不能打开」不能判断「有没有被占」**：Node/libuv 默认带
  `FILE_SHARE_READ|WRITE|DELETE` ⇒ 被独占的文件照样 `openSync('r')` / `openSync('r+')` **成功**（本次实测）。
  可靠代理 = **同名 `renameSync(p, p)`**（被占抛 EBUSY，非破坏性）或 **Restart Manager**。
  落成一个工具：`tests/find-output-locker.ps1 -Target <文件或目录>`。
- ⚠️ 该 `.ps1` 必须存 **UTF-8 BOM**：无 BOM 时 PS 5.1 按 GBK 解析，中文字符串报
  `TerminatorExpectedAtEndOfString`（看着像语法错、其实是编码）。
- **受控对照**（区分「通用行为」还是「路径相关」）：往 `tests/` 写 120 KB `dummy-probe.asar` + 同尺寸 `.txt`，
  T+3/8/15 s **均未被占**；回退后新目录里**同样两个** `.asar` 也**未被占**
  ⇒ 是那两条具体路径的残留句柄，与扩展名无关、不是「见 `.asar` 就抓」。实验文件已清理。

**遗留**：`tests/pack/electron/win-unpacked/resources/` 下那两个 `.asar` 仍被占 ⇒ 该目录**现在删不掉**，
重启 WorkBuddy 释放；不重启不影响出包（会一直走时间戳目录，每次 ~150 MB，记得清）。
根 `AGENTS.md`「五、变更记录」未加行（该表已落后到 10-07，且该文件有在途改动，避免合并噪声）。
详细记录：`docs/changes/2026-10-11.md` 的 v1.74 节。

  —— 均不触碰断言集 / 判定逻辑 / 产品代码）。
- ⚠️ **变更是「等待上限」时，记录与源码的字面差异要显式声明**：否则「文档写 180、记录跑的是 120」
  会被后人读成「对不上」。明写「记录采集于放宽之前 + 放宽只影响超时判定」即可闭环。

## v1.77 悬浮球「背景异样」第二个源头：球窗其实带着任务栏按钮（Tauri-only）

- 起因：使用者真机「悬浮图标 背景异样(不选中时) 仅限 tauri 才会出现，Electron 版本无此问题」+ 截图。
- **先证伪再动刀**：对用户跑的 `osfipin.mark.exe` 做字符串取证 —— `aria-label="单击`=1、`title="单击`=**0**
  ⇒ v1.73 的「球元素不挂 title」修复**确实在包里**，症状是**第二个源头**（同名的另一处）。
- 形态坐实：截图像素分类，浅灰圆角残片 bbox 的 x 到 **81 已超出球窗椭圆裁剪区**（球只到 79）、
  内嵌橙 / 深蓝竖条、下缘圆角收拢 ⇒ 独立的**提示条类窗口**被 always-on-top 球窗压在身后。
- 根因：tao 0.35 两段实现 —— `ON_TASKBAR` **按「窗口无父」置位**（与 `skip_taskbar` 无关）⇒ 建窗时写死
  `WS_EX_APPWINDOW`；`set_skip_taskbar(true)` 只额外调一次 `DeleteTab` **且是在 `visible(false)` 时调的**
  ⇒ 对从未显示的窗口无效，`show()` 时按钮回来。本机读回球窗 `ex=0x40118` 坐实。
- 「仅限 Tauri」的答案：Electron `skipTaskbar: true` 是**真移除**（`WS_EX_TOOLWINDOW`）⇒ 没有承载提示条的
  载体。**Electron 球窗还带标题**（`title: deps.title`）却没症状 ⇒ 反证根因是 `APPWINDOW` 不是标题文本。
- 修法：显示球窗**只能**经 `show_ball()`（`show → unminimize → apply_ball_window_styles → delete_taskbar_tab`）。

### 本轮两条硬教训

- ⚠️⚠️ **tao 会在「显示路径」用缓存标志整体重写 `GWL_EXSTYLE` ⇒ 手改样式写在 `show()` 之前 = 完全没改**。
  `apply_diff`（`window_state.rs:315`）：`diff = self ^ new`，非空则末尾
  `SetWindowLongW(GWL_STYLE/GWL_EXSTYLE, …)`，值由**缓存的 tao 窗口标志**重新拼出
  ⇒ 缓存里没有的 `NOACTIVATE` / `TOOLWINDOW` 被抹掉、`ON_TASKBAR` 把 `APPWINDOW` 写回。
  读回证据：`ex` 始终 `0x40118`。**连带结论**：v1.72 加的 `WS_EX_NOACTIVATE` 用的是同一处「写在 show 之前」
  的调用点 ⇒ **一直没真正生效**（`0x40118` 里没有 `0x8000000`）。
  ⇒ 通用范式：**凡手改 `GWL_EXSTYLE`，必须在每次 `show()` / `unminimize()` 之后重补**，并读回校验。
- ⚠️⚠️ **取证前先确认「被测对象真的被创建了」**：本机默认 `settings.json` 里**没有** `float_enabled`
  ⇒ 球根本不建、枚举结果里看不到球窗，一度误判成「修复没生效」。
  另：本机受限会话下球窗 WebView2 初始化慢，`run_on_main_thread` 的 1s 兜底回调被推迟
  ⇒ 等 16s 时 `vis=False`、**20s** 才稳定可见（是环境等待，不是产品行为）。
- ⚠️ **「同名症状」不等于「同一根因」**：`title` 提示条（HTML 层，v1.73）与任务栏按钮浮层（窗口层，v1.77）
  现象几乎一模一样。修第二次时**必须先证明第一次的修复确实生效**（对产物做字符串取证），
  否则会在错误的方向上反复。

### 守卫与门禁

- 新增契约守卫 ⑥b `float_window_is_excluded_from_taskbar_and_has_no_title`
