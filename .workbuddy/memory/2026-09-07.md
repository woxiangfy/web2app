# 2026-09-07 工作日志

## 修复：Android 交叉编译失败（多页签改造的 cfg 隔离遗漏）

CI `check-android` 报 1 error + 2 warnings，均为多页签改造时 cfg 隔离不完整所致。

### 错误与修复
| 问题 | 位置 | 修复 |
|------|------|------|
| E0425 `handle_main_close` not found | `lib.rs` | 该函数原加 `#[cfg(not(target_os="android"))]`，但在 `CloseRequested` 被无条件调用 → **去掉函数级 cfg**，把 cfg 下沉到内部的 `window_state::persist_label` 那一行（真正桌面端专属的只有几何持久化） |
| warning: unused `old` | `settings.rs` | `old` 仅用于桌面端快捷键/托盘 diff → `let old` 加 `#[cfg(not(target_os="android"))]` |
| warning: unused `is_first` | `bootstrap.rs` | 仅 Windows 多页签缓存用到 → 函数加 `#[cfg_attr(not(windows), allow(unused_variables))]` |

### 关键经验（重要）
- **「模块级 cfg 剔除」与「调用点 cfg」必须成对检查**。抽函数时若给函数加 `cfg(not(android))`，务必确认所有调用点也在同样 cfg 下；否则 Windows 编译通过、Android 直接 E0425。
- 正确姿势：**尽量把 cfg 下沉到真正平台专属的那一行**，而不是整个函数。这样跨平台语义（如 Android 上读 SettingsState 判断托盘）不会被误删。
- cfg-only unused 变量是 Android/iOS 编译告警的常见来源，用 `#[cfg_attr(not(windows), allow(unused_variables))]` 局部放宽，比 `_is_first` 改名更能保留语义。

### CI 制度性修复
- `ci.yml` 的 `check-android` job 原本挂着 **`continue-on-error: true`** → Android 编译错误只黄灯不阻断，一路漏到打包 workflow。已**移除**，改为阻断（ubuntu-latest 预装 NDK，该 job 已验证可稳定运行）。
- 顺带修 `ANDROID_NDK_HOME` vs `ANDROID_NDK_ROOT` 不匹配的警告：setup-android 预置更新的 NDK 并写 `ANDROID_NDK_ROOT`，只设 `ANDROID_NDK_HOME` 会冲突 → 两个变量统一指向同一版本锁定的 NDK。

## 修复：Lint & Test (Ubuntu) —— 格式化 + Windows 专属 clippy 盲区

### 1. `cargo fmt` 历史债务
CI 的 fmt 步骤（`continue-on-error`，非阻断）报 `window_state.rs` 等文件的 let-else 未展开。
- **根因**：仓库**从来没跑过 `cargo fmt`**（HEAD 里 `use settings::{SettingsState};`、`else { return; };` 等处早已不合规），fmt 步骤一直是红灯但被忽略。
- 处理：全量 `cargo fmt --all`（10 文件，+114/-63，纯排版）。
- ⚠️ 教训：**本地 rustfmt 与 CI 可能不同版本**（本地 rustc 1.95.0；CI 用 `dtolnay/rust-toolchain@stable`，无 `rust-toolchain.toml` 锁定）。判断某条 diff 是「真实问题」还是「版本噪声」的方法：看规则类型——let-else 展开、`use {X}`→`use X`、中文字符计宽导致的换行属**真实问题**（所有版本一致）；而「合并短行」类可能是版本差异。
- ⚠️ 排查坑：`cargo fmt --check` 输出的是 **Windows 反斜杠路径**，用 `grep "src/lib.rs"`（正斜杠）匹配不到，会误判为「0 处差异」。

### 2. Windows 专属 clippy 盲区（重要）
- `tabs.rs` / `webview_hooks.rs` 是 `#[cfg(windows)]`，CI 的 clippy 跑在 **Ubuntu** 上**根本不编译**它们；而 `check-windows` job 只跑 `cargo check`、不跑 clippy → **Windows 代码的 clippy 问题在 CI 中完全不可见**。
- 实例：`tabs.rs` 中 `let _ = host.on_window_event(...)`（返回 `()`）触发 `clippy::let_unit_value`，只有本地 Windows clippy 才发现。
- 修复：去掉 `let _ =`；并在 `ci.yml` 的 `check-windows` 新增 `Clippy (Windows)` 步骤。
- 经验：**多平台项目要让每个平台都至少跑一次 clippy**，只靠单一平台的 clippy 会有系统性盲区。

### 两个环境坑
- `git worktree add /c/dev/...` 在 Windows git 下会被解析成 `C:/c/dev/...`（凭空多一层 `C:\c`）。用 **Windows 风格路径**（如 `C:/dev/...`）才正确。
- 本次又遇到 rustc 1.95 增量 ICE（`error copying object file ... 拒绝访问 os error 5` + `encode_metadata` panic）。该警告**不是代码 lint**，不触发 `-D warnings`，CI 因 `CARGO_INCREMENTAL=0` 也不受影响；本地删 `target/debug/incremental` 即可。

### 本地验证手段的边界（踩坑）
- 本地**无法**验证 Android：`cargo check --target aarch64-linux-android` 在 `ring` 的 build script 就失败（`aarch64-linux-android-clang` / `clang.exe` not found），无 NDK。**连 check 都跑不了**（不是链接问题，是依赖要编 C）。
- 替代方案：**穷举 `#[cfg(not(target_os="android"))]` 门控项 → 逐一 grep 调用点确认同样被门控**。已核查 `window_state::*`、`tray::*`、`settings::{hotkey_to_shortcut,settings_open_shortcut,open_settings_window}`、`tabs::*`，全部安全。
- 正向 `#[cfg(target_os="android")]` 块全局只有 `settings.rs` 的 `let root = base;` 一处，改动时优先确认它没被波及。
