# 2026-09-06 工作日志

## 多页签（tab）模式（仅 Windows）实施

需求定性：**同账号、共享数据**的多页签，非真正独立窗口。一个宿主窗口 + 顶部标签栏，每个 tab 是独立 WebviewWindow（共享同一 WebView2 data_directory，cookie/localStorage 天然互通）。tab 可新建/切换/关闭；`target="_blank"`/`window.open()` 直接新开 tab。编译期开关控制，默认关闭。

### 方案要点（收敛版）
- 共享数据这一约束**消除了代理/Cookie 隔离难题**：本地反向代理保持单实例单端口，所有 tab 连同一 `127.0.0.1:port`，`proxy.rs` 零改动。
- 「tab」本质是「多 WebviewWindow 叠放伪装」：tab 窗口去边框（`.decorations(false)`）+ 吸附到宿主窗口标签栏下方，宿主 Moved/Resized 时批量跟随。
- 标签栏走方案 X：宿主窗口渲染 `shell://localhost/`（自定义协议 + 前端 HTML），tab 增删切换经 IPC 回调 Rust。

### 改动清单
- `config.rs`：新增 `TABS_ENABLED`（env_bool!，默认 false）。
- `tabs.rs`（新增，`#[cfg(windows)]`）：`TabManager`（tabs/active/counter/navigation 缓存/titles）+ `shell` 协议 + `create_tab/switch_tab/close_tab/get_tabs/set_tab_title` IPC + `spawn_tab`/`activate_tab`/`close_tab_inner`/`relayout`/`push_tabs_to_shell`。
- `shell.html`（新增）：前端标签栏，高度 38px 与 `TAB_BAR_HEIGHT` 一致，`-webkit-app-region: drag/no-drag` 处理无边框窗口拖动。
- `bootstrap.rs`：`Navigation` 派生 `Clone` + 字段 pub(crate)；`bootstrap`→`bootstrap_for_label`/`bootstrap_inner`（首次启动缓存导航信息到 TabManager）；`navigate_main` 参数化 label；新增 `navigate_window`（Windows 复用缓存导航）。
- `lib.rs`：注册 shell 协议 + TabManager + tab IPC；setup 按 `tabs_enabled()` 分支建「宿主+首 tab」或「main」；RunEvent 按 label 路由（tab 前缀/宿主/main 三种关闭语义）；抽出 `handle_main_close`。
- `loading.rs`：`show_error`/`hide` 参数化 label；`js_str` 改 pub(crate)。
- `window_state.rs`：`persist_now`→`persist_label(app, label)`。
- `tray.rs`：`main_window_label()` 统一返回宿主/main；`toggle_window` 与菜单去硬编码。
- `webview_hooks.rs`：`NewWindowRequested` 在多页签模式下切线程后 `open_new_tab_from_request`（COM 回调不能直接建窗，须切后台线程 + run_on_main_thread 排队）。

- `cargo test`：11 passed / 3 ignored（联网 DNS）✅

### 踩坑
- tauri command 与同名私有函数不能共存（`close_tab` 冲突）→ 内部逻辑重命名 `close_tab_inner`。
- `.state::<T>()` 返回 `State<T>` 借用，链式 `.lock()` 的临时 MutexGuard 在块尾表达式会触发 E0716/E0597 → 必须先 `let state = app.state::<T>()` 绑定，MutexGuard 用 `let guard = ...` 绑定再 `*guard`。

### 补充：标题回传链路
- 新增 `src/tab_title.js`：独立注入脚本（不进 loading.js，因后者零依赖且 splash 模式也执行）。监听 document.title（MutationObserver + 定时轮询兜底）→ `invoke("set_tab_title", {label, title})`。
- label 由 spawn_tab 注入 `window.__web2appTabLabel`（js_str 转义），tab_title.js 读取。
- 已验证：`TABS_ENABLED=true` + `-D warnings` 编译通过。

## TABS_ENABLED 接入打包模板与 workflow

- `config.example.json`：加 `tabs_enabled: "false"` 字段。
- `build-custom.yml`：Windows/Android 两 job 的 Python 解析脚本 DEFAULTS 加 `tabs_enabled`、BOOL_KEYS 加 `tabs_enabled`；顶部字段说明注释补充；一次性签名材料的 cfg dict 也补 `tabs_enabled`（保证生成的 packaging-config.json 字段集完整）。解析后注入 `TABS_ENABLED=true/false` 环境变量 → Rust `env_bool!` 读取。
- `release.yml`：两 job 的 env 加 `TABS_ENABLED: ${{ vars.TABS_ENABLED }}`（release 走仓库变量，不走 JSON）。
- `ci.yml`：`check-windows` job 新增一步 `TABS_ENABLED=true cargo check --all-targets`，让 CI 覆盖多页签代码路径（默认开关关，否则 tabs 改动只在真机打包才暴露编译错误）。
- `README.md`：功能特性表加「多页签」行；打包配置说明加 `tabs_enabled` 字段说明段。

### 验证
- 三个 workflow YAML 均 `yaml.safe_load` 通过；config.example.json 合法 JSON。
- 模拟解析链路：`tabs_enabled: true`（布尔）→ BOOL_KEYS 处理 → `TABS_ENABLED=true` ✅。
- `TABS_ENABLED=true RUSTFLAGS="-D warnings" cargo check --all-targets` ✅（模拟 CI 多页签检查）。
