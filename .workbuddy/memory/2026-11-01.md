# 2026-11-01

## CI「Build Android APK」零产物 → 修注入块里的 `java.io.File`

- **现象**：CI android job 失败在 gradle **配置期**（Rust 编译已成功、`.so` 已进 jniLibs）：
  `app/build.gradle.kts:108:26: Unresolved reference 'io'`，`BUILD FAILED`，零 APK。
- **根因**：`.github/scripts/inject-gradle-patch-task.py` 注入的 Kotlin 里写了
  `val w2aScriptsDir = java.io.File(w2aRepoRoot, ".github/scripts")`。在 `build.gradle.kts` 里
  `java` 是 Gradle 生成的类型安全访问器（`JavaPluginExtension`，AGP 应用 java-base），**不是包名**
  ⇒ `java.io` 被当成员访问 ⇒ 列号 26 正好是 `io` 的起始列，与日志一致。
  该行 2026-10-16（`e588845`）随脚本新建引入；android job `continue-on-error: true` ⇒ 红了但 workflow 绿，
  从 10-16 潜伏到 11-01（与 `docs/changes/2026-10-28.md` §5 的第 3 类可疑点吻合）。
- **修复**：改 `w2aRepoRoot.resolve(".github/scripts")`（`w2aRepoRoot` 本就是 `File`）。
  `--selftest` 补两条守卫：注入产物（**剥 `//` 注释后**）不得出现 `java.io.`、必须由 `resolve` 派生。
- **取证**：selftest 通过；把行改回 `java.io.File` 反向跑 → FAILED；还原后 sha256 = `e7f7cf61…` 逐字节相同；
  临时 gen 目录目视注入产物正确。真 gradle 编译本机做不了（无 SDK/NDK）⇒ 等 CI 复核，不行再用
  `W2A_SKIP_GRADLE_PATCH=1` 二分。
- **文档**：新增 `docs/changes/2026-11-01.md`；`AGENTS.md` §五 加一行并摘掉最旧的 10-14；
  `webview-app/docs/android.md` 补「注入的 Kotlin 片段禁用 `java.io.*`」约束段。
- **未做（已记入 changes 文档 §5）**：android job 的 `continue-on-error` 仍在（静默失败根源）；
  `Line 017 android {}` 的 AGP 9 legacy DSL 弃用警告未处理（模板自带，非失败原因）；
  `src/lib.rs:131 unused variable: app` 警告未处理（非 Windows 目标）。
