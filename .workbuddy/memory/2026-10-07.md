## 修复 Android 自定义打包「Failed to find package 'platforms;android-37'」（v1.51，**未提交**）

- **现象**（用户实跑 `自定义打包` 贴回日志）：android 作业在「Initialize Android project + 安装匹配平台」步骤失败。
  日志顺序：`目标 compileSdk=37 buildToolsVersion=34.0.0` → sdkmanager 弃用告警 → `Warning: Failed to find
  package 'platforms;android-37'` → `yes: standard output: Broken pipe` → exit 1。
- **两个根因（都取实，不是猜）**：
  1. tauri-cli 模板（`crates/tauri-cli/templates/mobile/android/app/build.gradle.kts`，Tauri 2.12 起）把
     `compileSdk`/`targetSdk` 写成 **37** 且不再给 `buildToolsVersion` ⇒ 旧脚本回落 `BT=34.0.0`；
     而 SDK 仓库自 Android 16 起平台包带**次版本号**：`grep path="platforms;android-"` 于
     `dl.google.com/android/repository/repository2-3.xml` 得 `36.1 / 37.0 / 37.1 / 37.2`，**没有 `android-37`**。
  2. **新平台先落 canary**：`repository2-1.xml`（stable）平台只到 `android-36`；`36.1`/`37.x` 只在
     `repository2-3.xml`（canary）⇒ 安装命令还要带 `--channel=3`，否则「列得到也装不上」。
- **修复**：新建 **`.github/scripts/install-android-sdk.sh`**（`build-custom.yml` 与 `release.yml` 调同一份，
  两 workflow 里只剩一行 `run: bash ../.github/scripts/install-android-sdk.sh`）。脚本行为：
  init（缺 `gen/android` 时）→ 读 gradle 的 compileSdk → `sdkmanager --list` 枚举真实包名（`sort -u`）→
  「无小数优先 → 最小小数版本」挑包；缺版本则合并 canary 清单 + `--channel=3`；只装到 `android-N.x` 时补
  `platforms/android-N` 软链；两个通道都没有模板版本时回落最高可用平台并改写 gradle 的 compileSdk/targetSdk
  （`::warning::`）；build-tools 按「模板钉住 → 同主版本 → 最高可用」且失败不阻断；开头校验
  `tauri.conf.json` 存在（防止不在 `webview-app/` 下静默跑错）。
- **本地行为验证**（新增 `tests/ci-sdk-step/`，**未纳入版本控制**）：假 `sdkmanager`（复刻真实 `--list` 表格：
  包名在 Path 与 Location 两列各出现一次）+ 从真实清单提取的 stable/canary 数据（`data/repo-pkgs-*.txt`）。
  `bash tests/ci-sdk-step/run-tests.sh` → **PASS=33 FAIL=0**（9 场景：模板 37/36/39、无 gradle、存在无小数 37、
  模板钉住 buildToolsVersion、缺 tauri.conf.json 守卫 + **2 条反向对照**）。
- **干跑当场抓到两个真缺陷**（否则就是「改了但还挂」）：
  ① `APP_GRADLE=$(ls a b | head -n1)`：`ls` 参数不存在时退出码 **2** ⇒ 叠 `pipefail + set -e` 整步**静默
  exit 2、out.log 全空**（反向对照复现：rc=2、零输出）；
  ② 清单未 `sort -u` 时变量变多行 ⇒ 把**含换行的字符串**当包名传给 sdkmanager（实测建出畸形目录）。
- **新增静态守卫**：`check-workflows.py` 原本只查 `run:` 内联脚本（且仅显式 `shell: bash`）⇒ 抽出共享脚本后
  变成守卫盲区，故补 `.github/scripts/*.sh` 的 `bash -n`。反向对照：追加未闭合 `if` → `rc=1` + 明确报错；
  还原后 sha256 与改前一致、检查器复绿。实跑 `check-workflows.py` → 7 workflow / 79 片段 / 1 个 .sh 通过。
- **改动文件**：`.github/scripts/install-android-sdk.sh`(新) · `.github/workflows/{build-custom,release}.yml` ·
  `.github/scripts/check-workflows.py` · 根 `AGENTS.md`（2026-10-07 行补 v1.51）· `docs/changes/2026-10-07.md`（v1.51 条目）·
  `docs/packaging-config.md`（静态检查两处）· `webview-app/AGENTS.md`（Android 环境要求不再写死 build-tools 34/android-34 +
  config-contract 说明）。工作区文件是 CRLF（autocrlf=true），Edit 工具改完 CR 数 = 行数、diff 干净。
- **未取证**：没跑 CI（本机无 Android SDK/NDK，交叉编译做不了）⇒ **AGP 9.3.1 是否接受 `platforms/android-37.0`
  或脚本补的 `android-37` 软链，仍需重跑一次 CI 才能确认**；gradle 阶段以后（图标/MainActivity 补丁/签名）本轮未动。
- 顺带确认：`ci.yml` 的 Android 作业只装 NDK（`cargo ndk` 交叉编译，不跑 gradle）⇒ 不需要平台包，未受影响；
  NDK 仍固定 `27.0.12077973`（模板未给 `ndkVersion`，本次未动）。
