# 2026-10-10

## v1.68 悬浮窗三条「静默失败」缺陷修复（使用者要求：检查电脑端悬浮窗功能相关代码并修复）

起因：v1.67 交付的悬浮窗在本地门禁（cargo test / pnpm unit / probe）**全绿**，故按「先取证再动手」逐条复核，
抓出 3 条只在真机现形的缺陷（编译零警告、单测全绿）。三条各自补静态守卫 + **反向对照**。

### 缺陷 ①（Tauri）：设置里取消勾选 = 销毁，实际只等于隐藏

- 根因（源码级确证）：`destroy_float_window` 用 `WebviewWindow::close()`。tauri-runtime-wry 2.11.4
  `src/lib.rs` 把 `Message::Window(id, WindowMessage::Close)` **直接交给 `on_close_requested`**
  —— 与 **Alt+F4 同一入口**；于是 `lib.rs` 里 `label == float ⇒ api.prevent_close() + hide` 整段把它吞掉，
  `on_window_close` 永不执行 ⇒ 窗口永不销毁。`destroy()` 则走 `WindowMessage::Destroy` → 直接
  `on_window_close`、**不发任何事件**（tauri 文档：*does not emit any events and force close*）。
- 修法：改 `w.destroy()`；与既有正确写法 `tabs::close_tab_inner` 同款（那边注释就写着「强制销毁窗口」）。
- 顺带：`hide_float_window` 补 `moving.store(false)`（拖动途中被隐藏 → pointerup 不再来 → 残留
  `moving=true` 会让悬停展开/缩回**永久失效**）。Electron 侧 `hideFloatWindow()` 同款补 `moving = false`。

### 缺陷 ②（Electron）：开着悬浮窗退不掉程序

- 根因（**脚本实测复现**）：悬浮窗 `close` 默认 `e.preventDefault()` 转隐藏，而 Electron 里
  「close 被 prevent」会**取消正在进行的 `app.quit()`**。实测：`calling quit() → main close allowed →
  float close PREVENTED → STILL ALIVE`（进程活着、主窗已关、悬浮窗只剩隐藏）。`allowClose` 只管
  「关开关 / 主动销毁」，管不到 app 级退出。
- 修法：`FloatWindowDeps` 新增 `isQuitting: () => boolean`（入口接 `quitting`，由 `before-quit` /
  `requestQuit()` 置位），close 处理器 `if (allowClose || deps?.isQuitting()) { persist; return }`。
  实测修后：`main close allowed → float close ALLOWED → will-quit reached`（进程正常结束）。

### 缺陷 ③（Electron）：冷启动不建立进程级副作用（重启后悬浮窗 / 托盘图标都不出现）

- 根因（**脚本实测**）：入口冷启动 `applySettings(loadedSettings.settings, {persist:false})`，
  而 `runtimeSettings` 在模块初始化时就等于**同一份** `loadedSettings.settings`；托盘 / 悬浮窗都是
  「变化才动」diff ⇒ **恒为 false**。实测 `before(applySettings): calls=[]`（副作用调用数 **0**）；
  修后 `after(applyInitialSettings): calls=["showFloat"]`、`after(all-off): calls=[]`。
  同一根因对**托盘图标**同样成立（冒烟实测本机 `%APPDATA%\Baidu\settings.json` 里 tray_enabled=true
  ⇒ 修复前每次重启托盘都不出现）。
- 修法：控制器新增 `applyInitialSettings(next)`（= `applySettings(next, {persist:false}, DEFAULT_SETTINGS)`，
  `applySettings` 加可选 `prevOverride`），两处 diff 比较基准由 `deps.getSettings()` 改为函数开头 `prev`
  （否则 prevOverride 被绕过）；入口冷启动改调它。与 Tauri `lib.rs` setup 显式建托盘 / 建悬浮窗同语义。

## 悬浮球全量静态审计（v1.71 现状，未改代码）

轮次：使用者要求「全面分析悬浮球功能，目前还有很多问题」。逐文件通读 `floatwin.rs` / `floaticon.html` /
`float-window.ts` / `float-layout.ts` / `float-preload.ts` / `protocols.ts` / `tray.rs` / `contract_tests.rs`
(`float_window_contract`) / `float-contract.test.ts` / `float-layout.test.ts` + 真机日志（`tests/float-tauri-diag/`）。

**结论：机制层没有新发现的必然缺陷；剩余问题集中在「覆盖盲区 + 文档漂移 + 两壳不对称」。**

- 🔴 P0 **Tauri 侧拖动 / 吸附 / 悬停整条链路从未真机验证**：v1.70 的合成指针 harness
  （`tests/float-v170-harness/main.cjs`）第 14 行 `require('electron')` —— **只驱动 Electron**；v1.71 的
  Tauri 真机脚本（`tests/float-tauri-diag/*.ps1`）只验了「球窗出现 + 单击 toggle + 截图」。
  ⇒ `on_down/on_move/on_drag_end/on_peek_enter/on_peek_leave` 在真机上零证据。**这是最大风险敞口。**
- 🟠 P1 **Electron 无 SetWindowRgn 等价物 ⇒ 透明矩形（尤其四角）吃鼠标**：Tauri 侧
  `apply_live_region` 用 `CreateEllipticRgn`+`SetWindowRgn` 把**可视+命中**一起裁圆；`float-window.ts`
  里既无 `setShape` 也无 `setIgnoreMouseEvents` ⇒ 56×56 方角挡桌面点击（两壳不对称，changelog 里
  「透明矩形点击穿透」一直是「待真机」。Electron 44 有 `win.setShape(rects)`，d.ts:3480/6303）。
- 🟠 P1 **双击球 = 两次 toggle**（双壳）：页面对 `dblclick` 只 `preventDefault`，但两次 `pointerup`
  已各发一次 `click` ⇒ 主窗「闪现」一次。缺点击去抖（页面侧 ~250ms 或主进程忽略紧邻第二次）。
- 🟠 P1 **`capabilities/float-icon.json` description 漂移**（安全文档）：仍写「单击球**调出**主窗口」
  （v1.71 已改 toggle），且事件表只列 6 个，**缺 v1.70 新增的 `float-down` / `float-cancel`**。
- 🟠 P1 **`tray.rs::show_window` 注释漂移**：仍写「…/ **单击悬浮球** 共用」，但 v1.71 起单击球走 `toggle_window`。
- 🟡 P2 `store.rs` 文件头示例仍是 v1.67 的 `"width":320,"height":460`（措辞也还是「悬浮小窗」）。
- 🟡 P2 `floaticon.html` 里 `#w2f-ball{left:28px}` / `calc(100%-28px)` 硬编码的是
  **ICON_SIZE/2=28**，与 `PEEK_LOGICAL=28` 数值巧合撞车且**无契约守卫钉住**（改 PEEK 就会让球在活柱里偏心）。
- 🟡 P2 冷启动建球时 `set_focus()`（Rust）/ `w.focus()`（Electron）会**从小球抢走前台**。
- 🟡 P2 「立即显示悬浮图标」与勾选框语义不一致：勾选未开也能建球；只点按钮不保存 ⇒ 重启后球消失。
- 🟡 P2 非 Windows（Android）设置页照样显示「启用桌面悬浮图标」，勾选只写一个永不生效的布尔值。
- 🟡 P2 `floatwin.rs` 模块头版本叙述停在「v1.68 纠正 v1.67」，落后到 v1.71。
- ⚪ 待真机（非已知缺陷）：跨显示器 / 125%·150% 下的 `scale_factor` 与 `live_px` 瞬态（窗口与光标跨屏
  不同 DPI 的那一帧）；`MIN_PHYS=40` 与 `live_px` 下限 32 两个下限不统一（极端缩放才可达）。

**两壳对齐核对（均通过）**：常量 PEEK 28 / SNAP 28 / MARGIN 12 / MIN_VISIBLE 16 / COLLAPSE_DELAY 300 /
ICON 56 / MIN_PHYS 40 两侧一致；`toggle` 语义、`isQuitting`/`destroy` 放行、`applyInitialSettings` 冷启动
副作用、`placeFloat` 唯一定位入口、`clearDragRuntime` 统一清态均两侧同构。
