## Electron 多页签版出包（用户任务：「打包成多页签版本」）

**交付形态**：`electron-app/config.json` 的 `tabs_enabled` 置 `true`（多页签开关是**运行期**唯一开关，`TABS_MODE` 只在 `index.ts` 最外层分叉一次）。

**出包命令**（`electron-app/` 下）：
```
pnpm run stage
node node_modules/electron-builder/out/cli/cli.js --win zip portable \
  --config.electronDist=node_modules/electron/dist \
  --config.directories.output=release-tabs
```
⚠️ 不要用 `pnpm run dist -- --config.electronDist=...`：pnpm 会把参数原样拼成 `"--" "--config.electronDist=..."`（带引号），electron-builder 不认 ⇒ 退回「解压 cache zip」慢路径并卡死 9 分 39 秒（实测）。直接用 node 调 CLI 最稳。

**产物**：`release/Web2App-0.1.0-win-x64.zip`（154MB）、`release/Web2App-0.1.0-win-x64-portable.exe`（101MB）、解压目录 `release/Web2App-0.1.0-win-x64/`。

**修复的一处缺陷**（`src/main/index.ts`）：原 `TABS_MODE = cfg.tabs_enabled || TABS_PROBE` —— 让 config 的页签开关也能决定**探针**的起窗模式。`tabs_enabled=true` 的包上跑 `--probe`（112 条单窗口断言）会以页签模式起窗，单窗口断言往壳页面 `shell://` 注入脚本必抛 `Error: Script failed to execute`，退出码 1 且报错不指向根因。
改为 `const TABS_MODE = TABS_PROBE ? true : PROBE ? false : cfg.tabs_enabled`（探针模式与断言组一一对应，非探针模式行为不变）。
判据对照：同一份包修前 `--probe`=1、修后=0。

**验证结果**（全部 `Start-Process -Wait -PassThru` 取退出码，跑前 `Remove-Item Env:ELECTRON_RUN_AS_NODE`）：
- 源码态：`--probe` 112/112 通过（config `tabs_enabled=true`）、`--probe --tabs` 23/23、`--smoke` 0
- 解压目录版：`--probe` 0 / `--probe --tabs` 0 / `--smoke` 0
- 便携版：`--probe` 0 / `--probe --tabs` 0 / `--smoke` 0
- 负向对照：修复前的包 `--probe` = 1（证明退出码门禁不是恒绿）

**踩坑（新增）**：
1. **覆盖已有 `release/` 会 EBUSY**：`release\win-unpacked\resources\app.asar` 与 `Web2App.exe` 被外部句柄占用（`[IO.File]::Open(...,'None')` 证实；rename 也失败），两次重试都失败。更糟的是**失败的 electron-builder 已先把 `win-unpacked` 删成残缺**（只剩 `resources/`）。⇒ 出包绕法 = `--config.directories.output=<新目录>` + copy 归位（zip/portable 是可写的，只有 exe/asar 被锁）。
2. **探针不能在交付目录里跑**：在 `release-tabs\win-unpacked` 跑 4 次探针后，exe 同级多出 `data/session`（Chromium 会话缓存）并被 copy 进解压目录 ⇒ 污染交付物。**zip 是打包时生成的、干净**。以后探针应在 `tests/` 下的副本上跑。
3. **沙箱禁止删除（safe-delete fail-closed）**：`release/Web2App-0.1.0-win-x64/data` 残留删不掉；`tests/` 下为验证复制的 `Web2App-0.1.0-win-x64-portable.exe`（101MB）也删不掉 ⇒ **别把大文件 copy 进仓库目录**。

## 19:0x Electron 打包产物瘦身盘点（分析产出，未改打包配置）

**产出**：新增 `docs/electron-size-reduction.md`（实测基线 + P0/P1/P2 分级 + yml 组合 + 验证清单）。

**实测数字**：原始运行时 367.67MB（`electron.exe` 单文件 234.91MB，占 64%）；`release/Web2App-0.1.0-win-x64` 389.9MB（含 `data\` 45MB 污染，净 344.9MB）；`zip` 147.6MB；`portable` 96.5MB；`app.asar` 仅 0.20MB。可裁：`locales` 48.30MB（保 en-US/zh-CN/zh-TW = 1.68MB）。不可动：`resources.pak`/`icudtl.dat`/`ffmpeg.dll`。

**关键结论**：
1. zip 与 portable 同载荷差 51MB，差异全在压缩算法（deflate -mx=7 vs NSIS 内嵌 7z/LZMA，`NsisTarget.js:509`）⇒ 别去瘦 zip，直接主推 portable 或换 `7z` 目标（`targetFactory.js:10`）。
2. `electronLanguages` 必须写全名：源码 `ElectronFramework.js:58-101` 的匹配是「精确名 或 wanted 以 <文件名>- 开头」⇒ Windows 上写 `zh` 命不中 `zh-CN.pak`（前缀规则只服务 mac 的 `en.lproj`）；全不命中只 warn 后跳过。
3. 实测 `LICENSES.chromium.html` 19.52MB → 7z 后 0.18MB（108:1）⇒ 删它只省解压目录、还担合规风险，保留。
4. `dxcompiler+dxil` 25.99MB（WebGPU）/ `vk_swiftshader+vulkan-1` 6.16MB（无 GPU 沙箱的探针要用）有收益但默认不动。

**记忆维护**：MEMORY.md 超注入上限被截断 ⇒ 拆成「硬契约 + 指针」：Tauri 全量 → `topics/tauri-contracts.md`，教训全量 → `topics/lessons.md`，MEMORY.md 只留 Electron 全部 14 条 + A 三条高频 + 教训 TOP5（13.4KB → 约 9KB）。

**数据勘误（同日修正）**：上面「``data\`` 45MB / 净 344.9MB」是量错了对象——45.0MB 是 ``release\data\``（**同级**残留，不属于交付目录），而交付目录 ``Web2App-0.1.0-win-x64\`` **内嵌**的 ``data\`` 实为 **18.22MB**。正确基线：交付目录 389.88MB，清掉内嵌 ``data\`` 后 **371.66MB**（自洽校验：= 原始运行时 367.67 + app.asar 0.20 + sidecar 3.58 + inject 0.09 ≈ 371.5）。``docs/electron-size-reduction.md`` 与 ``MEMORY.md`` 已按此修正（P0② 收益 45→18.22MB；dir 目标 344.9→371.66MB）。教训：**量体积前先确认量的是哪个目录**，同名 ``data\`` 在两处都存在。

## 19:2x 复核「exe 不可动」结论：UPX 三变体实测全崩（推翻"能压"，坐实"剪不掉"）

**触发**：用户质疑前一轮「234.91MB exe 不可动」是否百分百确定，要求查社区成熟方案。按教训 C-16（结论落笔前三查）与 C-15（写方案前先实测）做了一轮**实测反驳**。

**A. 它是什么（PE 节表实测）**：`.text` 183.66MB + `.rdata` 43.32MB + `.pdata` 5.33 + `.data` 1.32 + `.reloc` 1.17 + `.rsrc` 0.10 + 9 个近空节 ⇒ **96.6% 是代码与只读数据，且官方已 strip**（无 `.debug*`/符号节，`.pdb` 只剩路径字符串）。`node_modules/electron/dist/electron.exe` 节表与打包后的 `Web2App.exe` **完全一致** ⇒ 不是本项目配置问题。**结论：剪不掉。**

**B. UPX 实测（三变体 + 对照组）**，下载 upx 4.2.4 到临时目录，对交付 exe 的**副本**操作：
| 变体 | 压缩结果 | `--probe` 结果 |
|---|---|---|
| `upx --lzma -9` | ❌ 被拒绝：`CantPackException: superfluous data between sections (try --force)` | — |
| `--force --lzma -9` | 234.91 → **72.95MB**（31.06%，115s） | ❌ **0xC0000005**（2.0s） |
| `--force -9`（默认 NRV） | 234.91 → **83.56MB**（35.57%） | ❌ 0xC0000005（1.0s） |
| `--force --lzma -9 --strip-relocs=0` | 234.91 → 72.95MB | ❌ 0xC0000005（2.0s） |
| **对照组：同目录/同参数/未压缩** | — | ✅ **ExitCode=0**，13.3s，112 条过 |
⇒ 责任在 UPX，不是环境。另：UPX 官方 768MiB 上限（conf.h）不构成障碍；但**手册明确"加壳程序不与其它进程共享内存"**，Electron 是多进程共用同一 exe ⇒ 每个进程各解压一份 235MB，磁盘省 162MB、运行内存涨几百 MB；LZMA 解压 7–9s/GiB ≈ 每次启动 +2s。同类已知 issue：upx#141（Electron exe 压后 Win7 APPCRASH）、#83（压后 0xc0000005）。

**C. 成熟方案对照**：①自编译 Electron（官方 `@electron/build-tools` + GN 参数裁模块）——**唯一能真正减小 exe 本体的合法路线**，但需 depot_tools + 数百 GB + 以小时计的构建，且每次升版本都要重做 ⇒ 可行但不经济；②mini-electron / miniblink——几 MB，官方自称实现约 90% Electron API，但 Windows only / Blink 落后 / 单进程 / session 模块缺失 / 商业授权 ⇒ 本项目（`WebContentsView` 多页签 + session 隔离）不适用；③换壳 Tauri——本仓实测 `web2app.exe` **11.06MB**，代价是把 Chromium 成本转给系统：本机 WebView2 固定运行时 **860.81MB**（`msedge.dll` 332.14MB），`tauri.conf.json` 未配 `webviewInstallMode` ⇒ 走 `downloadBootstrapper`。**没有任何可直接下载的"瘦身版 Electron"运行时。**

**D. 落回文档**：`docs/electron-size-reduction.md` 新增**附录 A**（PE 节表 + UPX 三变体实测表 + 三条路线对照 + 结论修正）；§1 与 §5.2 的"不可动"改为「在官方运行时 + 标准管线内不可裁；UPX 实测不可用；要减小只有自编译或换壳」。`topics/lessons.md` 新增 18–21 条（`--force` 默认答案是"不"；加壳类必须有未压缩对照组；加壳与多进程架构冲突；社区数字要标版本）+「二进制体积审计 SOP 4 步」。

**E. 清理提示**：测试产物在系统临时目录的 w2a-size-probe 子目录（exe.7z、upx.zip、upx-test 内含原始与 UPX 版 exe，合计约 700MB；沙箱禁止删除，可手动清理）；交付目录 `release\` **未被改动**（全程只在副本上操作）。
