# 2026-09-05

## 代码优化（webview-app）

全面代码走查后实施三类低风险健壮性/性能/安全加固，均不改变现有行为：

1. **Mutex 中毒防护**（lib.rs）：6 处 `.lock().unwrap()` 改为 `.unwrap_or_else(|p| p.into_inner())`，避免 Mutex 中毒（如全局快捷键回调内 panic）时连锁崩溃。涉及 SettingsState（get/save/快捷键 handler/close 事件）与 ProxyTask（ExitRequested）。
2. **DNS Resolver 复用**（resolve.rs）：原 `query_txt_all` 每查一个域名都重建 Resolver（重读系统配置 + 重建 reactor），改为 `build_resolver()` 构建一次、`resolve_url_from_domains` 内多域名共享同一实例。签名 `query_txt_all(resolver, domain)` 同步调整。
3. **消除 panic 隐患**（resolve-core/src/lib.rs）：`parse_public_key` 的 PEM 分支原用 `der[der.len()-32..].try_into().unwrap()`，改为 `der.get(..).ok_or(...)?` + `try_into().map_err(...)?`，边界异常走 Err 而非 panic。

验证：`cargo clippy --all-targets` 零警告；`cargo test --all` 11 passed / 3 ignored（联网 e2e 测试仍 `#[ignore]`）。

## lib.rs 模块化拆解

把 1282 行的 lib.rs 拆成 7 个职责单一的模块，lib.rs 本体降到 283 行（只留 `run()` 入口 + 模块声明 + 窗口生命周期事件）：

- `config.rs`（216 行）：编译期 env 注入宏（env_str/env_bool/str_eq）+ 全部 env 常量 + `sanitize_dir_name` + `build_proxy_args`。
- `bootstrap.rs`（172 行）：`bootstrap`/`prepare_navigation`/`navigate_main`/`Navigation`/`ProxyTask`/`SPLASH_BG`/`local_proxy_enabled`/`strip_userinfo`。
- `webview_hooks.rs`（268 行，`#[cfg(windows)]`）：`attach_webview_hooks` + `read_menu_count`/`read_menu_name` + 全部 webview2-com/windows use。
- `window_state.rs`（104 行，`#[cfg(not(android))]`）：原 `mod window_state` 整体抽出。
- `tray.rs`（158 行，`#[cfg(not(android))]`）：`create_tray`/`toggle_window`/`get_settings`/`save_settings`/`close_settings_window`。
- 拆解后调整引用：`crate::{sanitize_dir_name, APP_NAME}` → `crate::config::...`；`crate::bootstrap(...)` → `crate::bootstrap::bootstrap(...)`（模块名与函数名同名）；`crate::WINDOW_TITLE` → `crate::config::WINDOW_TITLE`；lib.rs/tray.rs 补回 `GlobalShortcutExt` trait 引入。

验证：`cargo clippy --all-targets -- -D warnings` 零警告；`cargo test --all` 13+11 passed / 0 failed / 3 ignored（联网 e2e）。功能不变。

## 加密层密钥防反编译（方案 A 已实施）

把 resolve-core 的硬编码 `SECRET` 改为编译期 env 注入（`RESOLVE_SECRET`，未设置回落 `web2app-fixed-secret-2026`），服务端 `tools/encrypt_url.py` 同步改为 `os.environ.get("RESOLVE_SECRET", 默认值)`。默认值不变 → 旧密文完全向后兼容（`e2e_ed25519_aesgcm_decrypt` / `e2e_crosscheck_python_generated` 全过）。每个打包产物可用独立 Secret，源码/二进制里不再有可搜索的固定密钥串。

- 结论：这是**提高门槛**而非根治——客户端持对称密钥的物理上限无法突破；真正可靠需换架构（运行时 TLS 下发 URL，客户端不内置密钥）。改 Secret 需两端同步切换，否则旧密文解密失败。

## resolve_secret 接入打包工作流

`build-custom.yml`（Windows/Android 两个 job 各一份）+ `config.example.json` 新增 `resolve_secret` 字段：
- 两处 DEFAULTS 加 `"resolve_secret": ""`（默认空=回落代码内置值，向后兼容）。
- 两处解析逻辑加 `merged["resolve_secret"] = merged["resolve_secret"].strip()`。
- 两处 display 遮蔽函数把 `resolve_secret` 归入敏感项（`***` 不打印明文）。
- 写入 GITHUB_ENV 走现有 `k.upper()` 逻辑，自动映射为 `RESOLVE_SECRET`，与 Rust 侧 `option_env!("RESOLVE_SECRET")` 对齐。
- 顶部字段文档 + config.example.json 补充说明。

注意：字段名是 `resolve_secret`（配置 JSON 用小写），编译期环境变量是 `RESOLVE_SECRET`（大写），靠 `k.upper()` 自动转换，勿在 DEFAULTS 里直接写大写键。

## 修复 Android 编译失败（拆解引入的平台门控错误）

CI 的 Android job 报 4 个错误，根因是拆解时把跨平台命令误放进了被 `#[cfg(not(android))]` 门控的模块，且一个 Windows-only 函数被无条件 import：

1. `bootstrap.rs` 无条件 `use crate::config::build_proxy_args`，但该函数是 `#[cfg(windows)]` → 改为条件 import（`#[cfg(windows)] use ...`）。
2. `lib.rs` 的 `invoke_handler` 无条件引用 `tray::get_settings/save_settings/close_settings_window`，但 `tray` 模块被 `#[cfg(not(android))]` 门控 → **把这三个 `#[tauri::command]` 从 tray.rs 移到 settings.rs**（它们本就是跨平台设置功能，Android 也需要）。同时把 settings.rs 的持久化函数 `save_settings` 改名 `persist_settings`（避免与命令同名递归），命令内 `create_tray` 调用改 `crate::tray::create_tray`。
3. `settings.rs` 的 `WebviewUrl`/`WebviewWindowBuilder` 在 Android 下未使用（`open_settings_window` 被 cfg 剔除）→ import 加 `#[cfg(not(android))]` 门控；补 `GlobalShortcutExt` 引入（命令里用 `global_shortcut()`）；`tray.rs` 删除随之不再使用的 `GlobalShortcutExt`。

验证：`cargo clippy --all-targets -- -D warnings` 零警告；`cargo test --all` 13+11 passed / 0 failed；`resolve-core` 在 `--target aarch64-linux-android` 下纯 Rust 编译通过（web2app 主 crate 的 Android check 仍被 `webview2-com` 缺 clang 阻塞，属已知本地无法交叉编译的限制）。
