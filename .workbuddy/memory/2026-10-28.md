## CI：Android 构建失败被 `| tee` 吞成绿色（同日第二处，改 6 文件 + 新增 harness）

- **现象**：`Build Android APK` 绿，下一步报「未找到 *-unsigned.apk，构建产物异常」+ `find: gen/android/app/build/outputs: No such file or directory`。
- **根因（P0）**：`run: cargo tauri android build … | tee log` 且**不写 `shell:`** ⇒ Linux 默认模板 `bash -e {0}` **无 pipefail** ⇒ 管道取 tee 的 0 ⇒ gradle/rustc 失败被吞。叠加 job `continue-on-error: true` 可整条 run 全绿。
- **修法**（`build-custom.yml` + `release.yml` 同源必须同改）：`shell: bash` + 显式 `set -o pipefail` + 失败分支摘根因行（`error[E` / `e: ` / `FAILURE: Build` / `What went wrong:`）+ 成功后校验 `apk/**/*-unsigned.apk` 真存在 + 下游文案改为「本行只是结果不是原因，看 Build 步骤与 android-build-log」。
- **守卫**：`android_build_step_must_not_swallow_failures`（**先剥注释**再匹配，防止注释满足针）；反向对照两处均 FAILED，还原 sha256 一致。
- **离线 harness**：`tests/android-build-step/run-harness.py` —— 从 YAML 抽真实 run 块、假 cargo 跑 3 分支 × 2 workflow，且用 `bash -e`（无 pipefail）执行，6/6 通过。
- **顺带**：`cargo fmt --all` 修掉 v1.81 遗留未格式化（`float_window_contract.rs`/`floatprobe.rs`/`floatwin/native.rs`/`floatwin/tests.rs`）—— HEAD 本来就会让 CI 的 fmt 门禁红。
- 门禁：Rust 279 passed / 6 ignored、clippy 干净、fmt ✓、check-workflows ✓。
- ⚠️ **真因仍未拿到**：gradle/rustc 到底报什么，只在那次 run 的 `android-build-log` artifact 里（`if: always()` 已上传）。
