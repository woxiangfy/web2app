## 修「单页签模式：最小化/最大化/关闭失效 + 打开其他页面后顶部栏消失」

### 根因（已证实）
- **按钮失效＝Tauri 2 对「远程 origin」强制 ACL**：`Webview::on_message`（tauri-2.11.5/src/webview/mod.rs）
  里 `if (plugin_command.is_some() || has_app_acl_manifest || !is_local)` 时强制校验，未命中 capability 一律拒绝。
  单窗口主窗加载的是**远程页**（直连域名，或本地反向代理的 `http://127.0.0.1:<port>`）——Windows 上只有
  `http://<scheme>.localhost` 才算 local（`is_local_url`：scheme 匹配 + 后缀 `.localhost` + scheme 已注册），
  所以 127.0.0.1 也是 remote。仓库此前**没有 capabilities 文件** → core:window 命令全被拒 →
  前端 `.catch()` 静默 ＝「点了没反应」。多页签模式没事：宿主 `shell://localhost` 是 local，且走应用自定义命令。
- **修法**：新增 `capabilities/default.json`（`windows:["main"]`、`remote.urls:["http://*","https://*"]`、
  5 个 core:window 权限：minimize / toggle-maximize / close / start-dragging / internal-toggle-maximize）。
  默认目录＝`CARGO_MANIFEST_DIR/capabilities/**/*`（tauri-build/src/acl.rs:428），构建期会校验权限 identifier。
  **应用自定义命令无法授权给远程 origin**（要 build.rs 的 app_manifest），故 titlebar.js 的前进/后退
  改为直接用 `window.history`（单窗口模式下与 Rust 的 history_nav 等价）。
- **拖动/双击**：Windows WebView2 上 `-webkit-app-region:drag` 不可靠，Tauri 只认 `data-tauri-drag-region`
  （drag.js：mousedown→`plugin:window|start_dragging`；detail==2→`internal_toggle_maximize`；clickable 元素默认挡拖动）。
  给标题栏与标题元素加该属性，并**删掉自绑 dblclick**（否则一次双击 toggle 两次＝无反应）。
- **顶部栏消失**：给 titlebar.js 加自愈守护（800ms 自检节点是否脱离文档→挂回，上限 20 次），
  覆盖 `document.write` 重写 / 框架重建 body 把注入节点整片抹掉这类「同文档内 DOM 被清空」的情形。

## 顺手修掉上节留下的「5s 未就绪」假告警（`attach_webview_hooks` 的 `done` 竞态）

上节末尾记的「已知待优化」已解决，根因不是"注册晚到 5s"，而是**判成功的标志用错了**。

### 现象与铁证
`%TEMP%\w2a_probe\app.log`（修复前）只有两行业务日志：
```
[webview_hooks] 单窗口模式拦截到新窗口请求：http://127.0.0.1:18100/page2.html
[webview_hooks] CoreWebView2 在 5s 内未就绪，窗口 main 的钩子未注册
```
第 1 行本身就证明 `NewWindowRequested` 处理器**已经被调用**（＝钩子早已注册），第 2 行却报未注册
⇒ 100% 误报，且每次启动/每个窗口必出现一条。

### 根因
旧循环**每轮新建**一个 `done` 标志，并在 `window.with_webview(...)` **返回之后立刻**检查它。
而 `with_webview` 从非主线程调用是**异步投递**（`proxy.send_event`）：返回时闭包还没执行 ⇒ 立刻检查
必然 `false`；闭包真正执行后置位的是**上一轮那个已被丢弃**的标志，再没人看它。于是**哪怕第一次尝试
就注册成功，循环也一定空转到 5s 超时**并打出假告警，同时每 50ms 排一个闭包、共白排约 100 个去占主线程
（能被 `HOOKS_REGISTERED` 闸门兜住不重复注册，但主线程白白多干 100 次活）。

### 修法（`src/webview_hooks.rs`）
- `done` 提到循环外，**全函数共用一个**；检查点从"投递后立刻"挪到**每轮开头**（此时已过完一整轮
  50ms，标志有充分时间被置位）。
- 超时后给**一次** 200ms 宽限：只 sleep 再 `continue`，让成功判定统一回到开头那一处 ——
  避免出现「其实注册上了却没有成功日志」的静默路径（第一版写成了在宽限分支里单独判断+静默 return，
  自己又制造了一个"日志与事实不符"的小坑，已改掉）。
- 成功时打一行确认日志（含尝试次数与耗时），让"钩子到底注册上没有"有据可查，不再靠猜。
- 同步更新两处过时注释：`attach_webview_hooks` 摘要里还写着"单窗口模式用 `SetNewWindow`"（上节已改实现）；
  `HOOKS_REGISTERED` 的文档补注"修掉竞态后在途闭包通常只剩 1~2 个，但闸门仍然必需"。

### 复验（真实 app，`APP_URL=http://127.0.0.1:18100/start.html PROXY_ENABLED=false`）

## 顶部栏占位 76px + 页面自己的头部被压（用户截图：空白条 / 显示不全）

用户报：单窗口模式「顶部标签会被网页计算出有空间，导致空白（图一）、显示不全（图二）」。
两处根因都在 `src/titlebar.js` 的 `html,body{padding-top:38px}` 上：

1. **留白 76px 而非 38px**：`html` 与 `body` 各加一次 padding，而 body 位于 html 的内容框内 ⇒
   页面正文被整体推低 76px，顶部露出空白条（图一）。
2. **padding 推不动 `position:fixed/sticky` 的页面头部**：这类头部恒锚在视口顶 `top:0`，
   于是被 38px 的标题栏压住上半截（图二）。sticky 头在**滚动后**才暴露（未滚动时它在流内，
   看起来正常），所以现象是"滚动到列表页就显示不全"。

### 复现与测量手段（不用截屏 —— 截屏抓不到 WebView2）
- WebView2 走 DWM 合成：GDI `CopyFromScreen` 拿到的是**下层窗口**、`PrintWindow(PW_RENDERFULLCONTENT)`
  返回**全黑**（实测 samePct=0.994），加 `--disable-gpu` 也无效 ⇒ 放弃 Win32 截屏。
- 改用「页面回传几何」：`%TEMP%\w2a_probe2\site.py` + `run_probe.sh <fixed|sticky|plain>`，
  页面把 `barRect/hdrRect/htmlPad/bodyPad/htmlBox/scrollY` 用 `<img src="/beacon?d=<json>">` 发回。
  入口 `start.html` 按 `scenario.txt` 用 `location.replace` **同步**跳转 ⇒ 换场景不用重编译。
- ⚠️ 只在这些**同步**时机上报（DOMContentLoaded / load / load 里手工再调一次）。本机窗口会被
  Chromium 判为「被遮挡」，`setTimeout/setInterval` 被节流到几乎不执行（16s 只出 1 条 beacon），
  连 `setTimeout(4500)` 的自动跳转都不触发。

### 修法（`src/titlebar.js`）
- CSS：`html{box-sizing:border-box!important;padding-top:38px!important;min-height:100%!important}`，
  body 不再加（`border-box` 让页面 `height:100%` 链 = 视口−38，不多出 38px 溢出）。
- 新增 `shiftPageTopBars()`：识别「宽≥视口一半、高≤视口一半、`rect.top ≤ 38+8`、声明 `top<38`」的

  **两阶段**（先只读收集、再统一写），避免逐元素重排；调度＝DOM 事件 + MutationObserver

  本环境的 `taskkill //F //IM` 实测**杀不掉**。
- 含非 ASCII 的 `.ps1`（无 BOM）会被 PowerShell 5.1 按 ANSI 读 ⇒ here-string 里的 C# 注释乱码、
  **把下一行吞进注释**导致编译失败。脚本一律 ASCII-only。

## 下载改走系统「另存为」对话框（`src/save_dialog.rs` 新增）

**需求**：网页里点下载「没反应」，应改成调**系统默认保存交互**（另存为对话框）。

**根因（读码 + MSDN 定案）**：旧实现（49be603 引入、一直没动过）只在 `DownloadStarting` 里
`SetResultFilePath(下载目录 + Content-Disposition/URL 里的文件名)` ⇒ 静默落盘、**零交互**；
且 MSDN 明说 ResultFilePath 指向已存在文件时「the file will be overwritten」⇒ 同名文件被直接覆盖。
用户看到的「没反应」= 既没有系统对话框、也没有 WebView2 下载 UI（旧的注释本来就写着「不弹 WebView2 默认下载栏」）。
仓库/历史里**从未有过** rfd / tauri-plugin-dialog / IFileSaveDialog 实现（`git log -S` 查过），「之前实现过」指的是下载拦截本身。

**MSDN 关键语义（`ICoreWebView2DownloadStartingEventArgs`，实测文档原文）**
- `Handled=true`：**只是隐藏默认下载对话框**，下载**照常进行**（"The download will progress as normal
  if it is not canceled, there will just be no default UI shown"）；默认 `false` ＝显示默认下载 UI。
- `Cancel=true`：下载取消，且"regardless of the Handled property"都不显示默认保存 UI。
- `ResultFilePath`：绝对路径（含文件名）；指向已存在文件 → **覆盖**；目录不存在 → 自动创建。
- `GetDeferral()` 存在（原计划异步弹框用，最终没用上）。
- 推论：**想「静默 + 无 UI」**＝`SetHandled(true)`（光设 ResultFilePath 仍会弹默认 UI）。

**实现**（`src/save_dialog.rs`，cfg(windows)，`SaveChoice{Save|Cancelled|Unavailable}`）
- `DownloadStarting` 回调里**同步**弹 `IFileSaveDialog`：确认 → `SetResultFilePath` + `SetHandled(true)`；
  取消 → `SetCancel(true)`；对话框建不出来 → **什么都不设**（保持 WebView2 原生行为，不静默改用户数据）。
- 默认值：文件名＝`suggested_filename()`（Content-Disposition → URL 末段 → "download"，照旧清洗）；
  默认目录＝`app.path().download_dir()`；`FOS_FORCEFILESYSTEM|PATHMUSTEXIST|OVERWRITEPROMPT|NOREADONLYRETURN`。
- 跨模态记忆靠 Common Item Dialog 自身（按 exe 记 LastVisitedPidlMRU），无需自己存。
- ⚠️ **必须主线程同步弹**：`Show` 会在当前线程跑模态循环。换后台线程同时丢两样东西：
  ① owner 窗口与对话框跨线程 ⇒ 没有真模态；② windows-rs 的 COM 接口**不是 Send**
  （`IUnknown(NonNull<c_void>)` 没有 `unsafe impl Send`），`args`/`deferral` 送不回主线程。
  好在 `webview2_com::EventClosure` **没有 Send 约束** ⇒ 回调闭包可以捕获 `HWND`（它本身 !Send）。
- 前提已成立：tao（`window.rs:1450`）与 wry（`webview2/mod.rs:115`）都调了
  `CoInitializeEx(None, COINIT_APARTMENTTHREADED)` ⇒ 主线程是 **STA**，Common Item Dialog 可用。

**windows crate 用法要点（踩点记录，下次直接照抄）**
- 只需给已有依赖加 feature：`Win32_UI_Shell` + `Win32_UI_Shell_Common`（不引新 crate）。
- `CoCreateInstance(&FileSaveDialog, None, CLSCTX_INPROC_SERVER)`（CLSID 在 `Win32::UI::Shell::FileSaveDialog`）。
- `SHCreateItemFromParsingName::<_, _, IShellItem>(&HSTRING, None)` 可设默认目录（`Param<T> for Option<&T>` 存在）。
- `Show(owner)` 在 `IModalWindow` 上，靠 `IFileSaveDialog → IFileDialog → IModalWindow` 的 Deref 自动解析；
  签名是 `Show(&self, Option<HWND>)`，取消＝`Err`（`ERROR_CANCELLED`）。
- `COMDLG_FILTERSPEC` 里的 `PCWSTR` **不持有**字符串 ⇒ 两个 `Vec<u16>` 必须活到 `SetFileTypes` 返回后。
- `IShellItem::GetDisplayName(SIGDN_FILESYSPATH)` 返回 CoTaskMem 串 ⇒ 读完 `CoTaskMemFree`。
- 项目内已有单版本 `windows 0.61.3`（Cargo.lock），tauri 的 `hwnd()` 就是同一类型的 `HWND`。

**验证**：`cargo check --lib` ✅ 首编即过 · `cargo clippy --all-targets -- -D warnings` ✅ 0 warning ·
`cargo test --lib` ✅ 39 passed（新增 `suggested_filename_*` 2 个）· `cargo build` ✅。
**待真机**：点下载 → 应弹系统「另存为」；判据＝stderr 里 `[webview_hooks] 下载：正在询问保存位置（建议文件名 X）`
（这行在弹框**之前**打，专门用来区分「钩子没触发」与「对话框没弹」）。

（代价：WebView2 自带下载 UI 会一起出现，与旧注释的取舍相反）。
