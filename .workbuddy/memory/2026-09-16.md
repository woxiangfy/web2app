## 两个真机 bug：标题栏按钮失效 + 页面底部被切

### 1. 「关闭/最小化按钮又失效了」＝ capability 的 remote.urls 没带端口通配
- 现象：右侧顶部按钮点了没反应（前端静默）。探针 `/diag.html` 直接问出了真话：
  `window.toggle_maximize not allowed on window "main", webview "main", URL: http://127.0.0.1:18200/`
  `allowed on: [windows:"main", URL: local], [URL: http://*], [URL: https://*]`
- 根因：tauri 用 **URLPattern** 匹配（`tauri-utils::acl::RemoteUrlPattern`），而 URLPattern 里
  **不写端口 ＝ 只匹配该 scheme 的默认端口**。`http://*` 匹配不了 `http://127.0.0.1:18200/`；
  `https://*` 匹配 443 所以直连域名时是好的 ⇒ 一旦换成本地反向代理（端口随机）按钮全废，
  看起来就是「之前修好了、现在又坏了」。
- 独立验证（`%TEMP%\urlpat_probe`：复刻 tauri 的 from_str + urlpattern 0.3.0）：
  `http://*` → 127.0.0.1:18200 = false；`http://*:*` = true；`https://*:*` 连 8443 也 true。
- 修：`capabilities/default.json` → `remote.urls: ["http://*:*","https://*:*"]`。
  复测探针：`{"kind":"ipc","phase":"ok","innerH":835}`（窗口真的最大化了又还原）。拖拽/双击最大化
  走同一条 `plugin:window|*` ACL，一并修好。
- 顺带（titlebar.js `wire()`）：窗口句柄**改成每次点击现取**（`currentWindow()`，兜底
  `__TAURI__.webviewWindow`），不再在挂载时缓存（旧写法拿不到就整段不绑定＝永久失效）；
  `.catch(function(){})` 改成 `console.error('[web2app] 窗口命令 X 被拒绝：', err)`。

### 2. 「页面底部有一部分被下面覆盖」＝ 38px 布局高度没人还
- 根因：`100vh` / `min-height:100vh` 量的是**视口**高度，视口并没有变小（我们只拿掉 38px 布局高度）
  ⇒ 底部锚定的容器整条被挤出视口下沿 38px。实测 `/vh.html`：`#root{min-height:100vh}`
  top=38 **bottom=688**（viewH=650），页脚 632..688 整条在屏幕外。
- 修：`shiftPageTopBars` → **`applyChromeFit`**，一个扫描里干三件事：
  ①贴顶 fixed/sticky → `top:38px!important`（去掉「高≤半屏」限制）；
  ②**底部锚定**（computed `bottom≠auto`）的贴顶元素只改 top（元素被缩短而不是下移，底边仍钉视口底）
  ⇒ `fixed;inset:0` 的整屏外壳也一并解决（旧版整类排除，就是「顶部 38px 一直压着」的老边界）；
  ③高度≈视口高度（±1px）且底边越过视口底的容器 → `height/min-height: calc(100vh - c)`，
  `c` = 38 或它离文档顶的实际距离，夹在 [38,54]（容忍 body 默认 8px 边距）。
  属性 `data-web2app-chrome-shrink`；仍保持两阶段只读→统一写、次数上限 40 的多轮调度。
- 复测：`/vh.html` root 38..**650**、页脚 594..650；`/inset.html` 外壳 38..650（页头 38..82、页脚 606..650）；
  `/fixed.html` 页头仍 38（无回归）；`/sticky.html` 滚到 700 sticky 头仍 38；`/plain.html` 正常流从 38 起。

### 探针（%TEMP%\w2a_probe2）升级
- `site.py`：新增通用 `marks()`（任何 `data-mark` 元素回传 rect/position）+ `innerH/docW/viewW`；
  新场景 `/vh.html`、`/bottom.html`、`/inset.html`、`/diag.html`（IPC 诊断：`typeof __TAURI__` /
  close 按钮 `elementFromPoint` 命中测试 / `toggleMaximize()` 结果与拒绝原因 / `window.onerror` 上报）。

- 坑：被遮挡窗口的定时器被节流 ⇒ 上报必须在 `load`/`DOMContentLoaded` 里同步发（`setTimeout(…,0)` 不跑）；
  app 单实例，连跑要等上一进程退干净，偶发「no beacon.log」重跑一次即好。

## electron-app 方案评估（未落地，仅分析）

- `electron-app/` 空目录；产出 `electron-app/ANALYSIS.md`：用 Electron 复刻 webview-app 的可行性分析。
- 核心结论（**先别重写**）：`tauri.conf.json` 未配 `webviewInstallMode`（默认 `downloadBootstrapper`，安装需联网）。
  若动机是「目标机没装/离线装不上 WebView2」，改用 `offlineInstaller`(+127MB) 或 `fixedRuntime`(+180MB)
  **只要改 3 行配置、零代码改动**。Electron 也救不了 Win7/8（v23 起移除支持，≤22 已 EOL，Chromium 109 是分水岭）。
- 反直觉点：**「必须自包含」时体积差距基本抹平**（180MB vs Electron ~150–200MB），真正差异变成内存占用
  （WebView2 共享 Edge 运行时 ~60–120MB vs Electron 多进程 ~150–300MB）、**Chromium 安全补丁维护责任**、
  以及 Electron **完全不支持 Android**（本项目最大架构优势就是一份 Rust 同时出 Win + APK）。
- 迁移账：约 3000 行 Rust 需重写（`webview_hooks.rs` 757 / `tabs.rs` 872 / settings / tray / window_state / bootstrap）；
  可直接复用：`proxy.rs`(741) + `resolve-core`(573) + 注入脚本 ~70KB + `shell.html`/`settings.html`。
  推荐形态 = **Electron 壳 + Rust sidecar**（代理与加密零重写）；`.github/workflows/build-custom.yml`（62KB）是最大隐藏成本。
- Electron 侧反而更简单的点：无 ACL/capability（那条 `remote.urls` 必须带 `:*` 的坑整条消失）、
  `setWindowOpenHandler`/`will-download`/`context-menu` 是一等 API（不用 COM + 后台线程轮询 `with_webview`）、
  多页签用 `WebContentsView` 同窗口内子视图（不需要 owned window + `place_tab` 闭环校准）。
  代价：Electron 无内建权限模型 → 必须自己把关 contextIsolation/sandbox/preload 最小 API 面。
- 建议路线：先查目标机 WebView2 注册表 pv 值 → 是 A/B 类问题就改配置收工；只有「合规要求自包含」或
  「放弃 Android」才启动 Electron，且先做一个 2 天 spike（无边框窗+titlebar.js+sidecar 代理+托盘+快捷键+下载，量体积/内存/冷启动）。

## electron-app 落地方案（决策已定，产出 `electron-app/PLAN.md`）

- 用户决策：**Electron 必做 · 仅 Windows · Win10+ · 体积不限 · 只出绿色版**。ANALYSIS.md 的「是否该做」论证作废，
  已在文件头标注并指向 PLAN.md；§2 功能对等矩阵 / §3 复用策略 / §5 安全基线仍有效。
- ⚠️⚠️ **绿色版最大的坑：不要用 electron-builder 的 `portable` target** —— 它是自解压单 exe，每次启动解压到
  `%TEMP%`（~250-300MB）、数据仍写 `%APPDATA%`、杀软敏感、不是真绿色。正确形态 = `target: dir` + 外部 zip 分发；
  真绿色靠 `app.setPath('userData'|'sessionData'|'logs'|'crashDumps', exe同级/data…)`，且**必须在 `app.whenReady()`
  之前**、早于任何 electron-store/session 使用；只读介质要 try/catch 回退 `%APPDATA%` 保证能启动。
  单实例锁文件在 userData 下 → 随重定向自动跟随。
- ⚠️ **sidecar 的 exe 不能放 asar 里（无法 spawn）** → 必须 `extraResources`，运行时用 `process.resourcesPath` 定位；
  spawn 用数组形式传参（路径可能含空格/中文）。握手建议 stdout 单行 JSON `{port,upstream}`；父进程退出要 kill 子进程
  防僵尸占端口。
- 复用账：`proxy.rs`(741) + `resolve-core`(573) 编成新 bin crate `crates/w2a-proxy` **零重写**；
  `titlebar.js` 只改 `__TAURI__`→`window.web2app` 且**必须整体保留 38px + `applyChromeFit()` 契约**；
  `loading.js`/`splash.html`/`shell.html`/`settings.html` 基本原样；**`dnd_polyfill.js` 不引入**（WebView2 专属 bug，Chromium 无此问题）。
  需重写约 2500–3000 行 TS；`tabs.rs` 用 `WebContentsView` 替代独立窗口（几何不用闭环校准，但 bounds 在最大化/全屏/DPI 下要自测）。
- 关键 API 映射：`setWindowOpenHandler` / `will-download` / `context-menu` / `app.on('login')`(Basic 兜底，⚠️需实测对 WS 握手是否生效)；
  外部代理可直接复用现有 `build_proxy_args()` 的产物 —— `--proxy-server` 是 Chromium 原生 switch。
- 兼容契约 12 条（config.json 18 字段不增不改名、android_* 字段静默忽略、38px、按钮、WS 鉴权、Cookie Domain 重写、
  Alt+4 / Shift+F1、托盘、单实例、数据目录语义映射、产物命名、注入脚本单一真源）。
  ⚠️ 已知差异：Electron 原生标题默认跟随 `document.title`（Tauri 版固定 `WINDOW_TITLE`），要一致需 `page-title-updated` preventDefault。
- **测试能力反超 Tauri**：直接 `webContents.executeJavaScript()` 断言 DOM + `capturePage()` 可用截图 + Playwright `_electron`
  做 E2E；Tauri 侧那套 beacon 回传/不能截屏（DWM 合成）的坑全部绕开。建议 M1 起就把契约变成用例。
- 计划 8 阶段约 8.5 人日；M0→M1→M2（骨架+窗口复刻+代理接入，2.5 天）即可判定能否替代。
- 待用户确认：①绿色版形态（目录 zip vs 单文件 portable）②数据目录（exe 同级 data\ vs %APPDATA%）③是否采购 Windows 代码签名证书
  （⚠️ `signing/` 里现有的是 Android keystore，不通用；未签名 exe 会被 SmartScreen 拦）④Tauri 版长期保留还是下线。

### 本轮三个坑（都属"错了也静默"，全在业务代码里看不出问题）
1. **宿主注入 `ELECTRON_RUN_AS_NODE=1`** → Electron 以纯 Node 启动：`require('electron')` 返回路径字符串、
   `app` undefined，业务代码第一句就抛 `TypeError`，**报错位置在我们的代码里**，且**时好时坏**
   （不同宿主 / 不同调用方式注入与否不一致），极易误判为随机故障。
   判别：`electron.exe --version` 打印 `v24.x`（Node）而非 `v44.x`。
   ⚠️ 排查时 **`env -u` 不能用**：`env(1)` 会重建进程环境、连宿主捕获 stdout 的管道一起切断 ⇒
   「退出码 0 但零输出」，于是会去怀疑参数、怀疑代码，而真正的问题是看不见输出。
   改用 bash 内置 `unset`（或 Node 里 `delete env.X`）。**也别清 `NODE_OPTIONS`**——那个 shim 正是输出通道。
2. **注入脚本跑在隔离世界** → `contextBridge` 暴露的 `window.web2app` 只存在于主世界 ⇒
   `shellName()` 永远 unknown、最小化/最大化/关闭三个按钮全部点不动；
   而 **DOM 跨世界共享**，标题栏照样画得出来、38px 让位也照样生效 ⇒ 表象"看着是对的"，最难查。
   改 `webFrame.executeJavaScript`（主世界，与 Tauri 侧 `initialization_script` 的世界对齐）。
   附带：加载层指令（fail/slow/hide）原先读隔离世界的全局，也必须跨到主世界执行。
3. **严格 CSP 站点（`style-src 'self'`）拦掉 `<style>` 元素** ⇒ 标题栏与加载层裸奔
   （透明背景、按钮挤成一团、38px 让位也丢）→ 改用 `document.adoptedStyleSheets`（**不受页面 CSP 约束**）。

### 探针自身修掉的 4 处期望值错误（是断言写错，不是产品缺陷）
- 「满宽」别比 `innerWidth`：`left/right:0` 的 fixed 元素要**减纵向滚动条**（本机 15.3px）→ 用 `clientWidth`。
- 「已着色」别写死浅色 `#eef0f2`：深色系统上是 `#1f2530` → 断言"落在已知浅/深两色里"。
- 「加载层淡出」别用固定 sleep（`MIN_MS 220 + FADE_MS 280 + DCL_DELAY 240`，元素动画结束才移除）→ 轮询等待。
- 夹具加 `h1{margin:0}`：h1 默认 margin 会**塌陷**到父容器，把 `#content.top` 从 38 顶到 56.8。

### ⚠️ 抓到一个真 bug（**Tauri 版同样中招**）
`handle_websocket` 里「先透传所有头、后面再设一次 `Origin` 来覆盖」**无效**：
`http::request::Builder::header` 与 `reqwest::RequestBuilder::header` 都是 `HeaderMap::append`。
上游收到**两个** Origin（逗号拼接），做 Origin 校验的后端直接拒连 =「页面能开，WS/POST 全挂」。
修法：透传循环跳过 `origin` + HTTP 分支补上 Origin 重写。
回归测试 `proxy_sends_exactly_one_rewritten_origin` + 探针两条断言。
**这个 bug 是探针第一次跑就红出来的** —— 正是"把契约写成可执行断言"的价值。

### 踩坑
- `--url-stdin` 时 `parse_args` 末尾的「必须提供 --url」校验会先把进程拦掉（url 还没读）⇒ 条件放宽。
- `USAGE` 常量含 JSON 双引号用普通字符串写 ⇒ 字符串提前结束，报错却是一串全角标点
  「unknown start of token: 。/（/：」，排查方向被带偏 ⇒ 改 raw string。

`tsc --noEmit` 干净 · `npm run probe` **50/50**。

### 四个关键决策
1. **设置页 HTML 不重写**：用设置窗自己的 preload 提供 `__TAURI_INTERNALS__.invoke` 垫片（白名单三命令），
   `webview-app/dist/settings.html` 一行不改地两壳通用 —— 与「注入脚本单一真源」同理。
2. **两个 JSON 写 `%APPDATA%\<app_name>\` 而非 `data\`**：为满足「与 Tauri 版可互相读取」；
   `data\` 下有同名文件则以它为准（读哪写哪）兼顾绿色性。
3. **物理像素存盘 + DIP 恢复**：Tauri 用 outer_position/outer_size（物理），Electron 用 getBounds/setBounds（DIP），
   必须 `dipToScreenRect` / `screenToDipRect` 换算，否则跨 DPI 错位。
4. **探针重定向存储到 `%TEMP%\w2a-probe-store\`**：探针会走「保存设置 / 开托盘 / 抢快捷键」全程，
   不隔离就会改掉用户真实设置。

### 「互通」怎么钉住（两方向都测）
Electron 写→Tauri 读：Rust 侧用**字面量**喂 serde（= Electron 实际写出的字节形态）。
Tauri 写→Electron 读：探针断言「序列化输出为规范 JSON」（字段名/嵌套/布尔类型/键顺序逐字节比对）。

### 踩坑
- 托盘「退出」走 `app.quit()` → 触发窗口 close → 被「关闭到托盘」分支拦下 ⇒ 必须先置 `quitting=true`。
- `globalShortcut.register()` 不抛异常只返回 boolean；失败**必须把旧键注册回去**，否则唤醒能力静默消失。
- 显隐语义 `visible && !minimized` 才隐藏，否则最小化时第一次触发「没反应」。
- `useContentSize: true`：Tauri 的 `inner_size` 是内容区，不写则少掉边框+标题栏高度。
- accelerator 里 `+` 是分隔符 ⇒ 符号键写原始字符（`Equal → =`）；不认识的键名一律返回 null（不猜）。
- 清理 `%APPDATA%` 下的测试残留：Git Bash 的 `rm -rf` 被 safe-delete 包装干预（绝对路径被当相对路径拼接而失败）
  ⇒ 改用 PowerShell `Remove-Item -LiteralPath`。
