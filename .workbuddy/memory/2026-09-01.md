## 修复 CI 编译错误（commit 45cb2f3）
- 现象：CI `cargo tauri build` 两个错误：
  1. `generate_context!` panic：`failed to open icon .../icons/icon.png`。
  2. `E0658 cannot call conditionally-const operator / cannot match on str in constants`，`PartialEq is not yet stable as a const trait`。
- 根因 1：`tauri.conf.json` 的 `bundle.icon` 只有 `icons/icon.ico`，而 Tauri 2 的 `generate_context!` 在 Windows 还需要 PNG 作为默认窗口图标。
- 根因 2：`env_bool!` 宏在 `const` 上下文里比较 `str`（无论 `==` 还是 `match` 都不行，`PartialEq` 非 const trait），且不能用 `&&`/`||`。
- 修复：
  1. 从 `icon.ico` 内嵌的 256×256 PNG 提取出 `icons/icon.png`，`bundle.icon` 改为 `["icons/icon.png", "icons/icon.ico"]`。
  2. 新增 `const fn str_eq`（字节逐个比较），`env_bool!` 改用 `str_eq` + if-else 链（避免 `==`/`match`/`&&`/`||`）。
  3. 提交 `Cargo.lock` 锁定依赖，避免 CI 与本地版本漂移（此前仓库无 lock 文件）。
- 已本地 `cargo check` 通过（Rust 1.95），并推送。

## 回答 Android 环境问题 + 打通 CI 自动生成 gen/android（commit 632c5d8）
- 结论：本机装 Android 环境（JDK17 + SDK + NDK r27 + build-tools 34 + rust target）确实复杂（5~10GB、20~60 分钟）；**最简方案是零本地安装——用 GitHub Actions CI**，Ubuntu runner 已内置整套 Android 工具链。
- 改动 `release.yml` Android job：
  1. 新增 `Initialize Android project` 步骤：`cargo tauri android init --ci --skip-targets-install`（`--ci` 跳过交互，`--skip-targets-install` 因上面已用 rust-toolchain 装 target），仅当 `gen/android` 不存在时执行。
  2. 新增 cleartext patch：`sed` 把 manifest 的 `usesCleartextTraffic` 置 true（应用走本地 `http://127.0.0.1` 反向代理，Android 9+ 默认禁明文）。
  3. 同时写 `NDK_HOME` 与 `ANDROID_NDK_HOME`。
- 修复跨平台编译 bug：`tauri-plugin-global-shortcut` / `tauri-plugin-single-instance` 是**桌面端专属插件（不支持 Android）**，原为无条件依赖会导致 Android 交叉编译失败。已改为 `[target.'cfg(not(any(target_os="android", target_os="ios")))'.dependencies]`，并同步门控 `main.rs` 的 use、`settings.rs` 的 `hotkey_to_shortcut`/`settings_open_shortcut` 两个函数及 `save_settings` 里的快捷键校验（`new_sc` 移入 cfg 块）。桌面端 `cargo check`/`cargo clippy -D warnings` 均通过。
- **重大发现（Android 仍未真正打通）**：项目是纯 `main.rs` 二进制结构（无 `src/lib.rs`、无 `#[cfg_attr(mobile, tauri::mobile_entry_point)]`、`Cargo.toml` 无 `[lib] crate-type`）。Tauri v2 移动端要求「lib.rs + mobile_entry_point + `[lib]` crate-type = staticlib/cdylib/rlib」结构，否则 `cargo tauri android build` 根本不会成功。之前「唯一缺口是 gen/android」的判断**不完整**，真正的剩余阻塞是这套 lib 结构重构（较大，且本地无 Android 工具链无法验证，只能靠 CI）。
